# mmoyager 日本麻将

本机可玩的立直麻将（日本麻将）项目：完整的规则引擎 + 浏览器 UI + **从零自我博弈训练**的 AI。

- **规则**：按天凤（Tenhou.net）四人打ち段位戦标准实现，40 个有争议的规则点逐条裁定并注明来源 →
  [`docs/RULES.md`](docs/RULES.md)
- **可玩**：一条命令启动本地网页，你和三个人机打牌，支持吃碰杠、立直、振听、流局、终局结算的完整交互
- **训练**：AI 不读任何人类牌谱，从规则内置的「牌效率基线」引导起步，然后靠自我博弈长期在后台变强 →
  [`docs/TRAINING.md`](docs/TRAINING.md)

## 快速开始

### 1. 编译

```bash
cd ~/Documents/mmoyager/mmoyager_mahjong
cargo build --release          # 首次约 2-3 分钟
```

### 2. 开打

```bash
./target/release/mmj-serve                 # 打开 http://127.0.0.1:8787
./target/release/mmj-serve --port 9000     # 换端口
./target/release/mmj-serve --checkpoint data/checkpoints/ck-0012.bin   # 指定 AI 权重
```

浏览器打开后：

- 顶栏选 **场次**（东风战 / 半庄战）、**座位**、**对手**（神经网络 AI / 牌效率 AI / 随机 AI），点「新对局」
- 点自己的牌即可打出；能立直时先点「立直」再点牌
- 有吃 / 碰 / 杠 / 荣和 / 自摸机会时，手牌**上方**会出现对应按钮
- 牌桌中央是四家牌河：每家按**自己的方向**摆（对家倒过来、左右竖着），立直宣言牌横放
- 中央面板显示场风、局数、本场、宝牌指示牌、供托立直棒与剩余牌数
- 手牌右侧实时显示自己的向听与听牌，振听时亮红标
- 「提示」按钮会让基线 AI 给出建议（推荐打什么、向听变化、进张数）
- 「牌谱分析」按钮打开已保存牌谱的分析面板（见下）
- 每局结束弹出结算（役种、番数、符数、点数收支），整场结束会保存牌谱到 `data/replays/`
- 页面底部的「对局记录」默认折叠成一行最新动态，点「展开」看全程

**训练控制台**在 `http://127.0.0.1:8787/dashboard`：当前的进程与迭代号、最近一次提升的权重、
逐轮趋势图（含 `--accept-margin` 门槛线）、历史表、实时日志尾，以及**启动 / 停止 / 重启**后台训练循环的按钮
（停止用 SIGTERM，循环会在当前迭代结束后写盘退出，与终端里 Ctrl-C 等价）。

改完 UI 之后跑一次界面回归检查（需要 Chrome；项目 venv 已装 `websockets`）：

```bash
.venv/bin/python scripts/ui_check.py fit     # 四个窗口尺寸：溢出、按钮可点、牌河朝向
.venv/bin/python scripts/ui_check.py play    # 打完一整局东风战并收集页面异常
.venv/bin/python scripts/ui_check.py riichi  # 立直后不许出现吃/碰/杠，手牌必须锁住
.venv/bin/python scripts/ui_check.py panels  # 面板遮挡、座位盒自裁、五张宝牌、牌谱面板
```

四个模式都是"布局/规则回归测试"，改完 UI 或规则之后应该像改完引擎之后跑 Rust 测试那样跑它们。

**生成训练数据前注意**：`mmj-selfplay generate` 的数据只由 `--seed` 决定
（每个 worker 的随机流按局重新播种），同一 seed 反复运行得到逐字节相同的文件——
任何"改动前后各生成一份、比对 md5"的对照实验，都要先确认这一点。

### 3. 训练（可长期挂后台）

```bash
# 起一个无限循环的训练器：自我博弈 → 训练 → 评测 → 保留最优
nohup ./.venv/bin/python python/trainer/loop.py --forever \
    --games-per-iter 1000 --eval-games 200 > data/logs/loop.out 2>&1 &

tail -f data/logs/loop.out          # 看进度
cat data/training_state.json        # 看当前最优权重与历史评测
```

随时 `kill` 都安全：状态每轮写盘，加 `--resume` 可接着跑。

### 4. 牌谱分析

每场对局结束都会把完整事件流写进 `data/replays/*.json`。点顶栏「牌谱分析」，或直接用命令行：

```bash
./target/release/mmj-analyze --replay data/replays/<file>.json            # 文本报告
./target/release/mmj-analyze --replay <file> --seat 2 --json              # 换座位、输出 JSON
```

面板里能看到：

- **终局与座位统计**：名次、点数、和牌/自摸/荣和/放铳/立直/听牌流局
- **每局结果**：谁和了什么牌、役种、番符、点数收支
- **逐手评估**：每个决策上，训练后的策略网络会给每张候选牌多少概率、它自己会怎么打；
  打牌决策还会给出**一步前瞻的期望得失**（把该选项推进一步后由价值网络估值，单位千点）
- 按「与网络首选的分歧」排序，优先看最值得复盘的几手

分析前会先用牌谱里的种子把整局**精确重建**一遍，并逐事件比对；只有完全一致才给出结果，
否则会明确报错而不会拿一局对不上的牌来糊弄。牌谱分析只用你当时能看到的信息，
不会偷看别家手牌或牌山。

## 目录结构

```
rust/mmj-core/        规则引擎（无依赖，可单独使用）
  tile.rs             牌表示、赤宝牌、宝牌指示牌
  hand.rs             和牌形判定、向听数、听牌、进张
  score.rs            役种、符数、点数（高点法）
  state.rs            牌桌状态机：摸打/鸣牌优先级/立直/振听/流局/连庄/终局
  rules.rs            规则开关（默认 = 天凤标准）
  action.rs           动作空间（109 维，引擎/UI/网络共用）

rust/mmj-ai/          智能体：随机、牌效率基线、神经网络
rust/mmj-nn/          观测编码（533 维）+ 手写 MLP 推理 + 权重文件格式
rust/mmj-selfplay/    自我博弈经验生成器（mmj-selfplay）与评测器（mmj-eval）
rust/mmj-serve/       本地 Web 服务（axum + WebSocket），UI 资源编译进二进制

web/                  前端（原生 JS，无框架、无构建步骤）
python/trainer/       PyTorch 训练器 + 训练循环编排
docs/RULES.md         规则裁定与来源（31 张表，36 个来源链接）
docs/TRAINING.md      训练方法与调参说明
data/                 权重、经验数据、牌谱、日志（不入版本库）
```

第 33 轮正面检验了**容量**这一侧：同一批数据、同一配方、同三个种子，只把网络从
768×768（1.24M 参数）加宽到 1024×1024（1.92M，**+54%**）。结果训练损失降了 7%、
验证准确率**毫无变化**（0.958~0.962 对 0.9613），而棋力**略降**：
对 v2 的组均值比在位者低 48，直接对战 −82.8 —— **不采用**（还会让每步推理贵一半）。
于是"信息受限"从排除法变成了正面的实测：**加信息、加容量、加训练量、换目标，四条路都是零**。
见 `docs/TRAINING.md` 第 44 节。

第 32 轮先修掉上一轮对照臂的一个缺陷（`--zero-features` 只在训练批次置零、推理没置零，
属训练/推理不一致），然后把它换成**同源数据砍掉新块、旧构建训练**的干净对照臂
（`im-v15-737`，逐字节校验前缀一致），用来回答另一个配方问题：**数据"新鲜度"值不值分**。
答案是不值：三个副本对 v2 的组均值比在位者 **+37.7**，但叠加在位者单次测量的误差后不确定度约 ±68；
直接对战（同牌配对）的均值是 **−16.9 ± 49** —— 两个口径都是零。
道理也简单：生成 `im-v12` 的策略与 `ck-ab` 只差约 40 分。见 `docs/TRAINING.md` 第 43 节。

**这三件事指向同一个结论：这条血脉不是"欠训练"，而是"信息受限"** —— 它已经学会了能从公开信息里
学到的东西。见 `docs/TRAINING.md` 第 38、39 节。

**吞吐（第 27、28 轮，两处改动都不影响棋力）**：剖析发现生成进程的耗时是
"网络前向 41% + 手牌评估 42%"。第 27 轮裁掉了编码器里"对每个手牌种类都算一次进张数"的浪费
（一次进张 ≈ 一轮 34 张 shanten 扫描，~30 µs），而这些值**只有"并列最好进张"的种类会被读到**，
裁掉后输出**逐字节不变**，生成 **+13%**。第 28 轮把权重改成 **binary16（F16C）**：
前向是**按权重字节数**受限（64×64 的网络权重全在缓存里，单位字节吞吐并不更高；
显式手写 AVX2、FMA、寄存器分块 GEMV 三种"换形状"的尝试都被同一批交替测量否掉——
其中寄存器分块还**更慢**，3 KB 的列步长打死了预取器），砍半字节数后前向 **+8%**、
生成 **+9.6%**，而棋力在 4800 局配对里是 +244.1 对 +261.1（差 +17，落在 ±100~150 的标准误内）。
两轮累计：**21.1 → 28.2 局/秒（+34%）**。见 `docs/TRAINING.md` 第 38、39 节。

第 29 轮又量了一遍**循环一轮的时间构成**（干净机器）：自博弈 6000 局 ~175 s、训练 2 轮 ~410 s、
评测 9600 局 ~275 s。训练的旋钮里只有一处是白拿的：这台机器 4 物理核 / 8 逻辑核上，
**8 线程反而不如 4 线程**（同样 300k 行的一轮：12/11 s 对 9/10 s），
于是循环的训练步骤改成 `--threads 4`，真实负载上 220 s → 203 s（+8%）。
另外试了"把和牌判定换成查表"（评测里和牌判定占 ~24%），**实测慢 13% 并已回退** ——
递归版只在 34 字节数组上做快速失败搜索、全在 L1，查表版每次 4 次哈希查找要去主存。
这个失败顺带照出一个**潜伏的缓存键冲突**（花色缓存的键是 5 进制，而"形式聴牌"查询会故意
在第 5 张牌上加一），已改成 6 进制并加了回归测试。见 `docs/TRAINING.md` 第 40 节。

⚠️ **关于训练噪声（第 24 轮实测）**：同一个配方、同一份数据、**只换训练种子**，
对 v2 的分就能差出 **250 分**（三次训练：+163 / −85 / +110，标准差 124）。
这是因为从头训练用的 bootstrap 配方（lr 1e-3、4 轮）本身不稳定；
温和配方（lr 5e-5、2 轮）的副本间标准差只有 47。
**凡"某改动更好"的结论，必须用温和配方训练、或每臂至少 3 次训练。**
| 训练循环现在的优化目标 | — | — | **已改成对 v2 的分**（对 v1 只作守卫），因为对 v1 调优产出的是"专精牌手" |
| 牌效率基线（另两个种子） | 25667 / 25676 | 24333 / 24324 | 种子 5150 / 31337，端到端可复现 |
| 牌效率基线（顺位） | **平均 2.442** | 2.558 | 随机为 2.500；顺位是麻将实力的标准度量 |
| 强化老师（会弃和/看役种） | 25743 | 24257 | 老师本身对旧基线的优势 |
| 随机 AI | 约 31500 | 约 18500 | 碾压 |
| 上一版权重 `ck-best` | 25575 | 24425 | 同种子同批牌局，当前版比它高 236 |

**当前最优权重是 `data/checkpoints/ck-dagger.bin`**（737 维特征）：模仿保真度 **0.969**，
对更强的手写 bot v2 的配对分从早期权重的 **−587** 一路提到 **−55**（三个副本口径 −216 → −43）。
路径是两步叠加：先把老师的**合成判据**做成特征（保真度 0.849→0.969），
再用学生在自己局面上的 DAgger 标签补掉分布偏移。：它是从模仿阶段的
权重出发、用「当前权重走棋 + 老师打标签」的数据（DAgger）再做两轮监督微调得到的。

这一剂的**期望收益是 +76 ~ +96 分**：8 个独立训练副本、每个两个评测种子实测——
只标中盘弃牌的臂 +96 ± 23，标全部决策的臂 +76，两臂配对差 −20 ± 61。
**标签覆盖范围无关紧要**，收益来自「用学生自己走出的局面配老师标签」这件事本身。
第 8 轮单次测到的 +193 是上尾抽样。

⚠️ 关于这个「+193」的修正史（这也是本项目最有价值的方法论部分）：

| 轮次 | 做法 | 结论 |
|---|---|---|
| 第 8 轮 | 训练 1 次，在 3 个评测种子上量 | 「+193，3.4σ」 |
| 第 9/10 轮 | 换牌局重跑 1~2 次 | 「效应约 0，那次是抽签」 |
| **第 11 轮** | **同配方训 4 个独立副本，各 2 个评测种子** | **效应 = +96.0 ± 23.4（t≈4.1）** |

真相在中间：**效应是真的，但只有原始声称的一半**。第 8 轮抽到上尾，
第 9/10 轮用 1~2 个副本去推翻它则样本量不足。
另外本轮还量出：四个副本之间的标准差只有 **46.8 分**，
说明这个温和配方（lr 5e-5、2 轮）是**可复现**的；
此前"单次训练差 373 分"的波动来自激进的 bootstrap 配方（lr 1e-3、4 轮）。

**教训（写给以后的自己）**：任何"某配方 +N 分"的结论，至少要有 3 个独立训练副本。
详见 `docs/TRAINING.md` 第 20、21、22 节。

从零开始（随机初始化）的演化轨迹：模仿准确率 53% → 65% → 78% → 81% → **89.1%**，
对基线从落后 11000 分到追平。关键节点是给网络补上「进张数」这一派生特征，
以及把推理速度提上去（前向 16 倍加速，使同样的算力能多训 3 倍局数）
——详见 `docs/TRAINING.md` 第 3、8 节，以及第 10 节关于「准确率更高未必更强」的实测记录。

## 设计要点

**为什么规则写在 Rust 里？** 自我博弈需要百万局量级的对局。纯 Python 引擎大约每秒几局，Rust 版本
（含神经网络推理）在本机 8 线程下每秒能跑十几到几十局，这是「长期后台训练」能成立的前提。

**为什么推理不用 PyTorch？** 训练在 Python 里做（PyTorch 生态无可替代），但推理手写在 Rust 里：
一个 533→512→512→(109+1) 的 MLP 前向只要几十微秒，且部署零依赖。双方通过一个自描述的二进制
权重文件对接（见 `rust/mmj-nn/src/lib.rs` 顶部注释）。

**为什么观测编码只在 Rust 里实现一次？** 经验文件里存的已经是编码好的特征，Python 只负责读特征和
标签，不重新实现编码，从根上消掉了「两边编码不一致」这类最难查的 bug。

**动作空间是固定的 109 维**：`0-33` 打某张牌、`34-67` 打牌并立直、`68-101` 杠某张牌、
`102` 自摸、`103` 荣和（九种九牌共用）、`104` 跳过、`105-107` 三种吃、`108` 碰。
引擎按当前局面给出合法动作掩码，网络只在合法动作上做 softmax。这样一套参数同时覆盖摸打、鸣牌、
立直、和牌所有决策，不需要为每种决策单独设计网络头。
