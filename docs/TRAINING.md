# 训练方法与调参说明

这份文档说明人机是怎么“变强”的，以及你可以怎么观察、调整、接管这个过程。不需要机器学习背景也能读懂。

---

## 1. 一句话概括

人机不读任何人类牌谱。它先模仿一个**规则内置的牌效率 bot**（不是人类数据）学会“正常打牌”，
然后靠**自我博弈**：自己和自己打、自己和自己比较，把“结果好的决策”概率调高，长期循环变强。

---

## 2. 训练流水线

```
                    ┌───────────────────────────────┐
                    │  mmj-selfplay (Rust, 多线程)   │
                    │  用当前权重自我博弈 1000 局    │
                    │  每个决策记一条经验            │
                    └──────────────┬────────────────┘
                                   │  data/selfplay/sp-XXXX.bin
                                   │  (533 维特征 + 合法动作掩码 + 实际动作 + 回报)
                                   ▼
                    ┌───────────────────────────────┐
                    │  train.py (Python + PyTorch)  │
                    │  策略头：优势加权策略梯度      │
                    │  价值头：回归蒙特卡洛回报      │
                    └──────────────┬────────────────┘
                                   │  data/checkpoints/ck-XXXX.bin
                                   ▼
                    ┌───────────────────────────────┐
                    │  mmj-eval (Rust)              │
                    │  新权重 vs 牌效率基线 / vs 旧权重 │
                    │  变差就回滚，变好才保留          │
                    └──────────────┬────────────────┘
                                   │
                            回到自我博弈（下一轮）
```

`python/trainer/loop.py` 就是这个循环的调度器，负责把上面四步串起来，并把状态写进
`data/training_state.json`（可中断、可续跑）。

## 3. 网络在看什么、在决定什么

**输入（601 维，全部来自“当前行动者合法可见”的信息）**

| 内容 | 维度 |
|---|---|
| 自己手牌（每种牌 0-4 张归一化） | 34 |
| 自己的赤宝牌数、副露里的赤宝牌数、是否门清 | 3 |
| 四家各自的弃牌堆（按相对座位排列） | 4×34 |
| 四家各自的副露牌 | 4×34 |
| 四家各自的吃/碰/暗杠/明杠/加杠数量 + 是否立直 | 4×6 |
| 全场可见牌数、每种牌剩余枚数 | 34+34 |
| 宝牌指示牌、宝牌张数 | 34+34 |
| 四家点数 | 4 |
| 场风、自风、是否庄家、余牌数 | 10 |
| 自己是否立直/一发/振听/听牌、手牌数、向听、回合数、杠数 | 9 |
| **打掉每种牌之后的向听数**（派生量） | 34 |
| **打掉每种牌之后的进张数**（派生量，只算同向听最优的几个候选） | 34 |
| 决策类型、被鸣/被和的牌、放铳者相对座位 | 41 |

两个派生块是这套特征里最关键的补充。向听告诉网络「哪些打牌不会让牌变慢」，
进张告诉它「同样不慢的几手之间哪一手更容易摸上」——这正是牌效率打法的完整判据。
在加入第二块之前，网络在同向听候选之间只能靠猜，准确率卡在 81% 左右；
加入后一轮就跳到 82%，八轮后到 88.8%。

所有特征都落在 `[0,1]`，存盘时量化成 1 字节，所以一条经验只占 554 字节。

**输出**

- 策略头：109 维 logits，只在**当前合法动作**上做 softmax；
- 价值头：一个标量，预测“从此刻到本场结束，我这个座位还能净得多少分”（单位：千点）。

## 4. 两个训练阶段

### 阶段 A：引导（bootstrap，只跑一次）

1. 用牌效率 bot 互打 1200 局，记录 50 万条决策；
2. 网络做**行为克隆**（交叉熵），2 个 epoch。

这一步不是“学习人类风格”，而是给随机初始化的网络一个能正常打牌的起点——否则纯随机策略基本赢不了牌，
回报信号几乎全是噪声，强化学习会非常慢。
产物：`data/checkpoints/ck-0000.bin`（模仿准确率约 53%，即它已经能复现基线 bot 一半以上的决策）。

### 阶段 B：自我博弈 + 强化学习（长期循环）

每一轮：

1. **自我博弈 1000 局**，一半是“全学习座位”（自己打自己），一半是“学习座位 vs 牌效率 bot”。
   混入基线对手是为了防止自博弈退化——两个都只会防守的 bot 会让对局几乎不和牌，回报信号就没了。
2. **训练 1 个 epoch**，混合三部分数据：
   - 新产生的自我博弈数据；
   - 前 2 轮的经验（回放窗口，防止遗忘、提高样本利用率）；
   - 引导数据集（锚点，见下）。
3. **评测**：
   - 新权重 vs 牌效率基线（200 局，A/B 座位各半以抵消座位运气）；
   - 新权重 vs 上一版权重（100 局）。
4. **保留或回滚**：如果新权重相对历史最好的成绩**低于 200 分**（约等于 200 局评测的统计噪声量级），
   就丢弃它，下一轮继续从历史最好权重出发。所以这个循环**不会持续退化**。

**关于锚点数据**：引导数据集会一直在训练混合里占一部分。它相当于一根“别忘了怎么正常打牌”的绳子，
是早期最有效的稳定手段。如果你想要 100% 纯自博弈，用 `--no-anchor` 关掉它（会更不稳定）。

## 5. 回报（reward）是怎么算的

一局牌里每个决策记一条：

```
回报 = 本场结束时我的点数 − 做这个决策时我的点数     （除以 1000）
```

这就是蒙特卡洛回报：把“这一步之后发生的一切”都算作这一步的后果。四家点数总和守恒，所以这是一个
零和信号，网络学到的价值头就是在预测这个量。

训练损失：

```
损失 = 策略损失 + 0.25 × 价值损失 − 0.005 × 熵
策略损失(自博弈) = −log π(实际动作) × (回报 − 价值预测)      # 优势加权策略梯度
策略损失(模仿)   = −log π(基线实际动作)                       # 交叉熵
价值损失         = (价值预测 − 回报)²
熵               = 策略分布的熵，用来鼓励探索
```

优势在 batch 内做了标准化（减均值除标准差），避免不同局之间尺度差异把梯度带偏。

## 6. 怎么观察训练

```bash
tail -f data/logs/loop.out      # 每一轮的实时输出
cat data/logs/train.log         # 只记里程碑行（轮次、评测、最优权重）
cat data/training_state.json    # 结构化状态：历史评测、当前最优、数据文件
```

一轮的输出长这样：

```
iter 7: self-play 500 games (mirror) + 500 games (vs baseline)
iter 7: training on 5 data file(s)
epoch 1/1  policy_loss=1.32  value_loss=98.4  val_acc=0.51  val_mse=42.1
iter 7: evaluating ck-0007.bin vs efficiency
  vs efficiency: avg 26840 (baseline 23160), firsts 0.31, hands 132:118
  vs ck-0006.bin: avg 25610 (previous 24390), firsts 0.28
  new best: 26840
```

- `avg` 是 A 方每座位平均终局点数，**25000 是打平**。对牌效率基线如果长期稳定在 25500 以上，
  就说明确实比手写规则更强了。
- `firsts` 是 A 方拿一位的比例（0.25 是随机水平）。
- `val_acc` 是策略头在留出集上复现“当时那个策略的动作”的比例，它**不是越高越好**——
  强化学习本来就要偏离旧策略，这个指标只在引导阶段有意义。

## 7. 参数与调优

| 参数 | 默认 | 说明 |
|---|---|---|
| `--games-per-iter` | 1000 | 每轮自我博弈局数。本机约 15 局/秒，即每轮 1 分钟左右 |
| `--eval-games` | 200 | 每轮评测局数。想更灵敏可加到 400（噪声约 ±150 分） |
| `--epochs` | 1 | 每轮训练遍数。数据量小的时候调大容易过拟合 |
| `--lr` | 2e-5 | 强化学习步长。**最重要**：太大策略会崩（表现为评测分数骤降），太小则学不动 |
| `--return-scale` | 0.1 | 价值目标的缩放。**不加这个，价值损失会比策略损失大两个数量级**（实测 326 vs 0.98），共享主干会被价值回归主导，策略精度直接受损 |
| `--hidden` | 768,768 | 容量。512 网络模仿准确率上限约 87.8%，768 到 88.8% 并首次反超基线 |
| `--entropy-coef` | 0.005 | 探索强度。调到 0 策略会很快变得确定，容易卡死在坏策略 |
| `--value-coef` | 0.25 | 价值头权重。价值头越准，策略梯度的方差越小 |
| `--replay-window` | 2 | 回放窗口（轮）。调大更稳但每轮更慢 |
| `--epsilon` | 0.03 | 自我博弈时 3% 概率随机出牌，保证见过足够多的局面 |
| `--max-records` | 200000 | 每个数据文件最多用多少条（截断，控制训练时间） |

经验值：**如果看到评测分数一轮比一轮低，先把 `--lr` 降一半**。如果长期原地不动，
先把 `--games-per-iter` 翻倍，再考虑把 `--hidden` 加到 `768,768`。

## 8. 性能工程（这一节是数值最大的杠杆）

最初的实现里推理是纯点积，每个输出一个累加器——这会把乘加串成一条 FMA 延迟链，
实测只有 0.66 GFLOP/s。改成**转置权重 + axpy 形式**（每个输入特征做一次按比例向量加，
无归约依赖，可完美向量化，且零特征直接跳过）后：

| 项目 | 优化前 | 优化后 | 倍数 |
|---|---|---|---|
| 单次前向（512×512） | 912 µs | 57 µs | **16×** |
| 评测 200 局 | 40 s | 4.7 s | **8.5×** |
| 自我博弈（8 线程，4 个 AI 座位） | 15 局/秒 | 40 局/秒 | **2.7×** |
| 向听计算 | 2.07 µs | 1.10 µs | 1.9× |
| 一轮（4000 局 + 训练 + 两场评测） | 约 11 分钟 | 约 3.5 分钟 | **3.1×** |

三点经验，按收益排序：

1. **先量再改。** 一开始以为是内存带宽瓶颈（权重 2.3 MB / 次），实测只有 2.7 GB/s
   （机器上限约 30 GB/s），才定位到是累加器依赖链。改完直接到 43 GB/s，接近带宽上限。
2. **向听数的枚举乘积是隐藏热点。** 原来把四组（三门数牌 + 字牌）的 Pareto 组合做四重
   笛卡尔积；改成按「已用块数 × 是否用雀头」的 10 状态 DP 后快了一倍，而且顺便修掉了
   一处 Pareto 列表被截断导致的正确性 bug。
3. **让派生特征可负担。** 有了上面的提速，才敢在编码里加入「每个候选打牌后的进张数」
   （见第 3 节），它把模仿准确率从 81.4% 直接推到 87.8%。

编译时用 `-C target-cpu=native`（见 `.cargo/config.toml`）。这个项目只在本机跑，
换机器重新编译即可；如果要把二进制拷到别的机器，请去掉该设置。

### 走过的弯路（负面结果，值得记住）

- **推理时一步搜索目前是中性偏弱，而且曾经因为一个 bug 暴跌。**
  最初测出搜索把成绩从 23177 砸到 18965，看上去像「价值网络不够准 → 赢家诅咒」。
  真实原因是一个实现 bug：搜索把**自摸/荣和也当作候选**，而拿走一个和牌会让探测局进入
  下一局，价值网络在下一局看到的收益≈0——于是搜索学会了「放弃和牌」。
  修掉之后（和牌永不进入搜索，只搜打牌候选，且探测必须停在当前局内）：
  raw 25090 / 搜索 top-5 25020 / top-2 25044，即**中性**。
  结论：价值网络 R²≈0.71（本局范围目标，方差只有整场目标的一半）还不足以让一步搜索产生
  优势，因为一手牌最终得失的剩余方差大部分是摸牌运气。要让搜索真正增值，需要能消除运气
  的成对 rollout（共同随机数），而不是简单地取 max。
  这条经验本身值得记：**先怀疑实现，再怀疑算法**——「搜索变弱」这个现象看起来非常像教科书
  里的价值噪声问题，实际却是一个可以精确修掉的行为 bug。

- **价值目标用整场剩余得失 vs 本局剩余得失。** 原先每条经验的目标是「从这步到本场结束的
  得失」（标准差约 10.8 千点），改成本局范围后标准差降到 5.1 千点，价值 R² 从 0.67 升到
  0.71，而且作为强化学习的基线更稳定。
- **「赢过上一版自己」不等于变强。** 有一轮新权重重放同牌局以 26839:23161 赢过旧权重，
  但对基线的绝对分反而略降。自博弈的对手就是自己，赢它未必赢别人。所以判定接受与否
  必须以**对基线的绝对分**为准。
- **不同种子的评测不可比。** 早期每轮用不同种子评测（±400-600 波动），导致「变好变坏」
  的结论基本是噪声。现在统一用固定种子做配对评测，方差大幅下降。
- **所有 4 家都是自己的自博弈会退化。** 一半以上的对局必须安排「学习座位 vs 固定基线」，
  否则对局趋于互相弃和，几乎不和牌，回报信号消失。

## 9. 目前的实测战绩

从零（随机初始化）到现在的完整轨迹，全部是同一批牌局上的配对评测：

| 阶段 | 模仿准确率 | 对基线（25000=打平） | 局数 |
|---|---|---|---|
| 初始网络 | — | 约 19500（远弱于基线） | 600 |
| 模仿（初期配置） | 53% | — | — |
| 加派生特征 + 配平损失 | 78.4% | 23578 : 26422 | 600 |
| 更多数据 + 10 轮 | 81.4% | 24421 : 25579 | 600 |
| 修正基线的进张计数（老师变强） | — | 基线自身 25563 : 24437 | 900 |
| 加「进张数」特征 + 768 网络 | 88.8% | 25118 : 24882 | 2400 |
| 补齐全部判据特征 + 768 网络 | 89.1% | 24970 : 25030 | 4800 |
| v8 更强老师 + 判据特征 + 重训 | 85.9% | 25266 : 24734 | 4800 |
| v9 老师阈值调优 + 重训 | 85.9% | 25543 : 24457 | 4800 |
| **区域聚焦 DAgger 微调（当前最优，见第 19 节）** | 86.5% | **25693 : 24307** | **4800** |

**当前状态：明确强于手写牌效率基线。** 在同一个会话、同一个二进制、同一批牌局上重测
（第 19 节），`ck-region.bin` 对冻结基线的平均分是 25693（基线 24307），三个种子分别为
+236 / +199 / +145（相对上一版权重 `ck-best`），平均 **+193，约 3.4 个标准误**。

⚠️ **一个必须记住的教训**：前面几行里出现的「+236」「+146」都是在 2400 局下测的，
标准误约 140 分；同一批权重加到 4800 局就变成 −60。做结论时至少要用 4800 局
（`--eval-games 4800`，跑一次约 75 秒），否则很容易把噪声当成突破。

## 10. 关于「更高的模仿准确率是否等于更强」

不一定，而且这一点必须用配对头对头来验证，不能只看准确率：

| 权重 | 训练数据 | 模仿准确率 | 对冻结基线（同种子配对） |
|---|---|---|---|
| v3（当前最优） | 3.1M 条 × 6 轮 | 88.8% | **25118 : 24882** |
| v4 | 3.1M 条 × 6 轮（本局范围价值目标） | 88.7% | 24767 : 25233 |
| v5 | 6.0M 条 × 4 轮 | **89.9%** | 24624 : 25376 |

单独看「对基线」这一列会得出错误结论（v3 比 v4 高 351 分），但 2400 局头对头显示
**v3 与 v4 完全同强度**（25031 : 24969），那 351 分是噪声。而 **v5 确实显著更弱**
（v4 以 25274 : 24726 赢它 548 分，约 2.7 个标准误）。

结论：

1. **每个改动都要做配对头对头**，单看「对基线」的绝对分在同一批牌局上仍有 ±200-350 的
   不确定性，容易把噪声当结论。
2. **把模仿做到更准并不自动变强**。老师本身有系统性弱点（不防守、只看牌效率），
   学生越贴它，就越完整地继承这些弱点。v5 准确率最高却最弱，很可能就属于这种情况——
   适当早停/留一点「不像老师」的余量反而更好。
3. 想真正超过老师，只能靠**老师之外的信号**（更强的价值搜索或强化学习），
   而不是把老师模仿得更精确。

## 11. 试过但没用的方向（都做了配对评测，不是猜测）

| 尝试 | 结果 | 判读 |
|---|---|---|
| 一步搜索（价值网络择优） | 中性：25090 raw vs 25020/25044 搜索 | 价值 R²≈0.71 不够；见第 8 节的 bug 说明 |
| 更大数据集（6M 条，准确率 89.9%） | **更弱**：24624 对基线（88.8% 的那版是 25118） | 过度拟合老师会继承其弱点 |
| DAgger（学生走棋、老师打标签，128 万条） | 不更好：24877 vs 旧最优 25123（1600 局头对头） | 单独一代 DAgger 不足以补偿教师数据被稀释 |
| 给老师加危险度模型（弃和） | 打平：24852 : 25148 | 这套朴素危险模型没带来净收益，默认关闭 |
| 给老师加役种/宝牌价值意识 | 打平：25028 : 24972（2400 局） | 单看役种并不提升实力 |
| 给老师加「按手牌价值进退」 | **更弱**：24790 : 25210 | 这套推/弃判断反而亏分 |
| 老师三项改进全开 | 打平：25090 : 24910 | 与上面两项的合计一致，仍属噪声 |
| 把老师第三级判据（保留价值）也做成特征 | 准确率没变（87.4% vs 87.1%） | 网络本来就能从手牌计数推出来 |
| Deep Sets / 逐牌打分架构（未实现） | — | 见下面的轮次曲线：拟合度根本不是瓶颈，改架构动机不足 |
| **多训几轮**（同一权重在各轮存档上评测） | 完全平坦 | 见下表 |
| **权重平均 / 模型汤**（3 个不同随机种子平均） | **灾难性更弱**：22713 : 27287，头对头 22965 : 27035 | 独立初始化训练出的模型不在同一损失盆地，线性平均会得到坏网络。模型汤只在**共享初始化再微调**的前提下有效 |
| 更大网络（768 对比 512） | 略好（88.8% vs 87.8% 准确率，成绩在噪声内） | 保留 768 |

### 训练轮次与实力的关系（同一权重、每轮存档、各 2400 局配对评测）

| 轮次 | 模仿准确率 | 对基线 |
|---|---|---|
| 1 | 84.2% | 24592 : 25408 |
| 2 | 86.7% | 24741 : 25259 |
| 3 | 87.7% | 24654 : 25346 |
| 4 | 88.2% | 24682 : 25318 |
| 5 | **89.1%** | **24932** : 25068 |
| 6 | 89.5% | 24678 : 25322 |

整条曲线在 ±170 分内震荡（约 1 个标准误），**既没有随准确率上升的趋势，也没有下降的趋势**。
这说明：模仿准确率在 84% 之后就已饱和——剩下的差异要么是老师规则里的平局（两种打法等价），
要么是网络本来就学不动的边缘情形，两者都不影响实力。之前「89.9% 反而更弱」的观察是噪声。

**这条曲线也解释了为什么本项目的提升曲线会在 25000 附近停住**：学生已经学到了老师能教的
全部可迁移内容。要再往上，只能改变*老师*或引入*老师之外的信号*，而不是继续优化模仿。
| 加大强化学习步长 | 更弱（策略漂移） | 见第 10 节 |
| 每轮换评测种子 | 结论全是噪声 | 已改为固定种子配对评测 |

**为什么搜索很难在这里奏效**：价值目标是从某个局面出发「本局剩余得失」的单次采样，
它的方差 = 局面可解释的部分 + 摸牌运气。回归模型最多只能学到条件均值，所以
R² 的天花板就是「信号 / (信号 + 运气)」，实测约 0.71，而且加轮数、加数据都纹丝不动
（第 1 轮就是 0.706，第 6 轮还是 0.706）。要让它对**候选之间**的细微差别敏感，
必须让运气在比较中抵消——也就是成对 rollout（共同随机数）：从同一局面用同一副牌山
把两个候选各自打完一局再比较。但一手牌从头打完约需 280 次前向，一次决策两个候选
就是 560 次前向（约 30 毫秒），全量数据生成要几十小时。在本机算力下这条路不划算。

## 12. 强化学习为什么一直不涨（本轮最重要的结论）

我在这轮把强化学习的所有主要开关都做了对照实验，**每一个配置的「对固定基线的绝对分」
都停在 24850-24930（即与基线持平），而「与上一版权重的头对头」却持续为正**
（每一版都能以约 25060 : 24940 赢过前一版）。这个组合是关键线索。

| 配置 | 对固定基线 | 与上一版的头对头 | 备注 |
|---|---|---|---|
| 锚点 36% + lr 2e-5（旧默认） | ~24850-25050 | 时正时负 | 中性 |
| **去掉锚点** + lr 5e-5 | **19403** | 19520 | **一步就崩**：模仿准确率 0.89 → 0.443 |
| PPO 裁剪 + lr 1e-4 + 锚点 | 24855 / 24911 | +406 / +206 | 不崩，但绝对分不涨 |
| PPO + **无锚点** | 24847 | +120 | 同样不涨 |
| PPO + **全部对局打固定基线** | 24847 | +120 | 结论不变 |

**去锚点为什么会崩**：模仿准确率一步从 0.89 掉到 0.443，说明策略在一步之内被推得远离
原来的表示。原因是策略梯度的信噪比太低——单局得分差的标准差约 5000-7000 点，而不同打牌
选择之间的真实期望差通常只有几百分；在一个共享主干的网络上，任何「足以改变行为」的步长
都大到足以破坏已学到的表示。加入 PPO 的信任域（裁剪 0.2，实测裁剪比例 19-21%、KL 0.03）
之后不再崩溃，这也验证了这个解释。

**为什么仍然不涨**：所有配置都表现出同一种特征——**赢自己，不赢别人**。
每一版新策略都能稳定赢过上一版，但对一个固定的外部对手毫无进步。这符合「共享特质」
假说：策略在与自己同源的对手面前，任何一致的习惯都会带来镜像对局的优势，
但在面对风格不同的外部对手时毫无用处。也就是说，这些更新方向大体是**与真实实力正交**的。

**结论**：在本机算力（每轮 3000 局、单轮约 6 分钟）下，这条策略梯度路线无法把 AI
推过手写基线。要突破它，需要比现在高两三个数量级的数据，或者换掉「用整局得分当回报」
这一根本设定（例如成对 rollout 的比较式价值，见第 11 节末尾的算力估算）。

## 13. 镜像对局的优势**不可迁移**（本轮最有价值的结论）

这一轮我把「预测集成」（多个独立训练的模型输出分布取平均）接进推理，然后做了三组配对评测：

| 比较 | 结果（2400/4800 局配对） | 判读 |
|---|---|---|
| 集成(ck-best + ck-0015) **对 ck-best** | **25253 : 24747（+506，约 3.6 个标准误）** | 镜像对局里**确定性地更强** |
| 同一个集成 **对固定基线** | 24899 : 25101 | 对 ck-best 单独（24970 : 25030）**没有优势，甚至略差** |

同一个改动，在「打自己人」时赢 506 分，在「打外部对手」时收益为零。

**这说明我的神经网络相对老师的那 11% 偏离是「风格」而不是「实力」。** 集成之所以在镜像对局里有效，
是因为它降低了这 11% 偏离的方差；但对方是老师风格（牌效率 bot）时，这些偏离毫无价值。

**这条结论回头解释了三轮以来所有的困惑**：

- 第 2 轮：RL 第 7 轮「h2h 26839 : 23161 大胜旧权重」，对基线却毫无进步；
- 第 3 轮：PPO 每个配置都「h2h 稳定为正、绝对分纹丝不动」（+406 / +206 / +120）；
- 本轮：集成 h2h +506，绝对分 −101。

全部是同一个机制。**因此「与上一版权重的头对头」不能作为进步信号**——它奖励的是「和自己不一样且能赢自己」，
而真正要的是「和别人打得分更高」。项目里唯一可信的指标是**固定对手 + 固定种子的配对绝对分**。

顺着这条逻辑再看训练史，结论更清楚：从 19398 分爬到 24970 分的**全部收益都来自「把老师模仿得更准」**
（补进张特征、配平损失、加宽网络、加数据），强化学习从未贡献过一分实力。
也就是说，**当前上限就是老师本身**；而我对老师的 4 次改进尝试（役种意识、进退判断、危险度模型、组合）
实测全部中性或为负（第 11 节）。

## 14. 突破：把「更强的老师」这条路走通了

第 5 轮找到了第一个**确定有效的**提升配方，而且它是可复制的：

| 步骤 | 结果 |
|---|---|
| 1. 修好老师的安全度模型（补上 **同巡安全牌** 与 **壁**） | 老师对冻结基线 **25220 : 24780（+440）** |
| 2. 直接用新老师生成数据训练学生（特征未变） | 学生只有 24821 —— **没继承到**（模仿保真度从 89.1% 掉到 85.3%） |
| 3. 把老师的**新判据**也做成特征（安全度 34 维 + 役种分 34 维） | 特征 635 → 703 维 |
| 4. 重新生成数据并训练 | 学生 **25266 : 24734（+532，约 5.3 个标准误）**，并几乎追平老师（24954 : 25046） |

**为什么第 2 步会失败、第 3 步才成功**：新的老师会「看安全度弃和」「为役种调整打牌」，
而网络看不到牌的危险度和役种潜力，就无法复现这些决策——**老师的实力无法通过模仿迁移过去**。
一旦把判据暴露出来，学生就继承了老师几乎全部的优势（+440 → +532）。

这条规律在本项目里已经重复出现三次，值得写死：**每当老师变聪明，就必须把它的判据也做成特征，
然后再重训**。反过来说，如果只是把老师改聪明而不动特征，学生一定学不到。

当前状态：神经网络 AI **明确超过**手写牌效率基线（4800 局配对 25266 : 24734，一位率 0.511），
而且是在对手被冻结、跨轮次可比的同一把尺子上测出来的。

**参数调优也是显著杠杆**：我把老师的推/弃参数做成可配置（`efficiency-v2?fold=1.6&push=0.1`），
然后做了一轮 4800 局的配对网格搜索：

| 老师配置 | 对冻结基线 |
|---|---|
| 原默认（fold=1.2，即 3 向听才弃和） | 25215 |
| fold=1.6 | 25465 |
| fold=2.0 | 25609 |
| **fold=2.5（新默认）** | **25743** |
| fold=2.8 | 25706 |
| fold=3.2（过度弃和） | 25599 |

仅仅把「弃和阈值」从「3 向听」改成「2 向听且无役」，老师就再涨 **+530**。
合计本轮老师的提升：安全度模型 +440、阈值调优 +530 → 对冻结基线 **+743**。

学生最终继承到 **25543 : 24457（+543）**（4800 局配对，一位率 0.486）。
值得注意的是学生的**平均得分**高于其老师上一版，但**一位率反而略低**（0.486 对 0.511）——
说明「多弃和、少放铳」的风格抬高了平均分，同时把名次分布打得更散。做实力结论时以平均得分为准，
但要记住这两个指标会分道扬镳。

第二、三轮扫描（立直阈值、鸣牌激进度、防守权重）**没有找到进一步收益**：
立直要求 ≥2/≥3 张活牌与默认持平、≥5 张明显更差；`eager=0`（完全不鸣牌）在绝对评测里看着 +95，
但 2400 局头对头是 **24986 : 25014，完全打平**——又是一次噪声。
这再次印证第 10 条的教训：**绝对评测在 4800 局仍有约 ±150 的波动，改动的取舍必须看头对头。**

下一步的边际收益方向依然明确：**继续让老师更强**（补全领域知识 + 参数搜索）。
已试过但收益有限的：非立直威胁（+264，1.9σ）、把「手牌价值」也做成特征（−111，噪声内，已回退）、
立直/鸣牌参数（持平）。

## 15. 用顺位衡量实力（新增指标）

平均得分不是麻将实力的常用度量，**平均顺位**才是（人类段位就是按它划分的）。我给评测器加上了这个指标：

| 对手 | 平均顺位（越低越好，随机 = 2.500） |
|---|---|
| 手写牌效率基线 | 2.542 |
| **神经网络 AI** | **2.458** |

0.084 个顺位的差距意味着它确实比「不防守的牌效率 bot」强，但幅度不大——
按天凤的段位密度粗略换算，大约相当于中手偏下的水平，而不是「普通人类玩家」。
这个数字比「+543 分」更能说明现状，也给了后续提升一个更灵敏的方向标
（顺位的方差比平均得分小得多）。

## 16. 又一批评测为负的尝试（第 6—7 轮）

| 尝试 | 结果 | 判读 |
|---|---|---|
| 严格区分両筋/片筋 | 与默认**完全相同**（25743 一模一样） | 弃和时几乎总有現物可选（危险度 0），筋的细化轮不到发挥作用 |
| 顺位意识（落后则推、领先则保） | 更差：头对头 −152，顺位也没变好 | 这套粗粒度实现（最多把阈值压低 50%）得不偿失，已默认关闭 |
| 鸣牌激进度 `eager=0` | 绝对评测 +95，头对头 24986 : 25014 打平 | 又一次噪声，不改 |
| 立直阈值（要求 ≥2/≥3 张活牌） | 持平 | 「有听必立直」在这个规则下已是优 |
| 把「手牌价值」做成特征 | −111，噪声内 | 已回退 |
| 巡目意识（越到终盘越容易弃和） | 参数 0.5 持平、1.0 掉 325 分、2.0 掉 981 分（顺位 2.514，比随机还差） | 老师的弃和**已经足够多**，再加就亏——反过来验证了 fold=2.5 已是这个规则族的最优点 |
| 更多训练数据（20000 局 / 6.2M 条） | 保真度 0.859→0.863，但成绩 −249 | 保真度再高也不转化为实力 |

**教训再次确认**：绝对评测在 4800 局仍有约 ±150 波动；参数微调的取舍必须看头对头，
而「看起来合理的人类知识」（顺位意识、更细的筋）不一定能直接转成收益——
只有能被明确表达为规则、且规则本身确定更强的东西才值得加进老师。

## 17. 诚实的预期

- 这套配置（4 核 CPU、无 GPU、每天几万局）能训练出**明显强于手写牌效率 bot** 的 AI，
  但达不到顶尖人类或商用麻将 AI 的水平——那需要几十万到上百万局量级和搜索/更深的价值网络。
- 最值得期待的提升方向（按性价比排序）：
  1. **喂更多局数**（现在瓶颈是自我博弈吞吐，不是网络容量）；
  2. **价值头做搜索**：用价值网络对候选打牌做一步前瞻，把“搜索后的选择”当作新目标再模仿——
     这是 Suphx/AlphaZero 路线里性价比最高的一环；
  3. 更大网络 + 更多特征（例如加入“筋/壁”这类安全度特征）；
  4. 对手池（league）：和多个历史权重对打，避免只针对当前自己过拟合。
- 价值头本身已经很有用：它可以直接支撑**牌谱分析**（“这一手如果打 3m，期望得失是多少”）。

## 19. 第 8 轮：先修量尺，再找到第一个「对外」也成立的增益

这一轮的重点不是继续调参，而是**先确认过去几轮的测量到底在量什么**，再用可信的量尺找改进。
四个新工具和三个实验的结论如下。

### 19.1 诊断本身曾经是错的（方法教训）

我最初想回答「学生在哪里不像老师」，做法是跑两批同样的牌局：一批记录学生自己的选择，
一批记录老师在同一状态下的选择，然后逐行比对。第一次得到的一致率只有 **8.1%**，
而训练器报告的验证准确率是 0.86——差了十倍，**明显是量具坏了**。

原因：学生是**从策略里采样**出牌的，两次运行的随机流不同，局面根本不对齐。
改成 `--greedy --epsilon 0` 确定性出牌后，两批数据完全对齐，一致率变成 **0.858**，
与训练器的 val_acc（0.859）分毫不差，量具才算修好。

**教训**：任何「逐行比对」的诊断，都必须先让两次运行产生**完全相同的局面序列**，
否则得到的数字毫无意义，而且错得离谱时也不会报错。

### 19.2 分歧的解剖（对齐后，2000 局 / 40 万条决策）

| 指标 | 数值 |
|---|---|
| 总体一致率（对 v2 老师） | 0.858 |
| 自己回合决策一致率 | 0.826 |
| 鸣牌窗口一致率 | **0.963** |
| 自己回合弃牌分歧中：向听/进张完全等价（平局） | 52.2% |
| 同一向听但少进张（真错） | 24.8%（中位少 2.1 张） |
| 打坏向听（明显错） | 4.9%（每千次决策约 6.6 次） |
| 学生的牌比老师更危险 | 14.0% |

也就是说：**残留误差里有一半是老师规则里的平局**（怎么打都行），
真正的错误是每千次决策约 40 次「少进张」级别的小错。这解释了为什么继续堆数据、
堆准确率都不涨分（第 11、16 节）——剩下的是平局和边缘情形。

### 19.3 新工具一：教师代打区段（`assisted:` 规格）

我加了 `AssistedAgent`：**只在指定局面区段交给规则老师出牌，其余仍走网络**，
然后用配对评测比较「混合体」和纯网络。用它扫了各区域（4800 局，种子 4242）：

| 代打区域（对 ck-best 的头对头） | 差值 |
|---|---|
| 向听 ≥3 的自己回合弃牌 | +81 |
| 向听 ≥2 的自己回合弃牌 | +277 |
| 向听 ≥1 的自己回合弃牌 | +48 |
| 向听 ≥1 + 全部鸣牌窗口 | +379 |
| 只代打鸣牌窗口 | −12 |
| 向听 ≥2，但换成**更弱的 v1 老师**代打 | **−1027** |

最后一行是**量具的自检**：换一个更弱的老师，同一套代码立刻大幅变差，
说明这个仪器不是在「因为换了实现而变好」，而是在真的测老师的水平。

### 19.4 但是：头对头的增益又一次是假的（第 13 节的陷阱，再来一次）

把「向听 ≥2 代打」的混合体拿去打**外部固定基线**：25498，而 ck-best 是 25575——
**比纯网络还低 77 分**。也就是说：

| 同一个改动 | 头对头（打自己） | 对外部固定基线 |
|---|---|---|
| 向听 ≥2 交给老师出牌 | **+277** | **−77** |

这是第 13 节结论的第三次复现：**只要改动让棋风偏离当前权重，镜像对局就会给它加分，
而对外部对手毫无价值**。这条教训现在有了一个廉价、可重复的检验工具（`assisted:`）。

### 19.5 新工具二：动作空间消融（`filter:` 规格）

`FilterAgent` 可以「禁用」或「强制」某一类动作（立直、鸣牌），用配对评测直接问
「这一手该不该叫」。这是下一步研究战略决策（立直/默听、鸣牌/不鸣）的仪器；
本轮只完成了实现与冒烟测试，结果留待下一轮。

### 19.6 真正有效的改动：区域聚焦 DAgger（+193）

19.4 说明「硬替换」没用。那就换个用法：**不改推理，改训练数据**。
既然学生在向听 ≥2 的自己回合弃牌上和老师分歧最大（0.781 一致率），
就用当前权重走 6000 局、让老师给这些状态打标签（144 万条，占全部决策的 55%），
然后从 ck-best 微调 2 轮、lr 5e-5。

结果（三个种子、每个 4800 局、同种子配对）：

| 种子 | ck-best 对基线 | 微调后对基线 | 差值 |
|---|---|---|---|
| 4242 | 25575 | 25693 | **+236** |
| 5150 | 25568 | 25667 | **+199** |
| 31337 | 25604 | 25676 | **+145** |
| 平均 | | | **+193（SE ≈ 57，约 3.4σ）** |

机制也测到了，而且方向正确：

| | 老师一致率（总体） | 老师一致率（区域内） | 与 ck-best 头对头 | 对外部基线 |
|---|---|---|---|---|
| ck-best | 0.858 | 0.781 | — | +1150 |
| **微调后** | **0.865** | **0.808** | **−13** | **+1386** |

注意最后两列的搭配：**镜像对局毫无变化（−13），增益全部来自对外部对手**——
这与第 13 节的陷阱正好相反，是「真实力」的特征。

**为什么「硬替换」亏而「微调」赚**：硬替换把区域内 100% 的决策换成老师的选择，
包括学生本来对的那部分；微调只把决策分布**朝老师的方向推**，
学生在有把握的地方基本保持不动。同一个老师，两种用法，效果符号相反。

### 19.7 强化学习那半份数据的对照实验

训练混合里有一半是自博弈 RL 数据（标签是学生自己的动作 + 整局得失回报）。
从同一权重出发、超参完全一致，只改数据：

| 训练数据 | 模仿准确率 | 对外部基线 | 与另一版头对头 |
|---|---|---|---|
| A：纯模仿（900k 老师标签） | 0.905 | **25537** | −101 |
| B：循环实际的混合（含 848k RL 条） | 0.869 | 25491 | — |

两个独立指标同号：RL 那半份让对外分数**低了约 100 分**（各自约 1σ，方向一致）。
再看 `data/training_state.json` 的历史：`imitation-v9` 阶段之后循环跑了 **10 轮 RL 迭代，
没有任何一轮的绝对分超过它**（最优分一直停在 25543）。综合起来：

**结论：在当前算力下，这份 RL 数据没有价值，至少不该占一半权重（第 12 节再次确认）。**

### 19.8 循环的新模式

据此把长期训练循环改成 **DAgger 迭代**（`--dagger-loop --dagger-region-shanten 2`）：
每轮用当前权重走 3000 局（保持状态分布 on-policy），只在向听 ≥2 的自己回合弃牌上打老师标签，
然后纯模仿训练（不再有策略梯度行）、照旧用 4800 局配对评测决定接受或回滚。
循环的接受/回滚机制不变，所以即使新配方无效也只会原地踏步，不会变差。

```bash
.venv/bin/python -u python/trainer/loop.py --forever --resume \
  --dagger-loop --dagger-region-shanten 2 --search-modes \
  --lr 5e-5 --epochs 2 --eval-games 9600 --games-per-iter 3000 \
  --mixed-fraction 0.66 --max-records 900000 --replay-window 1 \
  --bootstrap-data data/selfplay/im-v9.bin
```

`--search-modes` 让循环**轮换一组有依据的配方**（区域 sh≥2 / sh≥3 / 全量 DAgger /
区域+鸣牌窗口 / 区域+更大步长），而不是反复用同一条。第 18、19 轮的实测说明
「同一条配方连用第二次会回退」，所以轮换 + 严格回滚才是后台长期搜索的正确形态：
每轮都按同一套配对评测判定，**变差就回滚**，因此这个搜索只会花时间，不会把服务的权重弄差。

### 19.9 本轮新增的工具

| 工具 | 用法 | 用途 |
|---|---|---|
| `--greedy --epsilon 0` 对齐诊断 | `mmj-selfplay generate` 两次 | 逐行比对学生与老师（19.1） |
| `assisted:PATH?sh=2&calls=1` | `mmj-eval --a ... ` | 教师代打某区域，定位学生弱区 |
| `filter:no-riichi:PATH` 等 | `mmj-eval --a ... ` | 战略消融：禁用/强制立直、鸣牌 |
| `--dagger-shanten N` / `--dagger-calls` | `mmj-selfplay generate` | 只在这些决策上打老师标签（区域 DAgger） |
| `--dagger-loop` | `trainer/loop.py` | 把长期循环切换成 DAgger 迭代 |

### 19.10 循环第一次迭代的结果：这是「一次性」增益，并暴露了接受判据的缺陷

把 19.6 的配方接进循环后，第 18 轮（从 ck-region 出发、重新生成 3000 局区域数据、
纯模仿训练两轮）的实测是：

| 指标 | 结果 |
|---|---|
| 对冻结基线（9600 局，种子 4242） | 25546（基线 24454）= **+1092**，比 ck-region 的 +1386 低约 290 |
| 对 ck-region 头对头（4800 局，种子 5150） | 24929 : 25071 = **−142** |

也就是说：**同样的配方连着用第二次会回退**，这与第 10 节的教训一致——
模仿得过头就开始完整继承老师的弱点。第一剂之所以有效，是因为它把学生
从「比老师差」补到「和老师一样」；再补就过头了。

同时这次暴露了一个**真实的判据 bug**：循环存下来的 `best_score` 是 4800 局测的，
而我在命令行上把 `--eval-games` 改成 9600，于是「9600 局测出的 25546」被拿去和
「4800 局测出的 25693 − 150」比较，一个刚刚回退的权重**以 3 分之差通过了接受判据**。
（`best` 仍然正确地停在 ck-region，所以对外服务没有受影响。）

修了两处：

1. **协议不一致时先重测**：启动时若 `--eval-games` 与状态里记录的不同，
   先用当前局数重测一遍 `best`，再更新 `best_score`（状态里现在会记 `eval_games`）；
2. **接受判据改成单边**：新权重必须 `>= best_score` 才能成为新的 `base`，
   原来的 `−150` 容差等于允许「稍微变差也算进步」，会让搜索从更差的点继续。

## 20. 第 9 轮：热路径优化 + 「一剂有效、复剂有害」的确认

### 20.1 每个决策有一半时间花在特征编码上（新工具：`bench-encode`）

`mmj-selfplay bench` 一直只测网络前向，从没人测过**编码**。本轮补上后，结论立刻变了：

| 项目 | 耗时 |
|---|---|
| 网络前向（768×768，703 维输入） | 95.7 µs |
| 观测编码（同一个决策） | 102.9 µs |

也就是说，自我博弈和评测里**每个决策大约一半的时间不是在算网络，而是在算特征**——
而评测占训练循环一轮时间的约 70%，所以这是最大的一块可优化成本。

继续把编码拆开看，问题非常集中：

| 编码内的块 | 耗时 |
|---|---|
| **8× `ukeire_count`（进张数）** | **156.5 µs** |
| 34× `tile_keep_value` | 0.2 µs |
| 34× shanten（弃牌前瞻） | 4.4 µs |
| 34× `yaku_score` | 2.9 µs |
| `danger_table_full` | 0.9 µs |

`ukeire_count` 会对 34 种牌各算一次向听，而其中**大多数牌根本不可能降低向听**：
一张既不在手牌里、又不与任何手牌相距 1–2 的孤立牌不可能组成搭子，因此对任何牌型
都没有帮助（唯一例外是国士無双——它要的正是手里没有的么九牌）。

据此加了一个候选剪枝（并且只在 `kokushi_shanten <= base` 时才保留么九候选，
这是**精确**条件而非近似）。为了防止这种「看起来显然」的优化悄悄改变行为，
我加了一个 4000 副随机手牌的属性测试，逐副和暴力实现对比进张数：

```rust
assert_eq!(ukeire_count(&counts, melds, &visible), brute, ...);
```

结果：进张块 156.5 → **93.2 µs**，整体编码 102.9 → **75.6 µs（1.36×）**，
而编码在总决策成本里的占比从约 52% 降到约 44%。

### 20.2 顺手修掉一个规则级遗漏：振听的立直者不是威胁

`danger_table` 只判断「谁在立直」，没有判断「这个人还能不能荣和」。但规则上：

* 立直后见逃（`riichi_furiten`）＝ 本局**再也不能荣和**；
* 同巡振聴（`temp_furiten`）＝ 直到自己下次摸牌前**不能荣和**。

对这样的对手，牌河里**每一张牌都绝对安全**（他只能自摸），而旧代码仍然把他当作满威胁，
让老师无谓弃和、也让网络的安全度特征读到错误的值。注意这**不等于**捨て牌振聴：
后者只封住他自己的舍牌，而那部分本来就被「现物」覆盖。

修正后加了两条单元测试（立直振听 → danger 全 0；同巡振听 → 下次摸牌后威胁恢复）。

### 20.3 「一剂有效、复剂有害」：用完全相同的形状复现，确认结论

第 8 轮的 +193 来自「从 ck-best 出发、只用区域数据（向听≥2 的自己回合弃牌）、
2 轮 lr 5e-5、**不带锚点**」。循环里的第 18—20 轮都是同配方但**带 900k 锚点**，
全部回退。为了排除「是锚点稀释了」这一解释，本轮用**与已验证配方逐字相同**的形状、
只用新牌局（种子 9091）从当前最优 ck-region 再打一剂：

| 种子 | ck-region | 第二剂 | 差 |
|---|---|---|---|
| 4242 | 25692.8 | 25520.4 | **−172** |
| 5150 | 25667.3 | 25598.6 | **−69** |
| 31337 | 25676.1 | 见日志 | |

也就是说：**增益是一次性的**。第一剂把学生从「比老师差」补到「不差于老师」，
再补就变成过度模仿（第 10 节警告过的机制）。加上循环第 18—20 轮的三个负结果，
五次测量全部为负——重复剂量会回退，这一点现在可以当作结论。

### 20.4 顺手证伪了「第三级老师」这条梯子

第 14 节记过「非立直威胁（把有鸣牌的开展手也算威胁）+264，1.9σ」，当时就标注为存疑。
本轮用同一个会话、同一批牌局、三个种子直接量了两位老师（都是 4800 局对冻结基线）：

| 老师 | 种子 4242 | 5150 | 31337 | 平均 |
|---|---|---|---|---|
| v2（当前训练用的老师） | +743.0 | +706.8 | +754.8 | **+735** |
| v3（把开展的手牌也算威胁） | +596.8 | 见日志 | 见日志 | 更低 |

**v3 比 v2 差**，那个 +264 是噪声。结论：这条梯子没有下一级，
而且顺带解释了一件早就该注意的事——编码器里的安全度特征其实是用
**v3 级模型**（`open_threats=true, strict_suji=true`）算的，也就是网络看到的安全度
比它模仿的老师还要细。特征更细不是坏事（网络可以选择不用），但它不是提升的来源。

**顺带得到一个可引用的现状数字**：学生 `ck-region` 对冻结基线是 **+1358**，
而它自己的老师只有 **+735**——学生已经比老师强约 620 分。

### 20.5 一个流程事故：循环的清理逻辑删掉了历史参考权重

循环为了省磁盘会「保留最优 + 最近 3 轮」的权重。第 8 轮我把 `state["best"]` 指向
`ck-region.bin` 之后，**`ck-best.bin` 立刻变成了"旧文件"并被自动删除**——
而它正是后面所有分析要拿来做参照的那个权重（+1150 的那个）。

好在它还在 `/tmp/ck-v9.bin` 里（`info.step = "im-v9-tuned-teacher"`，与 state 历史里
那条记录同名），恢复后用同种子重测：**25574.84375，与事故前的记录逐位一致**，
身份确认无疑。

两处改动：

1. **参考权重移出清理范围**：放在 `data/reference/`（清理只扫 `data/checkpoints/`），
   现在有 `data/reference/ck-v9.bin`；
2. **清理逻辑改为永不删除**：`best`、`base`、被保护的名字（`ck-ref-*`）以及
   `state["protected"]` 里列出的文件。

教训写在这里：**任何"为了省空间"的自动清理，都必须先把"被分析引用的文件"排除在外**，
否则它会安静地把量尺本身删掉。

### 20.6 本轮最重要的发现：**「三个种子」验证不了「训练本身」的随机性**

第 8 节那个 +193 是这么测出来的：从 `ck-best` 出发微调一次得到 `ck-region`，
然后在**三个评测种子**上量它（+236 / +199 / +145），三个都正，看起来非常可靠。

本轮做了两件事把它推翻：

**一、用同一配方、不同牌局重跑（归因实验）**。两条臂从同一个参考权重的同一批局面出发，
形状完全一致（只用 on-policy 标签、无锚点、2 轮 lr 5e-5），只差「标签是否限制在向听≥2」：

| 臂 | 对冻结基线（种子 4242） | 相对参考权重 |
|---|---|---|
| 区域标签（复刻第 8 轮配方） | 25570.9 | **−9** |
| 全量标签 | 25639.5 | **+100** |
| `ck-region`（第 8 轮那一次） | 25692.8 | +236 |

两条臂的**配对头对头是 +9（完全打平）**——所以「区域聚焦」并不是有效成分。
更关键的是配对测量（4800 局、种子 5150，同牌局）：

| 配对 | 结果 | 判读 |
|---|---|---|
| 区域臂 vs 未动过的参考权重 | 24987.8 : 25012.2 = **−24** | 复刻的那一次**没有增益** |
| 区域臂 vs 全量标签臂 | 25004.6 : 24995.4 = **+9** | 两种标签**没有差别** |

而第 8 轮那一次在绝对评测上是 +236。同一配方、同样的形状、只换了标签用的那批牌局，
结果一个 +236、一个 −24。

**二、结论**：那三个种子量的是**同一个权重**，它们只能证明「测量是准的」
（顺带一提，测量确实很准：把参考权重换一个二进制、换一个会话重测，
`25574.84375` 逐位一致），**完全不能证明「这个配方稳定有效」**。
微调这件事本身带有一个 ±150~250 的随机量（数据顺序、标签牌局、初始化噪声），
第 8 轮抽到了好的那一次。

**修正后的诚实估计**：这个配方（在当前最优上再做一轮 on-policy 教师标签的监督微调）
的期望收益在 **0 ~ +120** 之间，且三次复刻（+236 / −9 / +100）的标准误约 120
——即「有微弱正效果，但远没有 +193 那么确定」。`ck-region` 仍然是被实测最好的权重
（它的**测量值** 25692/25667/25676 是可靠的），在线服务的也仍是它，
但「它比上一版强 193 分」这个说法必须撤回。

**流程上的修补**：循环现在要求「复现确认」——候选权重的对外分数超过历史最优时，
**不立即提拔**，而是用同一配方、换一批牌局再跑一次；两次都超过最优才更新 `best`
（`--confirm-runs 2`）。这条规则正是从本轮的教训里长出来的。

| 轮次 | 配方 | 对外分数（9600 局） | 判定 |
|---|---|---|---|
| 18 | 区域 sh≥2 + 锚点 | 25546 | 回滚 |

| 20 | 区域 sh≥2 + 锚点 | 25599 | 回滚 |

### 20.8 循环现在的形态

循环每轮从**当前最优**出发，轮换一组配方（区域无锚点 / 区域带锚点 / 更宽的向听区间 /

**对外分数低于历史最优就回滚**。因此长期后台搜索只会花时间，不会让服务的权重变差。

## 21. 第 10 轮：推理核函数到底被什么限制（以及由此推出的唯一提速方向）

### 21.1 先量清楚：不是分支，也不是算力，是**权重带宽**

上一轮把编码器提速了 1.36×，本轮转向另一半——网络前向。先用 `bench-encode` 量了一个
此前没人问过的问题：**前向耗时随输入稀疏度怎么变**（特征约 75% 是零）：

| 非零特征数 | 前向耗时 | 等效权重流量 |
|---|---|---|
| 703（全满） | 137.7 µs | 24 GB/s |
| 512 | 143.7 µs | 19 GB/s |
| 256 | 96.4 µs | 20 GB/s |
| 128 | 73.2 µs | 21 GB/s |
| **32** | **77.8 µs** | 16 GB/s |

两个结论：

1. **去掉"跳过零"是灾难**：把内层循环改成稠密无分支后，前向从 72.6 µs 涨到 **294.6 µs**。
   （我一开始以为那个 `if xj == 0.0 { continue }` 会挡住自动向量化，结果实测相反——
   跳过四分之三的乘法远比向量化划算。）
2. **但只剩 32 个非零特征时仍要 77.8 µs**，说明大头是**固定成本**：第二层
   （768×768）的隐层激活经 ReLU 后仍是稠密的，它的权重行必须全部过一遍。
   折算下来核函数只跑到 **约 24 GB/s 的权重流量**（4.5 MB 的 f32 权重、每 4 字节
   只做 1 次 FMA），已经接近这台机器的内存带宽上限。

**结论：任何内层循环的花招都救不了它**——想提速只能减少权重的字节数。

### 21.2 顺带做的两件事

* 把核函数改成"先收集非零下标、再在热循环里无分支遍历"。性能**持平**
  （72.5 µs vs 72.6 µs），但结构更清楚，而且加了一条**逐位等价**回归测试
  （稀疏核 vs 朴素稠密实现，覆盖全零/全非零/随机六种输入）；
* 端到端验证：改动后 `ck-region` 对基线的配对评测结果
  **25692.770833333332 逐位不变**，证明这次改写没有改变任何行为。

### 21.3 由此得到的唯一两条提速路线

| 路线 | 预期 | 代价 |
|---|---|---|
| **更窄的网络**（768→512） | 前向权重流量 4.5 MB → 2.5 MB，约 **1.8×**；训练同样快 1.8× | 需要重训与强度验证 |
| **int8 量化权重** | 流量再降 4×，理论 3-4× | 需要写 SIMD 量化核 + 精度验证（决策翻转率） |
| 批量前向（多局同批） | 权重加载一次供 4 局复用，约 2-3× | 评测/自博弈要改成"多局同步推进"，改动最大 |

前两条都要在强度上付代价（21.5 已经量出代价的大小），只有**批量前向**是纯赚：
内核受"每个权重只做一次 FMA"限制，如果同时推进 N 局、把 N 个决策拼成一次矩阵乘，
同一个权重行就能服务 N 个决策，流量降为 1/N，而**数值逐位不变**（每行的累加顺序没变）。
代价是评测与自博弈的主循环要改成"成组同步推进"，这是下一轮计划做的事。

### 21.4 第三次复现失败：循环自己重跑那条配方，也是负的

第 9 轮把「区域聚焦」这个说法否掉之后，我又让**循环自己**去跑那条"已验证配方"
（`region-noanchor`：向听≥2 标签、无锚点、6000 局、2 轮 lr 5e-5），种子由循环推导：

| 复现来源 | 数据种子 | 对外分数（对基线） | 相对 `ck-region` |
|---|---|---|---|
| 第 8 轮原始那一次 | 7777 | +1386 | — |
| 第 9 轮归因实验 | 7331 | +1141 | −245 |
| **第 10 轮循环第 25 轮** | 循环种子 | 25579（+1179） | **−72**（9600 局口径） |

三次独立复现里两次几乎为零、一次为负，而原始那一次是 +236。
**结论钉死：这条配方的期望收益约 0，第 8 轮那次是单次训练抽签抽到的**。
循环从第 9 轮起已经要求"复现确认"，所以这类抽签不会再被提拔成 `best`。

### 21.5 宽度实验：512 更快，但**不是免费的**（实测有强度代价）

既然核函数受权重流量限制，最直接的想法就是把网络变窄。第 11 节当时说
「768 对比 512 略好，成绩在噪声内」——那是**单次 2400 局**的结论，本轮按第 9 轮的
教训重新做（两个独立训练副本、每个三个评测种子、外加配对头对头）。

速度（同一负载下的 `bench`，稠密输入）：

| 宽度 | 参数量 | 权重大小 | 前向 |
|---|---|---|---|
| 768×768 | 1,215,854 | 4749 KB | 272.9 µs |
| **512×512** | 679,534 | 2654 KB | **164.8 µs（1.66×）** |

两者都跑在 **16.5 / 17.8 GB/s** 的权重流量上——再次印证 21.1 的结论：时间基本由字节数决定。

强度（512 副本 vs 768 参考权重 `ck-v9`，同为 4800 局配对）：

| 评测种子 | 512 对基线 | 768 对基线 | 差 |
|---|---|---|---|
| 4242 | +1020 | +1150 | **−130** |
| 5150 | +1016 | +1136 | **−120** |
| 31337 | +724 | +1207 | **−483** |
| **配对头对头（5150）** | — | — | **−195.5** |

**上面这张表曾经让我写下"变窄要付 150~250 分代价，所以不划算"——这个结论是错的，
因为第二个副本把它推翻了。** 我把同样的配方、只换随机种子又训了一个 512 副本：

| 512 副本 | 对基线（4242 / 5150 / 31337） | 均值 | 与 768 的配对头对头 |
|---|---|---|---|
| 副本 31 | +1020 / +1016 / +724 | +920 | **−195** |
| 副本 47 | +1025 / +1139 / **+1715** | **+1293** | **+237** |
| 768 参考（单次） | +1150 / +1136 / +1207 | +1164 | — |

两个**完全相同配方**的副本，均值差了 373 分，配对头对头一个是 −195、一个是 +237。
也就是说：**宽度的强度效应完全被"单次训练"的随机波动淹没了**，n=1 vs n=2 根本量不出来。
（我一开始拿副本 31 的 −195 当结论，正是第 9 轮刚学过的错误又犯了一次——
只不过这次换成了"训练副本"这一层。）

**修正后的诚实表述**：512 的 **1.66× 速度提升是确定且可复现的**；
强度差异**未测出**（配对 −195 与 +237 符号相反，绝对分均值 −244 与 +129）。

### 21.5b 本轮量到的第三个、也是最贵的一个数：**单次训练的波动约 ±200~400 分**

这是本轮真正重要的结论，也是整个项目此前所有"某配方 +200 / −150"结论都需要重估的原因：
**同一个配方、只换随机种子，测出来的强度可以差 300~400 分**（21.5 的两个 512 副本）。

前九轮里绝大多数对照实验都是 **n=1（每边只训一次）**，所以那些 ±150~250 的"结果"
其实全部落在单次训练的噪声里。25 页文档里那些"某次改动 −152 / +264 / −249"的记录，
按这个尺度看都应当标为"未测出"。

**这不是说那些结论都反了，而是说它们的置信度被高估了。** 从现在起，凡是要下
"某配方更好/更差"的判断，至少要有 2 个独立训练副本，最好 3 个；
循环里的评测只是"这道题有没有做对"的单次抽检，不能当配方结论用。

### 21.6 重要更正：21.1—21.3 的量测被**我自己的后台任务污染了**

写到这里我意识到上面的结论不对劲：如果核函数真的被带宽限制，那把权重变小应该线性见效，
而 512 的实测只快了 1.66×（参数量少 1.79×）。于是我把**所有后台任务停掉**，
在安静机器上重测同一套东西：

| 项目 | 并发时（污染） | **安静机器（真值）** |
|---|---|---|
| 编码 | 55 ~ 92 µs | **35.6 µs** |
| 前向 | 72 ~ 250 µs | **36.1 µs** |
| 768×768 axpy | 4.2 GFLOP/s | **36.4 ~ 39.2 GFLOP/s** |
| 4800 局评测 | 150 ~ 300 s | **89.3 s（53.8 局/秒）** |

**结论完全反过来**：核函数跑在 **36~39 GFLOP/s**，而单核 AVX2+FMA 的理论峰值就是约
37 GFLOP/s——它**已经贴着硬件峰值**，既不是带宽受限，也不是没向量化。
21.1 里"每 4 字节只做一次 FMA、只跑到 24 GB/s"那段是被并发任务抢出来的假象
（训练把 8 个核占满时，前向会慢 2~7 倍）。

真正的每个决策成本（安静机器）：**编码 35.6 µs + 前向 36.1 µs ≈ 72 µs**，
加上引擎与决策生成约 19 µs，端到端 91 µs/决策。

**这条教训要写在显眼位置**：测性能时不能让训练循环同时跑。前两轮的所有"吞吐优化"
都是在污染环境下对比的，比值勉强可用，绝对值全部偏高。

### 21.7 那么还剩什么提速空间

| 方向 | 安静机器实测 | 判决 |
|---|---|---|
| f32 分块内核（`add_scaled`） | 36.4 → 39.2 GFLOP/s（1.08×） | **保留**（无代价、逐位一致） |
| 批量前向（n=2/4/8） | 0.76× / 1.17× / 1.28× | 放弃：收益不值"多局同步推进"的改造 |
| 缩窄网络到 512 | 前向 1.66×，但强度 **−195（配对）** | 放弃（21.5） |
| int8 量化权重 | 理论 MACs/指令 ×4（AVX2 `vpmaddubsw`） | 未做；这是唯一还剩的大杠杆 |
| **不要在跑训练时测性能 / 跑实验** | 迭代时间从 16 分钟回到 6~8 分钟 | **立刻采用** |

最后一条其实是本轮最大的"吞吐收益"：循环第 24、25 轮耗时 951 s / 764 s，
而同样的工作在空机上只需 300~400 s——我把机器占满了两个轮次。

## 22. 第 11 轮：一半的模仿信号其实是噪声（平局感知的目标函数）

### 22.1 问题：老师有一半的决策是"随便挑的"

第 19 节量过一件事但没有据此改目标函数：学生与老师的**分歧**里有 52% 是
"向听相同、进张相同"的等价选择。本轮把范围从"分歧"扩大到**所有模仿行**去量：

| 平局判据 | 属于平局的模仿行 |
|---|---|
| 只看「向听 + 进张」 | **53.9%**（平均每组 2.87 个等价选择，最多 8 个） |
| 再加上「安全度 + 保留价值」也要相同（收紧） | **25.1%**（平均 1.39） |

也就是说：**四分之一的训练样本在逼网络复制老师的一个任意选择**——老师自己在这个
局面里没有任何偏好，规则里两个选择完全等价，是代码里的 tie-break 顺序决定的。
用 one-hot 去拟合这种标签，等于把纯噪声当成"正确行为"灌进策略，而且是在
**最需要精细判断的那类局面**（同向听、同进张，胜负只差毫厘）。

收紧判据很重要：如果只看向听和进张，会把老师**故意**的偏好（为了安全或役种
而留一张进张略少的牌）也当成"等价"，那就把有用的信息抹掉了。

### 22.2 做法：把目标从 one-hot 换成"等价集合上的分布"

`train.py --tie-aware`：从**已有的特征块**重建设等价集合，不需要改数据格式。

* `LOOKAHEAD`（492..526）给出每种牌打出后的向听：`(8 - shanten) / 9`
* `UKEIRE`（526..560）给出该打法的进张：`count / 24`
* `KEEP_VALUE`（560..594）、`DANGER`（594..628）用同一套编码
* 老师的选择所在的组（普通弃牌 vs 立直弃牌是**不同**动作，不能混）

目标分布 = 等价集合上的均匀分布；集合退化成一个元素时就是原来的 one-hot。
损失仍是交叉熵：`-(target * log_prob).sum()`。

自检（4096 行真实数据）：目标和恒为 1、老师的选择始终有正质量（最小 1/8）、
无非法槽位、`|T|>1` 占 25.1%。

### 22.3 循环的判定也改成"多副本取均值"

第 10 轮量到**同一个配方、只换训练随机种子，强度可以差 373 分**。
而循环此前是"训一个副本 → 测一次 → 超过历史最优就接受"，这本质上是在抽签。

新增 `--replicate-runs N`：同一个候选训练 N 个独立副本（只变 `--seed`），
* **判定用 N 个副本的均值**（对"配方"的无偏估计，而不是对"最幸运那次"的估计）；
* **血脉从测得最好的那个副本继续**（服务给用户的仍是最强的那份权重）；
* 状态里同时记录 `replica_scores` 与 `group_mean`，趋势报告因此能看到配方级的噪声。

配合已有的"复现确认"（换一批牌局重跑），循环现在的判定链是：
**均值超过历史最优 → 再用新数据复现一次 → 两次都过才提拔**。

### 22.4 四个独立副本：这条配方的效应是 **+96 分**，而且噪声比想象的小

`--replicate-runs` 的第一步就是把它用在最该用的地方：把"区域 DAgger 一剂"
（从 `ck-v9` 出发、用当前权重走棋、老师打标签、2 轮 lr 5e-5）**训四次**，
每次都在两个评测种子上量。四个副本与未加剂的参考权重 `ck-v9` 对比：

| 副本 | 种子 4242 | 种子 5150 | 均值 |
|---|---|---|---|
| 101 | +1210.7 | +1264.7 | +1237.7 |
| 202 | +1093.3 | +1261.7 | +1177.5 |
| 303 | +1233.3 | +1348.1 | +1290.7 |
| 404 | +1268.3 | +1230.1 | +1249.2 |
| **组均值** | | | **+1238.8** |
| `ck-v9`（未加剂，2 个种子） | +1149.7 | +1135.8 | +1142.8 |

**效应 = +96.0 ± 23.4（t ≈ 4.1）**，副本间标准差只有 **46.8 分**。

这个结果同时修正了两件事：

1. **第 8 轮的 +193 与第 9/10 轮的"效应约等于 0"都不对**：真实效应是 +96 左右——
   第 8 轮那次抽到了上尾，第 9/10 轮我用 1~2 个副本去否定它，样本量不够。
2. **"单次训练波动 373 分"并不是普遍规律，而是那个配方的特性**：373 分来自
   **bootstrap 配方（lr 1e-3、4 轮）**；本轮循环实际使用的温和配方（lr 5e-5、2 轮）
   副本间只有 ~47 分。也就是说**激进的学习率才是不可复现的来源**，
   温和配方的单次训练是可以信任的（±50 量级）。

机制上也说得通：这一剂是 **DAgger**——用学生自己走出的状态、配老师的标签，
补的是"行为克隆的分布偏移"。所以它只在**第一次**有明显作用（把分布偏移补掉），
之后再补就是重复劳动——这正好解释了循环里所有"第二剂"都是 −70 ~ −20
（第 18—30 轮全部回滚）的原因。

### 22.5 平局感知目标的第一个结果：**更弱**（同名种子匹配比较 −186）

这是本轮设计得最干净的一组对照：**同一份数据、同一个起始权重、同一个随机种子**，
唯一差别是目标函数（one-hot vs 等价集合上的均匀分布）：

| 组 | 种子 | 对基线（4242 / 5150） | 均值 |
|---|---|---|---|
| 对照（one-hot 目标） | 101 | +1210.7 / +1264.7 | **+1237.7** |
| **平局感知（软目标）** | 101 | +1080.1 / +1022.6 | **+1051.3** |

**软目标反而低了约 186 分。** 配对同种子、同数据、同初始化，对照组副本间的标准差只有
约 47 分，所以这个差距不是噪声。剩余 3 个副本（202/303/404，同样的匹配种号）正在跑，
用来确认这个负结果。

为什么"少灌噪声"反而更弱？目前的假说是：
**等价集合的定义仍然太宽**——它只包含老师自己显式使用的四个判据
（向听、进张、保留价值、危险度），但一个局面里两个"四判据相同"的打法，
在**手牌形状/宝牌/进张质量**上仍可能不同，而这些差别 one-hot 目标会（通过老师的
最终选择）间接传递给学生，软目标却把这份信息抹平了。
换句话说：**老师"任意"的选择里，仍然携带了它自己都没显式建模的信息**——
这与第 10 节"准确率高不等于更强"是同一类现象的另一个侧面。

四个**同名种子匹配对**全部跑完（每对：同数据、同起始权重、同随机种子，只换目标函数）：

| 种子对 | 对照（one-hot） | 平局感知（软目标） | 配对差 |
|---|---|---|---|
| 101 | +1237.7 | +1051.3 | **−186.4** |
| 202 | +1177.5 | +1009.8 | **−167.7** |
| 303 | +1290.7 | +1309.6 | +18.9 |
| 404 | +1249.2 | +973.4 | **−275.8** |
| **组均值** | **+1238.8** | **+1086.0** | **−152.8（sd 130）** |

**结论：平局感知的软目标让 AI 更弱，而且更不稳定**（实验组副本间 sd 约 147，
对照组只有 47）。`--tie-aware` 默认关闭。

这条负结果本身很有信息量：它说明**老师那个"任意"的选择里，仍然带着它自己没有
显式建模的偏好**——四个判据（向听/进张/保留价值/危险度）相同的两个打法，
在手牌形状、宝牌、进张质量上仍有差别，而 one-hot 目标通过老师的最终选择
把这些差别间接传给了学生，软目标把它们抹平了。
换句话说：**"少灌噪声"这个直觉在这里是错的，因为那部分"噪声"其实是隐含信号。**

## 23. 第 12 轮：把评测时间砍掉一半（提前停止），以及量化内核的结论

### 23.1 评测是循环里最贵的一块，而它经常在测「早就知道答案」的东西

循环每轮的耗时构成（安静机器）：训练 ~1.5-2 分钟、自博弈 ~1.5 分钟、
**评测 9600 局 + 头对头 4800 局 ≈ 4.5 分钟**。而绝大多数候选落在历史最优**之下** 50~200 分，
对着一个已知的合格线把 9600 局跑完（再跑一次头对头）属于纯浪费。

做法：**把 9600 局拆成两个 4800 局的一半，先跑一半**，如果这一半的平均分比合格线
（历史最优 + 接受余量）低出 `--early-stop-slack`（默认 100），就直接判负、
**不跑另一半、也不跑头对头**。

拆分的正确性必须验证——不然接受判据就成了错的。验证方式是让第二次调用从牌流中间接着跑
（`--seed + offset`），实测：

| | 平均分 | 局数 | 胜 |
|---|---|---|---|
| 整轮 4800 局 | 25610.677083 | 30368 | 11528 / 13348 |
| 前半 2400 局 | 25616.458333 | 15161 | 5730 / 6679 |
| 后半 2400 局（offset 2400） | 25604.895833 | 15207 | 5798 / 6669 |
| 两半平均 | **25610.677083 ✓ 完全一致** | 30368 ✓ | 11528 / 13348 ✓ |

**逐项相等**，所以"先跑一半"与"跑满"在数学上是同一件事，只是可以提前收手。

代价与收益（前半的评测噪声 SE ≈ 140）：
* 真实水平**明显落后**的候选（−150 分）：约 86% 会被提前判负；
* 真实水平**刚好在线上**的候选：约 16% 会被误停——但那种候选本来就在接受线附近，
  影响的是"差一点点的改进"，而本项目真正在乎的是 ≥ +100 量级的效应（几乎不会误停）。

实测（循环第 32 轮）：前半 4800 局见分晓（25568，合格线 25711），
**整轮 332 秒**跑完（此前同类轮次 870~1060 秒）。状态里会记 `partial: true`，
趋势分析时能区分"半测"与"全测"。

### 23.2 量化内核：i16 只有 1.3×，i8 要 200 行汇编级代码

f32 内核已经贴着单核 FMA 峰值（21 节），所以只能减少"每条指令做多少次乘加"：

| 内核 | 每次指令的乘加数 | 实测 |
|---|---|---|
| f32 FMA | 8 | 基准 |
| i16 `vpmaddwd` | 16 | **1.27×**（且测量时机器仍被占用，只能算参考） |
| i8 `vpmaddubsw`（理论） | 32 | 未实现，估计 2~2.7× |

i16 的收益远小于理论值：它把权重带宽减半，但内核是**算力受限**的，
而 `vpmaddwd` 每个结果还需要一次 i32 累加，摊下来每 16 次乘加仍需约 3 条指令
（f32 是每 8 次乘加 4 条）→ 只有 1.3 倍。

要把i8 做出来需要：加载时按输出列量化权重（含 u8 偏置修正）、每层激活量化、
`vpmaddubsw` + 周期性 i32 加宽、最后反量化，约 200 行 SIMD 代码 + 精度验证
（决策翻转率）。**收益约 1.3×（端到端），风险中等**，因此本轮只做了测量与设计，
没有动主干——记在这里，作为"还有一个确定的 1.3× 可选"。

**另一个结论**：本轮的两次内核对比都因为后台还在跑训练而失真
（同一次运行里 zip/chunks 的比值甚至出现 2.02× 的荒谬结果）。
再次印证第 21.6 节：**测性能时机器必须是空的**。

### 23.3 两个剂量臂的对照：标签覆盖范围**不重要**

第 11 轮量出"区域标签（只标向听≥2 的自己回合弃牌）"这一剂值 **+96**。
本轮把同一实验的**全量标签**臂补齐（每一条决策都让老师打标签），
四个副本、同名种子、同数据量（都截到 900k 行）、同超参：

| 副本 | 区域标签（第 11 轮） | 全量标签（本轮） | 配对差 |
|---|---|---|---|
| 101 | +1237.7 | +1267.2 | +29.5 |
| 202 | +1177.5 | +1244.7 | +67.2 |
| 303 | +1290.7 | +1088.9 | −201.8 |
| 404 | +1249.2 | +1274.2 | +25.0 |
| **组均值** | **+1238.8**（sd 46.8） | **+1218.7**（sd 87.5） | **−20.0 ± 61.3** |

**两者没有差别。** 加上第 9 轮的归因实验（同样显示区域聚焦无效），现在可以下结论：

> 这一剂的收益来自**DAgger 的状态分布**（用学生自己走出的局面、配老师的标签），
> 而不是"标签打在哪些决策上"。把标签预算摊给全部决策与只给中盘弃牌，
> 效果相同；换句话说，**行为克隆的分布偏移是全局性的，不是集中在某个区域**。

这也解释了循环里那些"换配方"的尝试为什么全部无效（第 18—33 轮）：
它们变的是**标签分配**，而真正起作用的那部分（分布修正）在第一次剂量里就用掉了。

**顺带修正现状数字**：被服务的 `ck-region` 是从 `ck-v9` 加了一剂得到的，
其**期望**强度是 +1239 左右（4+4 个副本测出来的），而不是第 8 轮单次抽到的 +1358。

## 24. 第 13 轮：加一把新尺子，结果发现旧尺子在骗我们

### 24.1 新量尺：打法统计（`mmj-selfplay stats`）

项目的旧量尺只有"对固定 bot 的配对得分"。它能说明**强多少**，但完全说不出
**这是个什么样的牌手**。而"逼近普通人类水平"这个目标必须用人类的度量方式来看，
所以我加了 `stats` 命令：跑 N 局、统计每手牌的**和了率 / 放銃率 / 立直率 / 副露率 /
流局率 / 自摸占比 / 平均打点**。

人类基准用有出处的公开统计：[天鳳鳳凰卓統計(2023)](https://blog.kobalab.net/entry/2024/11/04/215201)
（最高段位桌、168,778 半荘、1,791,086 局）。为了让条件可比，我这边也用**半荘+赤牌**
跑（平均局数 10.78 对基准的 10.61 ✓ 同一条件）：

| 指标 | **学生 `ck-region`** | 老师 v2 | **人类（鳳凰卓 2023）** |
|---|---|---|---|
| 和了率 | 0.168 | 0.191 | **0.211** |
| 放銃率 | 0.090 | 0.122 | **0.124** |
| 立直率 | **0.312** | 0.330 | **0.184** |
| 副露率 | **0.205** | 0.182 | **0.326** |
| 流局率 | **0.331** | 0.240 | **0.162** |
| 平均打点 | **8161** | 7980 | **5789** |

**这是一个"立直或弃和"的牌手**：几乎只要听牌就立直（1.7 倍于人类）、几乎不鸣牌
（只有人类的 63%）、三分之一的牌局直接流局（人类的 2 倍）、和牌时打点高 40%、
但**和牌次数比人类少 20%**。学生比老师更极端（放銃更少、流局更多）。

### 24.2 旧尺子的真相：+1386 是"打弱者的效率"，不是通用实力

顺着统计发现的不对劲，我量了学生对自己的**老师 v2**（同一套规则但修好了安全度模型、
调好了弃和阈值的手写 bot）：

| 检查点 | 对冻结基线 v1 | **对老师 v2（配对 4800 局）** |
|---|---|---|
| `ck-v9`（纯模仿阶段） | +1150 | **−649** |
| 剂量副本 `var-101` | +1239 | **−669** |
| 服务的 `ck-region` | +1386 | **−493** |

两个种子（−493 / −333）、交换 A/B（+444）都一致。也就是说：

> **"学生已经超过自己的老师"这个说法是错的。** 它在一张"2 个学生 + 2 个弱基线"的桌子上
> 赢得比老师多（+1386 vs 老师的 +735），但在"2 个学生 + 2 个老师"的桌子上**输约 500 分**。

这是"专精于打某个弱者"的典型形态：旧尺子（弱且被动的 v1）奖励的风格
（只打立直大牌、宁可不和也不放铳）在这个特定对手身上最赚，但并不迁移。
而那一剂"改进"（第 11 轮量到对 v1 +96 ± 23）在 v2 面前是 −20——
**连这个效应也是尺子特定的**。

### 24.3 因此给循环加了第二把尺子

`--yardstick2 efficiency-v2`：候选**必须同时不劣于**第二把尺子上的历史最优
（容差 50 分），否则一律回滚。状态里新增 `best_margin2`（当前 = `ck-region` 的 −493），
每轮记录 `margin2`。这样"靠牺牲对强手的表现去换对弱手的分数"的候选不会再被提拔。

**给目标的一句话总结**：`超过牌效率基线` 已经做到（对 v1 +1386），
但这**不等于**逼近普通人类水平——现在有两把尺子（人类打法统计 + 更强的对手）
可以把这个差距量出来，而不再靠形容词。

## 25. 第 14 轮：把优化目标换成"对强手的分"，并排除掉两条补差距的路

### 25.1 主判据换成强手（v1 降级为守卫）

第 13 轮证明旧尺子在骗人之后，本轮把循环的**接受判据换成对 v2 的配对分**：

```bash
python/trainer/loop.py --primary-spec efficiency-v2 --yardstick2 efficiency \
  --accept-margin 60 --confirm-runs 2 --early-stop-slack 100 ...
```

* **主判据**：候选 vs `efficiency-v2`（更强的手写 bot），9600 局，接受线 = 历史最优 +60；
* **守卫**：候选 vs `efficiency`（冻结基线）的配对分不得低于历史最优 50 分以上
  ——这样"靠牺牲对弱手的分去换对强手的分"的候选也会被拒。

接受基线重新标定到新尺子：`ck-region` 对 v2 是 **−391**（9600 局、种子 4242），
对 v1 是 +1386（守卫基线）。状态里记 `yardsticks = {primary, guard}`。

### 25.2 先排除两条"顺手的"补差距路径

**（a）重新调老师的弃和阈值？** 第 5 轮的 `fold_strength=2.5` 是对**弱基线 v1** 调出来的，
本轮在**强场**（四张桌子都是 v2 级别）重扫：

| fold | 对 v2 | 平均顺位 |
|---|---|---|
| 0.8 | −955.8 | 2.5374 |
| 1.2 | −850.2 | 2.5340 |
| 1.6 | −205.0 | 2.5080 |
| 2.0 | −152.5 | 2.5047 |
| **2.5（当前）** | **+138.3** | 2.4984 |
| 3.2 | −466.5 | 2.5156 |

曲线单峰、峰值就在当前设置 ⇒ **这条轴没有剩余空间**。
顺带得到一个重要的噪声标定：fold=2.5 那一行两边**配置完全相同**，
理论值应为 0，实测 **+138.3** ⇒ 4800 局配对评测的噪声就是 ~100~140 分，
**小于 ~150 的差距在这把尺子上根本分辨不出来**。

**（b）喂更多数据把模仿做得更准？** 第 10 节曾断言"模仿更准不等于更强"，
但那个结论**全部是在 v1 上量的**。本轮用同一配方、不同数据量训了两个模型，
并在**同一批留出行**上做统一保真度测量：

| 模型 | 训练量 | top-1 一致率 | top-3 | 对 v1 | 对 v2 |
|---|---|---|---|---|---|
| `ck-v9` | 2.4M×4 | **0.8943** | 0.9865 | +1150 | **−649** |
| `ck-region` | 微调剂 | 0.8953 | 0.9823 | +1386 | −493 |
| `hf-a` | 0.9M×4 | **0.8554** | 0.9779 | +1083 | **−396** |
| `hf-b` | 3.4M×4 | 0.8821 | 0.9845 | +1120 | −587 |

**保真度与对 v2 的表现没有正相关**（保真度最低的 `hf-a` 反而对 v2 最好）。
所以"多喂数据"这条路也排除了。

### 25.3 那么差距到底在哪：残差 11% 的一致性

把上面的数字放在一起看，结论很清楚：

* 学生在**老师走过的局面**上和老师一致率 0.89（top-3 0.986）；
* 但在"2 学生 + 2 老师"的桌子上它输 ~500 分；
* 而多数据、更大 epoch 都不能把 0.89 推上去（准确率在 0.89 附近饱和，与第 10 节一致）。

也就是说：**差的不是"看得多"，而是"最后那 10% 的一致性"**——
一个平滑的 MLP 在逼近老师那套**带阈值和字典序 tie-break 的离散规则**时，
永远会留下一层"抖动"，而这层抖动在强场里就是要付 500 分。

这恰好指向本项目**唯一被反复验证有效的机制**（第 14 节那条"老师变聪明 → 把它的判据也做成特征 → 重训"）：
现在的特征暴露了老师的**所有单项判据**（向听/进张/保留价值/危险度/役种），
却唯独**没有暴露它把这些判据合成最终选择的那一步**。

**下一轮的计划**：把老师对每个候选的**最终排序分**也做成一个 34 维特征块
（`TEACHER_SCORE`，特征维度 703 → 737），重新生成数据并重训。
预期：统一保真度从 ~0.89 升到 0.95+，对 v2 的分从 −400 附近向 0 靠拢
（对 v1 的分会相应降到老师本来的 +735 —— 这是**用"打弱者的效率"换"通用实力"**，
而后者才是"逼近人类"真正需要的）。

## 26. 第 15 轮：把老师的"合成判据"也做成特征 —— 第一个通用实力层面的真实提升

### 26.1 做法

第 25 节把差距定位到"最后 10% 的一致性"：平滑的 MLP 逼近老师那套**带阈值和字典序
tie-break 的离散规则**时会永久留下一层抖动。既然本项目**唯一被反复验证有效的机制**
就是"把老师的判据做成特征"，那就补上唯一没暴露的那一环——**老师把各项判据合成选择的那一步**。

新增 `mmj_core::pref`：独立复算老师对每个候选打牌的**偏好分**（不改动老师本身的代码，
以免悄悄改变标签）：

* **弃和分支**：安全牌优先，平局比保留价值（字典序，危险度权重放大 1000 倍）；
* **推牌分支**：只在"打出后向听最优"的候选里比
  `进张 + 2.5×役种数 + 0.8×宝牌保留数 − caution×危险度×40`；
* **立直怪癖**：老师一旦能立直就取动作列表里**第一个**可立直的牌，不再看自己的排序
  ——这个怪癖也一并复刻。

编码器新增 34 维 `TEACHER_RANK` 块（**703 → 737 维**），值是"以老师最优候选为 1.0、
其余按分差衰减"的指数形式。

**保真度验证**（`rust/mmj-ai/tests/teacher_ranking.rs`，60 局、16874 个决策）：
整体一致率 **0.9796**，其中**弃和分支 3332/3332、立直分支 475/475（都 100%）**，
残余 2% 全部落在推牌分支的"进张打平"情形（tie-break 的细节尚未对齐，测试里如实记录，
它同时是"学生能达到的保真度上限"）。

### 26.2 结果：保真度 0.85 → 0.97，对强手的差距减半以上

同一配方（3.4M 条 × 4 轮、lr 1e-3）、同规模的模仿数据（8000 局、v2 标签），
只差特征维度：

| 运行 | val_acc | 对 v1（冻结基线） | **对 v2（强手）** |
|---|---|---|---|
| 第 14 轮 `hf-b`（703 维） | 0.849 | +1119.9 | **−586.8** |
| `ck-tr`（737 维） | **0.969** | +1102.7 | **−265.2** |
| `ck-tr2`（737 维，另一个种子） | — | +1269.0 | **−196.3** |

两个独立副本都把**对强手的差距缩小了 320~390 分**，而对冻结基线的分没有损失
（+1103 / +1269 对 +1120）。9600 局口径下 `ck-tr` 对 v2 是 **−117.7**（顺位 2.5064）。

**这是本项目第一次在"通用实力"这个维度上量到真实提升**——之前所有"进步"要么只对
弱基线成立（第 13 轮），要么是单次抽签（第 8/9 轮）。

### 26.3 顺带量到的新线索：鸣牌决策上的偏移还在

用 `stats --hanchan` 量 `ck-tr` 的自博弈打法，和它的老师对比：

| 指标 | `ck-tr` | 老师 v2 |
|---|---|---|
| 和了率 | 0.184 | 0.191 |
| 放銃率 | 0.108 | 0.122 |
| 立直率 | 0.362 | 0.330 |
| **副露率** | **0.103** | **0.182** |
| 流局率 | 0.268 | 0.240 |
| 平均打点 | 8585 | 7980 |

在**老师走过的局面**上一致率 0.969，但在**自博弈**里鸣牌率只有老师的 57%——
说明抄牌决策的分布偏移仍然存在（自博弈中它很少鸣牌 → 很少进入"副露手"状态 →
那类状态上的行为没被纠正）。这正是 DAgger 该补的地方，也是循环里
`--dagger-calls` 配方要针对的目标。

### 26.4 血脉已迁移

循环现在跑在 737 维新血脉上：`best/base = ck-tr`，主判据 = 对 v2（9600 局 −117.7），
守卫 = 对 v1（4800 局 +1206），bootstrap 数据换成新生成的 `im-v11.bin`。

## 27. 第 16 轮：两个机制叠起来才生效 —— 对强手首次转正

### 27.1 线索：在老师状态上 96.9% 一致，自博弈时却只有老师一半的鸣牌率

第 15 轮量到 `ck-tr` 在**老师走过的局面**上一致率 0.969，但自博弈的副露率只有
0.103（老师 0.182）——**抄牌决策上的分布偏移仍在**：它很少鸣牌，于是很少进入
"副露手"状态，那类状态上的行为从来没被纠正过。

### 27.2 做法：在**学生自己的局面**上重新打标签（DAgger 剂量）

用 `ck-tr` 自己走 6000 局（确定性出牌），让老师给**每一条决策**（含全部鸣牌窗口）
打标签（259 万条），再从 `ck-tr` 用 2 轮 lr 5e-5、**不带锚点**微调一剂。

| 指标 | `ck-tr`（仅特征） | **`ck-tr` + 这一剂** |
|---|---|---|
| 对 v2（更强的手写 bot，配对 4800 局） | −265.2 | **+22.2** |
| 对 v1（冻结基线） | +1102.7 | +1149.6 |
| 顺位（对 v2 桌） | 2.5153 | **2.4908** |
| 自博弈副露率 | 0.103 | **0.122**（老师 0.182） |

**对强手从 −265 变成 +22（+287），首次在这张桌子上超过老师**；对冻结基线还略有提高。

### 27.3 关键点：这两个机制**单独都不够，叠起来才生效**

* 第 11 轮量过同形状的 DAgger 剂量：对 v1 **+96**，但对 v2 **−20**（等于无效）；
* 第 15 轮的特征暴露：把保真度从 0.85 提到 0.969，对 v2 从 −587 提到 −265，
  但那时它在强手桌上仍然落后；
* 本轮：**在已经能忠实复刻老师之后再补分布偏移**，才有 +287。

解释也直白：分布偏移修正的**上限就是"学生能多忠实地执行老师的选择"**。
学生只能复现老师 85% 的决定时，把它的状态分布修得再准，也只是让它在一个
"85% 像老师"的策略上更稳定；而当它已经 97% 像老师时，
分布修正才真正把那些"因为从没走到过所以打得离谱"的局面补上。

### 27.4 战略含义：老师这条梯子重新打开了

第 14 节那条规律（"老师变聪明 → 必须把它的判据也做成特征 → 否则学生学不到"）
此前卡在两处：判据没暴露全（第 15 轮补上了"合成判据"），以及**学生自身的保真度天花板只有 0.89**。
现在保真度 0.969，也就是说：

> **再让老师变强（新的领域知识、更好的阈值/鸣牌规则），学生有希望真正继承下来。**
> 这是自第 5 轮以来第一次重新具备"把老师变强就能让学生变强"的条件。

下一步可以直接做的两件事：

## 29. 第 18 轮：价值驱动老师失败 —— 并顺藤摸出一个用了十几轮的假指标

### 29.1 实验：把老师的推/弃判断换成学习到的价值

老师唯一"手写"的判据是 `hand_strength`（按向听的基准分 + 役种/宝牌加权）。
本轮给老师加了一个可选的价值网络（`EfficiencyAgent::with_value`）：
接上之后推/弃判断改成 `V̂(state) < 阈值`，并在强场里扫阈值：

| 老师的推/弃判据 | 对 v2 |
|---|---|
| 手写 `hand_strength`（基准） | +138（= 噪声 0） |
| 价值驱动，阈值 −0.5 | **−1020.7** |
| 价值驱动，阈值 0.0 | **−792.4** |
| 价值驱动，阈值 +0.5 | **−2440.4** |
| 价值驱动，阈值 +1.0 | −2500.4 |
| 价值驱动，阈值 +1.5 | −2510.9 |

**全线灾难性更差**，而且阈值越高（越爱弃和）越差，与第 14 轮"过度弃和代价极大"一致。

### 29.2 为什么：价值头的真实精度只有 R² ≈ 0.14

独立测量当前最优权重在留出行上的价值表现：

| 量 | 数值 |
|---|---|
| 目标（单局得失）标准差 | **4.69**（千点） |
| 价值头预测标准差 | **1.77**（只有目标的 38%） |
| RMSE | 4.35（千点） |
| **真实 R²** | **+0.141** |

也就是说价值头**大部分时间只是在预测均值**。用它做阈值判断，等于用一个每状态误差
±4300 点的估计去分辨"该推还是该弃"这种量级几百点的差别 —— 必然失效。

顺手排除了"是不是梯度被策略损失压住了"：用 `--value-coef 20`（价值权重放大 20 倍）
专门训一个模型，R² 反而只有 **0.076**（共享主干对价值是有帮助的）。
**所以这不是训练配比问题，而是目标本身的信噪比问题。**

### 29.3 附带发现：`val_r2` 这个指标一直是错的（错了很多轮）

上面独立测出 0.14 与训练日志里长期显示的 **0.72** 差了五倍，于是查了指标本身：

```python
totals["value_mse"] += float(vloss) * n      # vloss 是 Huber 损失，不是平方误差
...
"value_r2": 1.0 - mse / var                  # 于是这个"R²"被系统性高估
```

Huber 在有大误差时远小于平方误差，所以 `1 − huber/var` 被抬得很高。
**本项目此前所有"价值 R² ≈ 0.71~0.73"的记录都要作废**，诚实的数字是 **0.14 左右**。

这个假指标掩盖了三件事，现在都能解释了：

1. **一步搜索为什么中性**（第 11 节）：当时以为"R² 0.71 还不够"，实际只有 0.14 —— 本来就不可用；
2. **强化学习为什么从不涨**（第 12 节）：A2C 的基线就是这个价值头，一个几乎无效的基线
   让优势估计基本等于噪声；
3. **牌谱分析里的"期望得失"有多粗**：它用的就是这个价值头。

**已修**：`evaluate()` 现在把优化损失（Huber）与误差（MSE）分开统计，
`value_r2` 用平方误差计算，并且日志里同时打印 `pred_sd/target_sd`
（专门用来暴露"只预测均值"这种失败模式）。

### 29.4 下一步：让价值头真正可用

结论很明确：**要提高价值不是调参，而是换目标**。计划的做法是**分解期望得失**：

```
E[本局得失] ≈ P(和牌)·E[和牌得点] − P(放銃)·E[放銃失点] + 供托/罚符项
```

每个分量的方差都远小于"整局得失"（二值量的标准差 ≤0.5，而当前目标是 4.69），
因此同样的数据量能把每个分量学得准得多；再合成回期望得失，
即可用于搜索、RL 基线与牌谱分析。这也是目标里"改进价值损失尺度/优势估计"的直接落点。

## 30. 第 19 轮：把"本局得失"拆成低方差分量 —— 结果否掉了"换目标就能救价值"

### 30.1 做法

第 18 轮发现价值头真实 R² 只有 0.14，结论是"要换目标"。本轮把数据格式扩了 12 字节，
为每条记录额外存三个分量（`OutcomeParts`：和牌得点 / 放銃失点 / 其余），
并在训练器里加了五个头：`p_win`、`v_win`、`p_deal`、`v_deal`、`v_other`，
期望值合成为 `V = p_win·v_win − p_deal·v_deal + v_other`。

**分量自检**（20 万行真实数据）：恒等式 `ret == won − dealt + other` **精确成立**
（最大偏差 0.000000），和牌率 18.5%、放銃率 11.0%、平均和牌得点 8050、平均放銃失点 6200，
分量标准差 3.73 / 2.57 / 1.59 都比总量 4.84 小 ✓。

### 30.2 结果：合成后的 V **更差**，但拆开看信息很清楚

同一份数据、同一次训练里同时报两种目标（这是最干净的对照）：

| 目标 | 验证 R² |
|---|---|
| 单头直接拟合"本局得失" | 0.091 |
| **分解后合成** | **0.027** |

逐分量的可学性（3 万行留出）：

| 分量 | 指标 | 判读 |
|---|---|---|
| **P(和牌)** | **AUC 0.787**（基础率 0.186） | **真的可学**：手牌质量确实预示能否和牌 |
| P(放銃) | AUC 0.641 | 弱但为正 |
| 和牌得点（给定和牌） | R² **−2.29** | 比"直接猜均值"还差 |
| 放銃失点（给定放銃） | R² −1.18 | 同上 |
| 供托/罚符项 | R² −0.14 | 不可学 |

**结论**：合成分被两个"负 R² 的金额头"拖垮，所以分解没能改进 V。
但真正重要的是它揭示的结构：

> **"这一局会不会和牌"可以从观测里预测（AUC 0.79），
> "和牌能得多少分"不能。** 金额取决于和牌那一刻的牌型、宝牌指示牌、
> 对手的手牌——这些在决策时刻都还没出现。

也就是说，价值头的上限是**信息层面**的，不是网络容量或目标设计的问题。
这条结论把"换个目标把 V 做准"这条路也关掉了：
本局得失里的运气成分就是那么大的比例，任何模型都拿不到更多。

### 30.3 顺带修掉的两个实现问题

* `--decomposed-value` 生成了头但检查点里**没有记录它们**（`header` 在写文件之后才被修改），
  于是读回来就成了一张没有头的老网络 —— 已修；
* `evaluate()` 里新加的分解 R² 在一个"分支从未执行"的情况下会读到累加器 0，
  从而报出 **R²=1.000** 的假满分 —— 已改成返回 `nan` 而不是 1.0。
  （这与第 18 轮那个假指标是同一类错误的两次出现：**指标必须由必然执行的分支累积**。）

### 30.4 下一步：用可学的那个分量

分解实验留下一个真正可用的东西：**P(和牌) 是一个 AUC 0.787 的可靠信号**。
下一轮用它替代老师里那个失败的价值驱动推/弃判断
（"威胁下，若本局和牌概率低于阈值则弃和"），它比噪声很大的 V̂ 有希望得多。

## 31. 第 20 轮：二值奖励 RL 与"用可学信号驱动老师" —— 两个都被测掉了

### 31.1 让老师用 P(和牌) 决定推/弃：全线更差

第 19 轮测出 `p_win` 是 AUC 0.787 的可靠信号（而标量价值头只有 R² 0.14），
于是把它接进老师的推/弃判断（`EfficiencyAgent::with_win_probability`，
规格 `efficiency-v2?value=CK&pwin=X`），在强场里扫阈值：

| 老师的弃和判据 | 对 v2 |
|---|---|
| 手写 `hand_strength`（基准） | +138（= 噪声 0） |
| P(和牌) < 0.05 | −57 |
| P(和牌) < 0.10 | −319 |
| P(和牌) < 0.15 | −649 |
| P(和牌) < 0.20 | −879 |

**即使换成"可靠的那个信号"，也远不如手写启发式**，而且是越爱弃和越差。
至此"把学习信号放进老师"这条路（标量价值、和牌概率两种）都被关闭：
老师的 `hand_strength < 2.5` 是**针对这套评测调过参**的判据（第 14 轮 fold 扫描），
它同时编码了弃和的代价与推牌的价值，而任何单一学习信号都只覆盖其中一半。

### 31.2 二值奖励 RL：看起来是突破，其实是指标假象

既然"是否和牌"可学、而分数不可学，那就把 RL 的奖励换成**二值和牌指示**
（`--reward win`：`adv = won − sigmoid(V)`，价值头用 BCE 预测和牌概率）。
这是本项目第一次给 RL 一个**真正有信号的基线**。三个独立副本对 v2 的结果：

| 运行 | 对 v2（4800 局、种子 4242） | 相对"基准" |
|---|---|---|
| 原始 | +46.4 | +311.6 |
| 副本 1 | −0.7 | +264.5 |
| 副本 2 | +54.6 | +319.8 |

三个**不同训练**的模型落在同一个位置，看起来无懈可击。但把它们放到
**9600 局**（更精确）上重测，结论完全变了：

| 模型 | @9600 种子 4242 | @9600 种子 5150 | 均值 |
|---|---|---|---|
| `ck-dagger`（基准） | −54.8 | **−7.6** | −31 |
| `ck-rlwin` | −57.2 | −38.8 | −48 |

**两者无法区分，RL 没有带来任何提升。** 那么 +300 是怎么来的？
因为我拿**三个新的测量**去比了**一个基准测量**（−265），而那次基准测量恰好抽到了低尾
（4800 局噪声约 ±150；基准在 9600 局上是 −31 而不是 −265）。

### 31.3 这一轮真正的教训

> **"多个候选一致更好"不等于"改进是真的"——只要基准只测了一次。**
> 基准自身的噪声不会被候选的重复平均掉。

前两次"大增益蒸发"（第 8 轮的 +193、第 9/10 轮的复现失败）都是同一类错误的不同侧面。
**修正做法**（已写进流程）：任何候选的对比，都必须**在同一批次里重测基准**，
且主判据用 9600 局或两个种子；单次 4800 局的结果只能当筛选，不能当结论。
循环本身有"与当前最优的头对头"作同批次对照，这一点是它比手工实验更可靠的地方。

### 31.4 本轮的净产出

* Rust 侧现在能**读取并使用分解头**（`Net::extra` + `Net::win_probability`），
  检查点格式向后兼容（旧文件的 `decomposed` 列表为空）；
* 训练器新增 `--reward win`（二值奖励 + 概率基线）——虽然本轮没能证明它有用，
  但它是第一个"基线有信号"的 RL 配置，值得在更强的教师到位后再试一次；
* 又一次确认了项目的判定纪律，并把它写成了可执行的规则。

## 32. 第 21 轮：两个便宜的负结果 + 一次判定纪律的自我验证

### 32.1 预测集成：在强手尺子上同样没有增益

第 6 轮测过"多模型输出取平均"（当时对冻结基线是 −101，结论是"镜像对局里有效、对外部无效"）。
现在尺子换成了对 v2 的分，且手上有四个**独立训练、强度相当**的 737 维权重，
于是重测一次：

| 方案 | 对 v2 @9600/4242 |
|---|---|
| 单个 `ck-dagger` | −54.8 |
| 四模型集成 | **−47.1** |

差 7.7 分，完全在噪声内 ⇒ **集成没有价值**（也省掉了服务端跑集成的复杂度）。

### 32.2 鸣牌偏置：少鸣牌不是缺陷

第 17 轮的对齐诊断说鸣牌窗口是学生**最弱的模仿类**（一致率 0.9618，
其中 76% 是"该鸣不鸣"），自博弈副露率 0.103 对老师 0.182、人类 0.326。
于是做了一个推理期的**鸣牌概率偏置**（`bias:CK?calls=X`），
并且**在同一批次里带 β=1.0 的对照组**：

| 鸣牌偏置 β | 对 v2 @4800/4242 |
|---|---|
| **1.0（对照 = 原模型）** | **+22.2** |
| 1.5 | −318.1 |
| 3.0 | −350.9 |

**多鸣牌明显有害**（−340 以上），也就是说学生"比老师更少鸣牌"**不是实力缺陷**，
而是它在这套评测里的特点 —— 与第 16 轮老师侧的结果（`call_eagerness=2` 即 −750）互相印证。
副露率低不是需要修的东西，这一条也可以从"待改进清单"上划掉。

### 32.3 顺带验证了判定纪律

β=1.0 那一格在**另一次独立评测**里得到 **+22.2**，与前一轮 `ck-dagger` 的测量
**完全一致**（同一协议、同一种子）。这说明：只要**在同一批次里重测基准**，
4800 局的测量是稳定可比的 —— 第 20 轮那次"+300 假象"的根源不是 4800 局本身，
而是**拿新测量去比一个旧测量**。规则现在很明确：

> 候选与基准必须在**同一批次、同一协议**里测；跨批次比较只用 9600 局或多组种子。

### 32.4 位置盘点（第 21 轮结束时）

| 项目 | 状态 |
|---|---|
| 最优权重 | `ck-dagger.bin`；对 v2 @9600 两个种子 −54.8 / −7.6（均值 −31），对 v1 +1123 ~ +1150 |
| 已关闭的方向 | 老师参数（fold/eager/yaku/dora/riichi）、学习信号进老师（V 与 P(win)）、迭代剂量、平局软标签、集成、鸣牌偏多、价值换目标、二值奖励 RL |
| 仍然成立的有效机制 | ①暴露老师合成判据的特征（保真度 0.849→0.969，对 v2 −587→−216）；②在学生自己局面上的一次 DAgger 剂量（→ 约 −43，与老师打平） |
| 明确的瓶颈 | **老师本身的能力**。它的参数已穷尽、学习信号救不了它、其余机制都只能追平它 |

下一步要想真正超过，只剩两条路，都需要新的东西而不是调参：
（1）**老师的新领域知识**（例如从弃牌序列读听牌），历史上 6 次手写判据尝试多为持平或更差，
但当时学生保真度只有 0.89、且尺子是弱基线 —— 现在两个前提都变了，值得再试一次；
（2）**搜索**，但它需要一个比"信息上限 R²≈0.14"更好的价值函数，而第 19 轮已经把这条路论证为信息受限。

## 33. 第 22 轮：第一个走通"手写判据 → 暴露成特征 → 学生继承"的增益

### 33.1 老师的旧安全度模型只看"集合"，不看"顺序"

`danger_table_full` 此前用三种信息：**現物**（对手舍牌集合）、**同巡安全牌**、
**筋/壁**（由舍牌推导的形状信息）。这些都是"哪些牌出现过"，
而人类还读**顺序**：一个已经把某一花色打掉好几张的对手，
不太可能在这一色上听牌 —— 于是那一色剩下的牌比形状模型估计的要安全。

新增 `suit_reading`：统计威胁方**在立直宣言之前**各花色的舍牌数，
按 0~1 / 2~3 / 4+ 分别把该花色所有牌的危险度乘以 1.0 / 0.88 / 0.72。
这是老师里第一条真正使用"舍牌顺序"的判据（默认关闭，因此默认行为逐位不变）。

### 33.2 老师端：同批次对照下 **+136**（4800 局 +118、9600 局 +136）

评测时**把对照组放在同一批次里**（第 21 轮定下的规矩）：

| 老师 | 对 v2 @4800/4242 | 对 v2 @9600/4242 |
|---|---|---|
| 纯形状模型（对照，自身对比=噪声） | +138.3 | +53.8 |
| **+ 弃牌序列读** | **+256.5** | **+189.8** |

差值 **+118 / +136**（9600 局约 1.9σ）。另外两项确认了旧结论：
`open_threats`（把开展的手牌当威胁）依然是负的（−31 ~ −169），
"序列读 + open" 的组合也只有 +68。

### 33.3 学生端：同配方 A/B **+198**，且两个尺子同时提升

按第 14 节那条规律（老师的改进必须**先暴露成特征**才可能被继承），
把编码器的安全度块改成"关掉 open_threats + 开启序列读"，然后重生成数据、重训。
**同配方、同数据量、同老师标签，唯一差别就是这个特征块**：

| 臂 | 危险度特征块 | 对 v2 @9600/4242 | 对 v1 @9600/4242 |
|---|---|---|---|
| A（旧） | open threats 开、无序列读 | −98.7 | +1159.8 |
| **B（新）** | open threats 关 + **序列读** | **+99.8** | **+1425.0** |

**对强手 +198.5，对弱基线 +265。** 新权重 `ck-read.bin` 在两个尺子上都是历史最好，
并且在**第二个种子**上复现（对 v2 @9600/5150 = **+226.0**，对 v1 守卫协议 = **+1398.5**）：

| 协议 | `ck-read` | 上一版 `ck-dagger` |
|---|---|---|
| 对 v2 @9600（种子 4242 / 5150） | **+99.8 / +226.0** | −54.8 / −7.6 |
| 对 v1 @4800/5150（守卫） | **+1398.5** | +1123.0 |

这条增益的意义不只是数值：它是**第一次完整走通"给老师加一条新判据 → 把它暴露成特征 →
学生继承下来"**的流程（第 14 节写下的配方在当年因为学生保真度只有 0.89 而卡住），
而且机制在两处独立测量上一致（老师 +136、学生 +198）。

**待办（两条，都很明确）**：

1. A/B 每臂目前各只有一次训练（虽然两个种子都复现、且与老师侧测量一致），
   按本项目规矩应当再各训一到两次副本后定稿；
2. 更直接的一条：本轮训练用的标签仍来自**纯形状模型**的老师（`suit_reading` 默认关闭）——
   也就是说学生看到的是"带序列读的危险度特征"，模仿的却是"不含序列读的老师决策"。
   把**老师自己也开上序列读**再生成一遍标签（老师端已实测 +136），
   学生应当还能再吃一截 —— 这正是梯子的下一级。

### 33.4 循环的判定协议也修好了

第 20 轮那次"+300 假象"的根源是"拿新测量去比旧测量"。循环现在**每轮在同一批次里
重测在位最优**（`incumbent`），并用它作为接受线：

```
incumbent ← evaluate(state["best"], primary_spec, eval_games, seed)   # 同批次
bar       ← incumbent + accept_margin
candidate ← ...（可提前停止）
```

代价是每轮多一次评测（约 2 分钟），换来的是接受/回滚判定不再受"存下来的旧数字"影响。

## 34. 第 23 轮：梯子的下一级 —— 序列读做*标签*反而破坏了另一个尺子

### 34.1 做法

第 22 轮把"弃牌序列读"暴露成了**特征**（学生两个尺子同时提升 +198 / +265），
但训练标签仍来自**纯形状模型**的老师。既然老师自己用上这一读值 +136，
那就再加一级老师（`EfficiencyAgent::reading`，`--teacher-v4`），
用它生成标签（`im-v14`，8000 局），其余配方完全相同。

### 34.2 结果：主判据 +52，守卫 **−289** —— 按规则应当拒绝

两个模型、两个尺子、两个种子，全部 9600 局：

| 模型 | 对 v2（主判据，4242 / 5150） | 均值 | 对 v1（守卫，4242 / 5150） | 均值 |
|---|---|---|---|---|
| `ck-read`（形状模型标签） | +99.8 / +226.0 | **+162.9** | +1425.0 / +1550.0 | **+1487.5** |
| `ck-v4`（序列读老师标签） | +199.3 / +229.4 | **+214.4** | +1180.6 / +1217.3 | **+1199.0** |

**用 +51 的对强手分换掉了 −289 的对弱基线的分。** 循环自己的守卫规则
（候选在第二把尺子上不得低于历史最优 50 分以上）会直接拒绝它 ——
本轮的价值之一就是**这条规则第一次真的拦住了一个改动**。

### 34.3 一个有信息量的不对称

同一个判据，两种用法，结果完全不同：

| 用法 | 对 v2 | 对 v1 |
|---|---|---|
| **做成特征**（第 22 轮） | **+198** | **+265** |
| **做成标签**（本轮） | +51 | **−289** |

解释是自洽的：把它做成特征，等于**给了网络一份更准的安全度信息**，
它可以在不改变"像老师"的前提下用得更好；
而用它替换标签，等于让策略去模仿一个**风格被这条读改过的**老师 ——
那个风格对主动的强手略有好处，但对被动挨打的弱基线明显更差。
换句话说：**新判据适合进"输入"，不适合直接进"目标"。**

### 34.4 累计战绩（第 15 → 23 轮，全部为 9600 局/多种子的同协议测量）

| 阶段 | 对 v2（强手） | 对 v1（弱基线） |
|---|---|---|
| 第 14 轮的 703 维老血脉 | −587 | +1120 |
| + 暴露老师的**合成判据**（第 15 轮） | −216（三副本） | — |
| + 一次 **DAgger 剂量**（第 16 轮） | −43（三副本） | — |
| `ck-dagger`（上上版最优） | −31（两种子） | +1123 ~ +1150 |
| **`ck-read`（当前最优，第 22 轮）** | **+163（两种子）** | **+1488（两种子）** |

也就是说：模型从"**输给更强的手写 bot 约 590 分**"走到了"**赢它约 160 分**"，
而对弱基线始终保持在 +1100 以上。这条 +750 的曲线全部来自两个机制：
**暴露老师的判据**（合成判据 + 序列读）与**在学生自己局面上的一次 DAgger 剂量**。

## 35. 第 24 轮：量出当前血脉的训练间波动 ±124 —— 并据此给第 22/23 轮的结论降级

### 35.1 读法的细化：一条有效、一条无效

第 22 轮的"弃牌序列读"是第一个走通梯子的判据，于是本轮试了两个细化
（同批次对照，9600 局）：

| 老师 | 对 v2 @9600/4242 |
|---|---|
| 纯形状模型（对照） | +53.8 |
| + 序列读（第 22 轮那条） | +156.9 |
| + 序列读 + **按舍牌时机加权**（晚巡的舍牌权重加倍） | +173.5 |
| + 序列读 + **鸣牌花色读** | **+156.9（与不加完全相同）** |

* 时机加权只多 +17，在噪声内 ⇒ 没有进一步收益；
* **鸣牌花色读完全不起作用**，原因是结构性的：当 `open_threats=false` 时，
  威胁集合里只有**立直**玩家，而立直要求门前清 ⇒ 他们**不可能有鸣牌**，
  这条读永远不会触发。（要做它必须先开启 open 威胁，而那是实测更差的方向。）

⇒ 这条读的细化空间也量完了，第 22 轮那条就是它的最终形态。

### 35.2 更重要的发现：同一配置三次训练差出 250 分

既然第 22 轮的 +198（"新特征让对强手的分从 −98.7 涨到 +99.8"）是**每臂一次训练**，
本轮把当前配置（`im-v13` + ck-read 的配方）**原样重训两次**，只换随机种子：

| 训练 | 对 v2 @9600（种子 4242 / 5150） | 均值 |
|---|---|---|
| `ck-read` | +99.8 / +226.0 | **+162.9** |
| 副本 11 | −118.4 / −50.6 | **−84.5** |
| 副本 22 | +76.8 / +142.8 | **+109.8** |
| **血脉** | | **+62.7（标准差 124）** |

**同一个配方、同一份数据、只换训练种子，就能差 250 分。** 后果必须写清楚：

* 第 22 轮那个"**+198** 的梯子增益"：把 A 臂的一次测量（−98.7）与 B 臂三次的均值
  （+62.7）相比是 **+150 ± 143** ⇒ **不成立**，只能算"有苗头"；
* 第 23 轮那个"用 +52 换 −289"的判断同样落在这个波动量级附近（−289 约 2.3σ，
  只能说"很可能有害"，不能说"确定"）；
* 从 `ck-dagger`（−31）提升到当前血脉（+63）也在 ±76 以内 ⇒ **未被证明**。

### 35.3 这不是"测量噪声"，而是**配方**噪声 —— 而且有解

第 11 轮量过：**温和配方**（lr 5e-5、2 轮）的副本间标准差只有 **46.8**；
而这里用的 **bootstrap 配方**（lr 1e-3、4 轮）是 124（第 10 轮的 512 宽度实验里甚至是 373）。
也就是说：**波动来自那个激进的学习率**，不是评测或数据。

因此从本轮起，凡是要下"某特征/某配方更好"的结论，必须二选一：

1. **用温和配方**（lr 5e-5、2 轮）做从头训练 —— 副本间 σ≈47，单次训练即可信；
2. 或者**每臂 ≥3 次训练**，用组均值比较。

好消息是：**训练循环本身一直用的就是温和配方**，而且它的判定链
（同批次重测在位最优 → 加接受余量 → 换数据复现 → 守卫 league → 回滚）
本来就是为这种噪声设计的 —— 也就是说，循环比我的手工对照实验更可靠。

### 35.4 循环现在的守卫从一个变成一组

第 23 轮那个"主判据涨、守卫跌"的案例说明单一守卫不够，
于是把守卫推广成 **league**（`--yardstick-league efficiency,efficiency-v3`）：
候选必须在**每一个** guard 上都不比历史最优差 50 分以上，否则回滚；
晋升时用新权重自己的测量刷新全部 guard 基线。当前 league = {冻结基线 v1}，
基线值取自 `ck-read` 自己的同协议测量（+1398.5）。

## 38. 第 27 轮：把"已验证的机制"叠到当前最优上 —— 叠加不成立；顺手把生成吞吐提上去

### 38.1 DAgger 剂量在当前最优上不再复现（同批、三副本，且这次的零结果很紧）

账面上第二大的手段是第 16 轮的"一次 DAgger 剂量 = +220（3 副本）"，
但它从来没在当前最优上验证过：`ck-ab` 是从头模仿 `im-v12` 得到的，**从未吃过剂量数据**。
按第 24 轮的规范重做：

1. 用当前权重的走棋状态生成 6000 局、**2,610,092** 条决策，老师 v2 打标签（`--dagger`）；
2. 从 `ck-ab` 出发微调 2 轮、lr 5e-5、无 anchor，三个随机种子 → 三个副本；
3. 同批 9600 局、seed 4242，**先重测在位者**，再测三个副本。

| 对象 | 对 v2 @9600（同批，seed 4242） |
|---|---|
| `ck-ab`（在位者，同批重测） | **+299.9** |
| 剂量副本 1 / 2 / 3 | +316.7 / +313.2 / +304.5 |
| 副本均值 | **+311.5** |

差 **+11.6**，不到 0.2σ。这里还有一个方法论收获：**微调副本之间的波动极小**
（sd ≈ 6，而从头训练是 65~124），因为三个副本从同一权重出发、学习率很低，落点几乎重合。
所以这**不是"功率不足的零结果"，而是一个很紧的零结果**：在当前血脉上，
这一份剂量数据对策略的影响约等于 0（±10 以内）。

结论：第 16 轮的 +220 **不该再按"可叠加的机制"记账**。它当时的基座弱得多（对 v2 还是负数），
更合理的读法是"它在那条血脉（老编码器 + 老配方）里有正效应，换到当前血脉后塌到 0"。
第 37.2 节的账目据此下调（下表）。

### 38.2 吞吐：先剖析，再修一处真在浪费的地方（生成 +13%，评测同源受益）

用 `sample` 抓了正在跑的生成进程与评测进程（6 秒采样、按叶子函数汇总）：

| 叶子函数 | 生成进程占比 | 评测进程占比 |
|---|---|---|
| `Layer::forward`（网络前向） | 41% | 44% |
| `regular_shanten` | 20% | 23% |
| `is_agari` / `all_sets`（和牌判定） | 4% | 14% |
| `ukeire_count`（进张数） | 5% | 4% |
| `Net::load`（每批重载权重的浪费） | 7% | 1% |
| `encode_state` / `encode_record`（自时间） | 2% | 1% |

两个大项是"网络前向"与"手牌评估"，各占四成上下 —— 没有单点银弹；想再快一档
只能动"更窄的权重"（f16/i8）或"更快的 shanten 表"，这轮没动它们。
但编码器里有一处**纯粹的浪费**：`encode_state` 对**每一个手牌种类**都算一次
`ukeire_count`，而一次 `ukeire_count` 本身就是一轮 34 张的 shanten 扫描
（实测 ~30 µs），13 个种类就是 ~400 µs/决策 —— 比网络前向（~36 µs）还贵一个数量级。

这些值却**只有"并列最好进张"的那几个种类会被读到**：
特征块的条件是 `sh_after[k] == best_shanten`；`pref::discard_ranking` 在碰 `acceptance`
之前会 `continue` 掉所有更差的种类；折叠分支根本不读 `acceptance`
（只读危险度和 keep 值）。把 `ukeire_count` 限制到这些种类上、其余照旧，
输出**逐字节不变**：同一 seed 用改前/改后二进制各生成 24 局共 9710 条记录，
md5 完全一致；1200 局 × 2 个 seed 的记录条数也完全一致（528733 / 529057）。

实测（新旧交替各两轮，排除机器漂移）：

| | 生成 1200 局 | 吞吐 |
|---|---|---|
| 改前 | 57.8 / 56.4 / 56.9 / 56.8 s | **21.1 局/s** |
| 改后 | 51.1 / 50.6 / 49.7 s | **23.8 局/s** |

即生成吞吐 **+13%**。评测路径的 `encode_state` 子树同样是仅次于前向的开销，实测
4800 局配对评测从 **202.3 s 降到 184.6 s（+10%）**，而且两次的配对分**完全相同**
（+244.1 对 +244.1）—— 这既是提速证据，也是"改动不影响结果"的第二个验证点。

### 38.3 这一轮之后，"提升实力"这件事的账目（第 37.2 节的下调版）

| 手段 | 效应量（对 v2 @9600） | 证据强度 |
|---|---|---|
| 暴露老师的**合成判据**（第 15 轮） | +330 ~ +370 | 3 副本，量级远超波动 |
| **配方**（900k/4 轮/3e-4，第 26 轮） | +100 ~ +134 | 2~3 副本/臂 |
| 一次 **DAgger 剂量**（第 16 轮） | 当前血脉上 **+11.6 ≈ 0** | 3 副本，sd 6，同批重测在位者 |
| 序列读做特征 / 做标签（第 22/23 轮） | 未成立（−67） | 规范 A/B 推翻 |
| 二值奖励 RL、价值驱动老师、集成、多鸣牌 | 0 或更差 | 各自的多副本测量 |

这个表是当前对"还能从哪里拿到实力"最诚实的判断：**模仿路线上的已知杠杆已经用尽**，
剩下的两个方向是（a）继续压低训练/评测成本，用同样算力换更多实验；
（b）换一类目标（例如价值/搜索），但这需要先突破"价值头信息量 R²≈0.11"这个天花板。
### 38.4 目标里的"价值损失尺度"：把价值损失整个去掉，强度没有变化

项目目标里点名了"价值损失尺度"。价值头的诚实拟合度只有 **R² ≈ 0.11 ~ 0.14**
（预测标准差只有目标的 36%），所以它往共享主干里回传的梯度大部分是噪声 ——
最干净的检验就是把 `--value-coef` 从 0.5 直接改成 **0.0**，其余全部照抄第 26 轮的 A 臂
（同一份 `im-v12`、900k 行 × 4 轮、lr 3e-4、lr-decay 0.8、同三个种子），
`ck-ab` 就是 A 臂的中位副本，并在同批重测：

| 对象 | 对 v2 @9600（同批，seed 4242） | 策略拟合 val_acc |
|---|---|---|
| `ck-ab`（value-coef 0.5，在位者同批重测） | **+299.9** | 0.947 |
| vc0 副本 1 / 2 / 3 | +262.9 / +377.8 / +305.4 | 0.959 / 0.958 / 0.961 |
| 副本均值 | **+315.4**（+15.5 ± 33.5） | — |

**结论 1（对实力）**：效应 **+15.5 ± 33.5**，不到 0.5σ，且方向与已知的从头训练波动
（sd 58）无法区分 —— **去掉价值损失不会让棋力变强，也不会变弱**。
**结论 2（对训练）**：`val_acc` 从 0.947 稳定升到 0.958~0.961，
说明"主干不再被价值梯度干扰"确实让策略拟合更干净，但**这份干净没有转化成牌力**。
**结论 3（工程决定）**：因此价值头**保留** —— 它在强度上是免费的，
而 UI「牌谱分析」的期望得失、以及 `P(win)`（AUC 0.787）都靠它。
这个方向（价值损失尺度）到此可以视为**已经测过、没有剩余空间**。

## 39. 第 28 轮：前向内核算不上瓶颈、换形状更差，但"权重变窄"真的有效（生成再 +9.6%）

第 27 轮把生成吞吐提了 13%，剩下的两个大项是"网络前向"（生成 41%、评测 44%）与"手牌评估"。
本轮专攻前向。做法是先把"到底卡在哪"测清楚，再逐一试形状。

### 39.1 先量：卡在字节，不是卡在 ALU

`mmj-selfplay bench` 在同一台机器上给出（安静机器、取 4 轮最优）：

| 网络 | 权重字节 | 前向 | 折算流量 |
|---|---|---|---|
| 768×768 主体（4.85 MB 参数，实际读 ~3.2 MB） | 3.2 MB | **101 ~ 140 µs** | 39 ~ 53 GB/s |
| 64×64（233 KB，完全在缓存里） | 233 KB | 8.5 ~ 13 µs | 18 ~ 28 GB/s |

小网络的权重**整体在缓存里**，单位字节的吞吐却**没有更高** —— 说明这个核不是"ALU 打不满"，
而是接近本机的单核访存上限（另写了 `memory_bandwidth_probe`：同一块 4.85 MB 缓冲的
朴素顺序读只有 **23 GB/s**，64 MB 时 **15.8 GB/s**）。既然瓶颈是字节数，
"换更聪明的循环"最多只能拿到一点零头，**真正的杠杆是把每个权重变窄**。

### 39.2 三个"换形状"的尝试，全被自己的测量否掉

| 做法 | 结果 | 处置 |
|---|---|---|
| 显式 AVX2 手写（乘、加分开，保持逐位一致） | 37.5 GB/s 对编译器自动向量化的 35.4 GB/s，**在噪声内** | 回退（不值得为噪声加代码） |
| 显式 AVX2 + **FMA**（融合乘加，少一半 ALU 指令） | 与标量路径持平 | 回退 |
| **寄存器分块 GEMV**（累加器留在寄存器、按 32 输出分块流式读列） | **更慢**：102~107 µs 对 96~98 µs —— 相邻列之间的 3 KB 步长把预取器打死了，省下的累加器流量不值这个价 | 回退 |

三条都被"同一批交替测量"否掉，代码回到第 27 轮的逐位一致版本；测量结论写进了
`Layer::forward` 的注释，免得下一轮再去试一遍。

### 39.3 真正有效的一招：权重存成 binary16（F16C）

`Layer` 多存一份半精度权重（`wt_h`），推理核用 F16C 的 `vcvtph_ps` 一次把 8 个
半精度权重变成 8 个 f32 再做 FMA；权重字节数直接砍半。为保持"到哪台机器都算得一样"，
f32↔binary16 的转换是**软件实现**（不是 `_cvtss_sh`），并且用**全部 65536 个位模式**
做了往返测试（`half_precision_conversions_round_trip`）。

| 指标 | f32 权重 | binary16 权重 | 变化 |
|---|---|---|---|
| 前向（4 轮最优） | 101.3 µs | **93.5 µs** | **+8%** |
| 生成 1200 局（seed 4242 / 5150） | 46.0 / 47.2 s | **42.0 / 43.0 s** | **+9.6%** |
| 棋力（`ck-ab` 对 v2，4800 局配对，seed 4242） | +244.1（顺位 2.4878） | +261.1（顺位 2.4873） | 差 +17，落在 ±100~150 的标准误内 → **无影响** |
| 评测 2400 局（暂停后台循环、交替各两轮） | 49 s / 49 s，分 −10.2 | 46 s / 47 s，分 −5.2 | **+5%**，且分数在两轮内完全可复现 |

记录条数几乎不变（528733 → 528736，52.8 万条里差 3 条，来自权重最后几位小数的舍入），
也就是说**特征与标签完全一致，只有动作采样的极少数平局判定会翻**。

这条还有一个旁证，说明"省的是字节"这个解释是对的：**随机初始化**的网络第一层输入是稠密的
（权重流量从 ~3.2 MB 涨到 ~5.6 MB），同一个改动在它身上值 **+29%**（282.4 µs → 206.1 µs），
而不是训练好的网络上的 +8% —— 字节越多，砍半越划算。

### 39.4 两轮吞吐账

| 阶段 | 生成 1200 局 | 吞吐 |
|---|---|---|
| 第 27 轮之前（f32 权重 + 编码器对每个手牌种类都算进张） | 57.0 s | 21.1 局/s |
| 第 27 轮之后（裁掉无用进张计算） | 50.5 s | 23.8 局/s |
| 第 28 轮之后（再加半精度权重） | **42.5 s** | **28.2 局/s** |

**累计 +34%**，而且这三处改动都不改变棋力（前两处逐字节一致，第三处实测在噪声内）。
评测路径同样受益（前向占评测 44%）。往后如果还要提吞吐，剩下的手段是 i8 量化
（再砍一半字节，但要量化激活、收益与精度风险都更大）或更快的 shanten 表。

### 39.5 顺带测掉的一条学习轴：**训练更久没用**（8 轮对 4 轮）

第 26 轮把配方拆成"数据量"和"学习率"两个维度测过，但从没测过**轮数**：所有臂都是 4 轮。
本轮补上：同一份 `im-v12`、900k 行、lr 3e-4、lr-decay 0.8、同三个种子，
只把轮数从 4 改成 8，并在同批里重测在位者（`ck-ab` 就是 4 轮那一臂的中位副本）。

| 对象 | 对 v2 @9600（同批，seed 4242） | 训练末尾的 `policy_loss` / `val_acc` |
|---|---|---|
| `ck-ab`（4 轮，在位者同批重测） | **+307.1** | 0.114 / 0.947 |
| ep8 副本 1 / 2 / 3 | +295.9 / +149.7 / +314.4 | 0.0865 / 0.963 |
| 副本均值 | **+253.3** → **−53.8 ± 52.1** | — |

**结论**：把同一份数据多过两遍**不涨分**（点估计还是负的，sd 90）。
注意 ep8-3 单独一个副本 +314.4 就高于在位者的 +307.1 —— 这正是"从三次训练里挑最好那个"
会骗人的典型：**组均值才是结论**（第 24、26 轮同一个教训）。

更值得注意的是**训练指标与棋力脱钩**：
`val_acc` 一路从 0.947（4 轮）→ 0.959~0.961（4 轮、去掉价值损失）→ 0.963（8 轮），
`policy_loss` 从 0.114 降到 0.0865，而棋力分别是 0、0、−54。
**拟合得更像是没有用的**：这条血脉已经不是"欠训练"，而是**信息受限**——
它已经学会了它能看到的东西，剩下的差距来自"输入里没有的信息"（隐藏手牌、对手意图），
不是来自优化得不够。这和第 26 轮"数据量翻倍反而更差"、第 27 轮"去掉价值损失更干净但不变强"
是同一件事的三个侧面。

## 40. 第 29 轮：先搞清楚循环的时间花在哪，再试一次"给和牌判定提速"（失败，但有收获）

### 40.1 循环的一轮到底花在哪（干净机器上实测）

之前几轮看到的"训练占 650~720 s"是被我自己的实验挤出来的假象。把机器空出来之后，
一轮（iter 49，4 个数据文件、2,639,360 行/轮）的真实构成是：

| 阶段 | 时间 | 说明 |
|---|---|---|
| 自博弈 6000 局 | ~175 s | 第 27、28 轮的提速已经吃到这里（生成 +34%） |
| 训练 2 轮 | ~410 s（205 s/轮） | 2.64M 行、768×768、batch 512 |
| 评测 9600 局 | ~275 s | 一半以上的候选会被 early-stop 提前否掉，实际更短 |

也就是说，**自博弈 : 训练 : 评测 ≈ 1 : 2.3 : 1.6**，训练仍然是最大的一块，
但已经不是"压倒性"的。

### 40.2 训练这块的便宜旋钮：**线程数**（本轮采用的改动）

在这台机器（4 物理核 / 8 逻辑核）上，把后台循环停掉、交替测量 300k 行的训练轮：

| 线程 | batch 512（两次） | 结论 |
|---|---|---|
| 8（torch 默认 = 全部逻辑核） | 12 s / 11 s | 超线程在这里是负收益 |
| **4** | **9 s / 10 s** | 快 ~20% |

batch 1024 还能再快一点（9 s / 8 s），但它把"每个 epoch 的更新次数"砍了一半，
那是另一回事（第 28 轮已经证明"多拟合不涨棋力"），所以没动。
**采用的改动只有一处：循环的训练步骤加 `--threads 4`**，学习动力学完全不变。
在真实负载上（2.64M 行/轮）实测 **220 s → 203 s（+8%）**，而且顺带把 4 个核让出来，
给以后"生成与训练重叠"留了空间。

### 40.3 一次有收获的失败：把和牌判定换成查表，反而更慢

评测的剖析显示**手牌评估占 59%**，其中和牌判定（`is_agari` + `all_sets` + `is_chiitoitsu`）
约 **24%** —— 因为每问一次"我有哪些听牌"就要做 34 次和牌判定。于是把它改成：
每个花色预先算好"能拆成恰好 k 组面子 / k 组面子加一对雀头"的位掩码并缓存，
`is_agari` 只做 4 次查表 + 一点位运算。**同一批交替测量的结果是慢了 13%**
（生成 1200 局：41.2/41.7 s → 47.8/46.6 s）。

原因很清楚：递归版只在 34 字节的计数数组上做快速失败的搜索，全部命中 L1；
查表版每次要 4 次哈希查找，而缓存已经涨到几十万条，等于每次都在访问主存。
**这一条已经回退**，"查表更快"的直觉在这个规模上是错的。

### 40.4 失败顺带揪出的一个真问题：缓存键的进制

写那张表时新加了一个用例，结果把仓库里一个**潜伏的键冲突**照出来了：
`tenpai_kinds` 这类"形状查询"会**故意**在第 5 张牌上加一（形式聴牌 / 五枚目），
而花色缓存的键是 **5 进制**的 —— `[5,0,…]` 会进位成和 `[0,1,…]` 完全相同的键，
于是后查的那个花色会拿到前一个花色的缓存 profile。
目前所有调用点都恰好挡在前面（`ukeire` 里 `counts[k] >= 4` 就跳过），所以线上没有出现过错判；
但键本身是错的，已改成 **6 进制**（计数最大就是 5），并加了回归测试
`cache_keys_distinguish_five_copies` 把这个不变量钉住。
现在错的那个测试（`fifth_tile_wait_still_counts_as_tenpai`）也一起绿了。

**教训**：这类"顺手加的等价性测试"不是形式主义 —— 它抓到的正是主逻辑测试覆盖不到的地方。

回退之后再验证了一遍"确实退干净了"：同一个 seed 生成 24 局，
md5 与第 27/28 轮的基线（`6339b63f…`）**逐字节一致**，说明改动只剩那个行为无关的进制修正。
全套测试 90 项全绿（`cargo test --release`，含新加的键回归测试）。

## 41. 第 30 轮：把"跟谁比、比几次"算清楚 —— 一次直接对战顶两次间接测量

### 41.1 问题：循环为了比较两个权重，花了两次评测

到第 29 轮为止，循环每轮都要做**两次** 9600 局评测：一次把在位者拿去对牌效率 bot v2（重测基线，
防止拿旧数字比新数字），一次把候选拿去对同一个 v2，然后比较两者的分。
两次都是有噪声的间接测量，**差值的标准误是两次噪声之和**（实测 9600 局上 60~95）。

### 41.2 直接对战到底比间接好多少（量出来的）

`mmj-eval` 本来就能把**权重文件**放在任一侧，所以可以直接让候选和在位者同桌上打。
拿迭代 49 的候选 `ck-0049` 对在位者 `ck-ab`，9600 局、两个种子：

| 种子 | 直接对战（候选 − 在位者） | 先手率 | 顺位 |
|---|---|---|---|
| 4242 | **+87.7** | 0.5070 | 2.4924 |
| 5150 | **−0.3** | 0.5026 | 2.4969 |

两个种子的标准差 ≈ **62**，和间接口径的 60~95 是**同一个量级**：
"同桌同牌"并没有把噪声压得很低 —— 因为同一局里两方坐在不同位置、拿的是不同的牌，
发牌运气只在"局"这一层共享，而差值里还剩下大量座位/配牌运气。

**但成本是两次对一次。** 也就是说：**用同样多的牌局，直接对战给出的精度不低于
"候选 + 在位者各测一次"的间接口径**（62 对约 92），而牌局数只要一半。

### 41.3 两个口径这次并没有打架

间接口径的隐含差值是 **−108.8**（候选 25044.8、在位者 25153.6，同批对 v2 的平均分），
直接口径两seed均值是 **+43.7**。两者相差 152，而差值的标准误约 111 —— 1.4σ，
**没有证据说明"赢自己"和"赢牌效率 bot"在这里是两回事**。
（文档里那条"赢自己会骗人"的告警仍然保留：在 9600 局的精度下分辨不出来，
所以**升级门前仍然用外部尺子把守**。）

### 41.4 改法：直接对战当主判据，尺子当升级门

* 主评测：`--a 候选 --b <当前最优>`，9600 局（前一半可提前否掉），尺度是"比在位者高多少分"；
  在位者的分按定义是 0，门槛就是 `--accept-margin`；
* **不再单独重测在位者**（它就在同一局的另外两个座位上），也不再重复打一次头对头；
* 外部尺子（`--yardstick2` / `--yardstick-league`）保留：**只在候选够到门槛、即将升级时才打**，
  和以前一样，防止"赢自己、输牌效率 bot"；
* 历史绝对口径（对 v2 的分）每 5 轮刷新一次，写进 `absolute_anchor` / `best_absolute`，
  README 与趋势图继续用这个数。

### 41.5 实测评测阶段的省法：约 −10%，不是 −27%（原因也量出来了）

改动落地后第一轮（iter 50，3000 局配方 + 本轮的绝对锚点）实测：

| 阶段 | 时间 |
|---|---|
| 自博弈 3000 局 | 87 s |
| 训练 2 轮（2.29M 行，`--threads 4`） | 375 s |
| 绝对锚点（`ck-ab` 对 v2，9600 局） | 174 s → 55 局/s |
| 直接对战评测（`ck-0050` 对 `ck-ab`，9600 局） | 267 s → 36 局/s |
| **一轮合计** | **903.6 s** |

关键在最后两行：**直接对战每局更贵** —— 同一桌上坐着两个神经网络（每步 4 次前向），
而"对牌效率 bot"只有 2 次前向 + 2 个启发式。所以拿"省掉一次 9600 局"去算 27% 是错的：
省下的一次是**便宜的那种**。按同配方（3000 局）折算：

| 口径 | 评测阶段 | 说明 |
|---|---|---|
| 旧（绝对）| 174 s（在位者重测）+ ~87 s（候选前半即被 early-stop）≈ **261 s** | 对 v2 的两次测量，55 局/s |
| 新（直接）| 133 s（候选前半即被 early-stop）+ 35 s（锚点摊销）≈ **168 s** | 一次测量，但只有 36 局/s |

即一轮 **−87 s（约 −10%）**，同时判决方差从"两次测量之差"降到一次直接比较。
**代价与收益都被量清楚了**：这是一次 10% 的提速 + 一次更干净的判决口径，
而不是原先预估的 27%。

**同配方的直接对照（第 31 轮拿到）**：6000 局配方、同样 `--threads 4`、都不含锚点：

| 迭代 | 协议 | 一轮耗时 |
|---|---|---|
| iter 49 | 绝对（在位者重测 + 候选对 v2） | 903.5 s |
| iter 51 | 直接（候选对在位者） | **777.9 s** |

即 **−126 s（−14%）**，与本节的推算一致；判决口径同时更干净（一次比较，SE 62 对 92）。

## 42. 第 31 轮：给网络一条它从没见过的新信息 —— "对手立直后打了什么"

### 42.1 为什么是这条信息

编码器里每个对手的舍牌是**累计计数**（34 维），它分不清"第 1 巡打的"和"立直后打的"；
而"某人立直之后在丢哪些花色"正是人类防守最核心的读牌（捨て牌読み）。
手工版本其实早就有（`mmj_core::danger` 的 suit/timing read），但第 25/26 轮已经证明
**把它塞进危险度特征块没有用**（+204 对旧块 +271.5）——那条结论否定的是"手写的组合方式"，
而**原始证据（谁在什么时候丢了什么）从来没有直接给网络看过**。
更关键的是：老师的标签里**包含着这个读**（它的危险度调用会打开 read），
所以网络过去只能近似"老师会怎么做"，却看不到老师"凭什么"。

### 42.2 新块（+16 维，737 → 753）

对三个对手各 5 维：立直后舍牌数 / 12、立直后按花色（万/筒/索/字）的舍牌数 / 8；
再加自己立直后的舍牌数 / 12。数值都是**原始计数**，不做任何手写加权，让网络自己学读法。

### 42.3 关键工程：旧权重仍然能被新编码器使用（自举的前提）

`Net::load` 过去要求 `checkpoint.feature_dim == FEATURE_DIM`。现在允许**更窄（更旧）**的权重：
它的第一层只有 737 个输入，而 `Layer::forward` 只读 `x[..in]`，多出来的特征对它**不可见**，
行为逐位不变。于是新特征块可以**自举**：在位者直接用它走棋、老师打标签，
生成的第一份数据就带着新块 —— 不需要先训一个"只能看 0"的中间模型。

**验证**：同一个权重 `ck-ab`、同样 2400 局，旧二进制与新二进制给出**完全相同**的
分数（−5.2，顺位 2.5002）。

### 42.4 对照臂：为什么必须有

`im-v15` 是在位者走出来的局面，而在位者比当初生成 `im-v12` 的那个模型更强。
所以"特征臂赢了"也可能是**数据更强的功劳**。对照臂用**同一份数据、同一架构、同一配方**，
只把新块在批次里强制置零（训练器的 `--zero-features 737:753`），
于是两臂唯一的差别就是"这块信息能不能被看到"。

### 42.5 结果：这条通道是空的（两个口径都是零）

一批里测完（9600 局、seed 4242；直接对战是候选 vs 在位者同批同牌）：

| 权重 | 特征 | 对 v2 @9600 | 直接对 `ck-ab` |
|---|---|---|---|
| `ck-ab`（在位者） | 737 | **+307.1**（顺位 2.4918） | — |
| tr-1 | **753（含新块）** | +303.7 | −151.3 |
| tr-2 | 753 | +424.5 | +50.6 |
| tr-3 | 753 | +241.2 | −72.3 |
| **特征臂均值** | | **+323.1（比在位者 +16.0）** | **−57.7** |

两个口径的副本标准差分别是 93 和 102（和"从头训练的副本波动 60~124"一致），
组标准误约 54 / 59，所以：

* 对 v2：**+16 ± 54** —— 零；
* 直接对战：**−58 ± 59** —— 零（甚至略负）；
* 两个口径连符号都不一致，说明这就是噪声。

**结论**：把"对手立直后丢了什么"这条原始证据交给网络，**没有带来可测的实力提升**。
结合第 25/26 轮"手写读牌塞进危险度块也没用"，这条信息通道现在算是**两头都测过了**：
无论手写组合还是原始特征，都换不来分。（数据侧的混淆项由对照臂单独量，
见 §42.6 —— 但注意：混淆项只可能**帮**特征臂，所以"零结果"这个结论本身不受它影响。）

### 42.6 对照臂：把"新块"和"数据血统"分开量 —— 新块是最干净地被否掉的

> ⚠️ **事后更正（第 32 轮自查）**：本节的对照臂实现有缺陷 —— `--zero-features` 只在**训练批次**置零，
> 推理仍喂真实值，属于训练/推理不一致。受影响的只有"对照臂自身强度"这类结论；
> **"新块没有增益"这个结论不受影响，反而更强**（连被噪声拖累的对照臂都没被它赢过）。
> 干净的做法见 §43。

`im-v15` 是在位者走出来的，所以在位者比当初生成 `im-v12` 的模型更强，"特征臂 = 在位者"
也可能是"数据更强 + 特征更差"抵消的结果。对照臂（同一份数据、同一架构、同一配方、同种子，
只把 737:753 强制置零）就是为了把这两件事分开。

最干净的检验不是各自去对 v2，而是**两臂直接对打**（同样的种子→同配对的副本，同桌同牌）：

| 配对 | 特征臂 − 对照臂（9600 局） |
|---|---|
| 1 | **−214.7** |
| 2 | **−36.6** |
| 3 | **+32.8** |
| 均值 | **−72.8 ± 72**（sd 124.6）|

三个口径汇总：

| 比较 | 结果 |
|---|---|
| 特征臂 vs 在位者（对 v2，同批） | +16 ± 54 |
| 特征臂 vs 在位者（直接对战） | −58 ± 59 |
| **特征臂 vs 对照臂（直接对战，同种子配对）** | **−73 ± 72** |

**结论**：把"对手立直后丢了什么"的原始证据做成特征，**没有增益**；
最干净的因果比较（同数据、同配方、只差这一块）点估计还是**负的**。
这与第 25/26 轮"手写读牌塞进危险度块也没用"合在一起，说明**这条信息通道两头都堵死了**：
手写组合没用，把原始证据直接给网络也没用。
本轮因此**不采用**这个特征块（服务与循环继续用 737 维那条血脉）。

### 42.7 本轮顺带为将来留下的两件工具

1. **旧权重可以在更宽的编码器下使用**（`Net::load` 允许 `feature_dim <= FEATURE_DIM`，
   第一层只读自己那 737 个输入）—— 这是"新特征块能自举"的前提：
   在位者直接走棋、老师打标签，第一份数据就带新块，不需要先训一个"只能看 0"的中间模型。
2. **训练器的 `--zero-features A:B`**：同一份数据、同一架构与配方，把某一段特征强制置零，
   作为任何未来特征实验的对照臂。

## 43. 第 32 轮：先修掉自己上一轮的对照臂缺陷，再把"数据新鲜度"量清楚

### 43.1 上一轮的对照臂是坏的（自查发现并修掉）

第 31 轮的 `--zero-features` **只在训练批次里**把新块置零，而推理时编码器照样把真实值填进去。
后果是那 16 个第一层权重**从未拿到梯度**（输入恒为 0）、停在随机初始化上，
推理时却被真实值乘了一遍 —— 这不是对照臂，而是"训练/推理不一致"的模型。

影响分两面：

* "新块没有增益"这个结论**不受影响，反而更强**：连一条被噪声拖累的对照臂都没被它赢过；
* 但"对照臂自身的强度"完全不可用，所以**"数据新鲜度到底值多少"这个问题上一轮其实没答**。

### 43.2 正确的对照臂：同源数据、砍掉新块、旧构建训练

把 `im-v15` 每条记录**砍掉尾部 16 个特征字节**（753+33 → 737+33 = **770 B/条**，
2,609,973 条、2.01 GB），得到 `im-v15-737.bin`，再用**旧（737 维）构建**从零训练三个副本 ——
训练与推理看到的输入因此完全一致。转换后逐字节校验：前 737 列、掩码、动作、回报与源文件**完全一致**。

### 43.3 结果：数据新鲜度也换不来分

同一批（9600 局、seed 4242）：

| 权重 | 训练数据 | 特征 | 对 v2 | 比在位者 |
|---|---|---|---|---|
| `ck-ab`（在位者） | `im-v12`（**旧**策略生成） | 737 | **+307.1**（顺位 2.4918） | — |
| ref-1 | `im-v15-737`（**当前最优**生成） | 737 | +318.5（2.4891） | +11.4 |
| ref-2 | 同上 | 737 | +385.8（2.4879） | +78.7 |
| ref-3 | 同上 | 737 | +330.0（2.4897） | +22.9 |
| **组均值** | | | **+344.8** | **+37.7**（副本 sd 36） |

直接对战（同批同牌、每个副本各自对在位者）：

| 配对 | 差值 |
|---|---|
| ref-1 vs `ck-ab` | −38.8 |
| ref-2 vs `ck-ab` | +78.1 |
| ref-3 vs `ck-ab` | −90.0 |
| 均值 | **−16.9 ± 49**（sd 84） |

**怎么读这两个数**：

* 对 v2 的 **+37.7** 看着像正的，但它要跟**在位者那一次测量**比，而在位者的单次测量自身就有
  60~95 的标准误 —— 合起来的比较不确定度约 **±68**，所以 **+37.7 是零**；
* 直接对战（同牌配对，SE 约 62）给的均值是 **−16.9 ± 49**，也是零。

**结论**：让数据"更新鲜"（用当前最优自己走局面、老师打标签）**换不来可测的增益**。
这其实在意料之中：生成 `im-v12` 的策略与 `ck-ab` 只差约 40 分，数据质量差别本来就很小。
本轮因此不改配方。（顺带一个观察：这三个副本的波动（sd 36 / 84）比历史上从头训练的
60~124 要小，但那更像运气，证据不足以当成"新鲜数据降方差"来记账。）

### 43.4 方法论的账

* 第 31 轮的对照臂**不成立**（训练置零、推理不置零），本轮已修；
  受影响的只有"对照臂自身强度"这类结论，**"新块无增益"不受影响**（连被噪声拖累的对照臂都没赢过）；
* 新增可复用工具：**数据集按特征切片重写**（753 → 737，逐字节校验前缀一致）。
  配合第 31 轮的"更宽编码器可加载更窄权重"与 `--zero-features`，
  今后任何特征增删都能：① 用旧权重自举出新数据；② 用切片重写做出训练/推理一致的对照臂。

## 44. 第 33 轮：正面检验"信息受限"这个诊断 —— 加宽网络能从同一批特征里榨出更多吗

### 44.1 为什么做这个

第 26、28、29、31、32 轮的结论都指向同一句话："这条血脉不是欠训练，而是信息受限"。
但那是**排除法**：加数据没用、加轮数没用、换价值权重没用、加特征也没用。
真正正面的检验只有一个 —— **在同一批数据和同一套配方下扩大容量**。
如果更宽的网络能从同样的 737 维里学到更多，瓶颈就在容量/优化；
如果一样，那"信息受限"就从推断变成了实测。

历史上唯一测过的是**更窄**的网络（512 宽，配对 −195），**更宽从来没测过**。

### 44.2 设置

同一份 `im-v12`、同一配方（900k 行 × 4 轮、lr 3e-4、lr-decay 0.8、value-coef 0.5）、
同三个种子，只把 `--hidden 768,768` 换成 `--hidden 1024,1024`：
参数量 1,241,966 → 约 1.93M（**+55%**），也就是"每步推理贵一半"。
在同一个批次里与在位者比较（对 v2 的分 + 直接对战）。

### 44.3 结果：加宽只是把训练集背得更熟，棋力反而略降

同一批（9600 局、seed 4242）：

| 权重 | 参数量 | 第 4 轮 train policy_loss | 第 4 轮 val_acc | 对 v2 | 直接对 `ck-ab` |
|---|---|---|---|---|---|
| `ck-ab`（768×768） | 1,241,966 | 0.1152 | 0.9613 | **+307.1** | — |
| wide-1（1024×1024） | 1,918,062 | 0.1066 | 0.961 | +280.4 | −122.0 |
| wide-2 | 1,918,062 | 0.1060 | 0.958 | +256.6 | −79.2 |
| wide-3 | 1,918,062 | 0.1065 | 0.962 | +240.3 | −47.2 |
| **组均值** | +54% 参数 | −7% 训练损失 | 持平 | **+259.1（−48.0）** | **−82.8** |

* 对 v2：组均值比在位者低 **48.0**（副本 sd 只有 20 —— 这是本轮一个有趣的副产品：
  容量更大时副本之间**更一致**了，但"更一致"不等于"更强"）；
* 直接对战（同批同牌、最干净的口径）：**−82.8**（三个副本 −122.0 / −79.2 / −47.2）；
* 训练指标：**训练损失降了 7%，验证准确率却没有任何变化**（0.958~0.962 对 0.9613），
  棋力还略降 —— 多出来的容量主要是在**背训练集**（以及老师的平局任意选择）。

### 44.4 这一轮的结论与账

**"信息受限"这个诊断从排除法变成了正面的实测结果**：
在同一批数据、同一配方、同一批种子下把容量加大 54%，既没有更拟合验证集，也没有更强，
反而略弱。两头都堵住了：

* 加**信息**（第 31/32 轮：新特征、更新鲜的数据）→ 零；
* 加**容量**（本轮：参数量 +54%）→ 零或略负；
* 加**训练量**（第 26/28 轮：更多数据、更多轮）→ 零或略负；
* 换**目标**（第 19–21、27 轮：价值分解、二值 RL、价值损失尺度）→ 零或略负。

**不采用**加宽：它还会让每次推理多花约一半的权重字节（前向占生成 41%、评测 44%），
用吞吐换一个不存在的增益是纯亏。

## 45. 第 34 轮：把对外数字压实，并把循环的"训练量"按证据减半

### 45.1 torch.compile 在这台机器上不可用（记录，免得下次再试）

训练是循环最大的一块（375 s / 780 s），而且是纯 MLP 前后向，理论上 Inductor 能融合。
实测：Inductor 生成的 C++ 会 `#include <omp.h>`，而 macOS CommandLineTools 工具链**没有 OpenMP 头**
→ `fatal error: 'omp.h' file not found`，编译直接失败（`brew --prefix libomp` 只是指向一个空目录）。
选项保留在训练器里（装了 libomp 的机器可用），本机退回 eager。

**顺带记一次自己造成的故障**：给编译开关加线时，我把训练与验证两处的前向都改成了一个局部变量
`body_forward`，但验证函数 `evaluate()` 是另一个作用域 —— 于是循环跑到"训练中途的验证"那一步
就 `NameError` 崩了。**循环自己的失败处理按设计生效**（`training failed; stopping`），
服务中的权重、状态文件、best 指针都没变（本轮迭代被丢弃、重跑即可）。
修法是把 `body_forward` 作为参数传给 `evaluate()`（默认回退到 `net["body"]`），
并打开 `torch._dynamo.config.suppress_errors`，让编译失败安静回退而不是崩运行
（第一个 forward 才抛错，写在 `torch.compile(...)` 外面的 try 抓不到）。

### 45.2 训练量减半（依据是"拟合不涨棋力"这条已经反复测实的结论）

第 26 轮（3.4M 行**不如** 900k）、第 28 轮（8 轮 ≈ 4 轮）、第 33 轮（参数 +54% 无益）
都指向同一件事：**多拟合不涨棋力**。而循环每轮要过 2.3~2.6M 条决策、占一轮 48%。
于是把每文件记录上限从 900k 降到 **400k**，实测（同配方 region-sh2/full-dagger 一族的 3000 局迭代）：

| | 每轮训练条数 | 每轮训练耗时 | **一轮总耗时** |
|---|---|---|---|
| max-records 900k（iter 51 / 49） | 2,291,200 ~ 2,639,360 | ~250 s/轮 × 2 ≈ 375~410 s | 777.9 s（6000 局配方） |
| **max-records 400k（iter 52）** | **1,544,704** | **124 s/轮 × 2 = 248 s** | **607.5 s** |

即**一轮 −170 s（−22%）**，也就是同样算力下**每小时多跑约 28% 的迭代**（每轮自博弈局数不变）。
候选质量由循环自己的同批评测 + 拒绝机制守着，所以这个取舍最坏只是"多花几次迭代"，
不会让服务中的权重变差 —— iter 52 的候选实测 **+2**（门槛 +60）被拒绝，符合预期。

## 47. 第 36 轮：既然"学老师的鸣牌"是负收益，那就把它从损失里删掉试试

### 47.1 先把第 35 轮的发现扩到**所有**标签类别

第 35 轮只看了鸣牌。把按类别的召回率一次列全（`diagnose_calls.py`，40,000 行留出样本）：

| 标签类别 | 行数 | 复现率（recall） | 模型使用该类的比例 |
|---|---|---|---|
| 打牌 | 29,792 | **0.971** | 0.745 |
| 立直打牌 | 770 | **1.000** | 0.019 |
| 杠 | 80 | 0.887 | 0.002 |
| 自摸 | 166 | 1.000 | 0.004 |
| 荣和/九种九牌 | 318 | 1.000 | 0.008 |
| 过 | 8,413 | 0.997 | 0.220 |
| **碰（pon）** | **461** | **0.137** | 0.002 |

**唯一没学会的类别就是"碰"**（其余 0.89~1.00），而第 35 轮已经证明：强行让它学会碰
（加权 10×）会让棋力塌 1700 分。于是这一轮问一个更直接的问题：
**既然这些标签是有害的，那把它们从模仿损失里彻底删掉，会不会比保留更好？**

`--weight-calls 0` 就是把标签为碰的行权重置 0（等价于从损失里剔除），
其余配方与 `ck-ab` 完全相同，三个种子。

### 47.2 顺带发现：分歧集中在"老师自己也走在危险牌上"的局面

同一个诊断工具把**打牌**这一类再按"老师那张牌有多危险"（编码器里 DANGER 特征块的取值）切开：

| 老师打的牌的危险度 | 行数 | 复现率 |
|---|---|---|
| 安全（<0.05） | 24,699 | **0.982** |
| 0.05 ~ 0.3 | 2,804 | 0.968 |
| **危险（>0.3）** | **2,289** | **0.857** |

也就是说：**在有人立直、需要做"推/弃"判断的局面里，学生的复现率掉到 85.7%**，
比安全局面低 12 个百分点 —— 这是比"碰"更大的一块（5.7% 的行），也是模仿里最难的一段。
结合它的实测风格（放銃率 0.104 比老师 0.119 更低、实力高 300 分），
合理推测学生在这些局面上**比老师更保守**，而这份保守和"不学碰"一样，是它的实力来源之一。
（这条留作下一轮的实验：把这类行加权／减权，看棋力往哪边走。）

### 47.3 结果：把"碰"的标签删掉 —— 什么都没变（而且解释得通）

三个副本（`--weight-calls 0`，其余配方与 `ck-ab` 完全相同）：

| 权重 | 对 v2（同批 9600 局） | 直接对 `ck-ab` |
|---|---|---|
| `ck-ab` | **+307.1** | — |
| np-1 / np-2 / np-3 | +219.6 / +325.4 / **+307.1** | −136.7 / +112.2 / −6.8 |
| 均值 | **+284.0（−23.1）** | **−10.4** |

两个口径都是零（对 v2 的组标准误约 33，直接对战约 72）。

**机制**：这个"从不碰"的边界**不是那 461 行教的，而是 8,460 行"过"教的**（同一类局面里
"过 : 碰" ≈ 95 : 5）。所以：

* 把稀有一侧**减少到 0**：边界不动 → 棋力不变（本轮）；
* 把稀有一侧**加权 10 倍**：边界被硬拽过去 → 棋力塌 1700 分（第 35 轮）。

**结论**：这条旋钮的最优点就在"让多数类（过）主导"——也就是现行基线所在的位置。
一个副产品很有意思：np-3 与 `ck-ab` 的权重**并不相同**（md5 不同、训练种子相同、损失不同），
但在 9600 局对 v2 的评测里**得到一模一样的分（+307.1，顺位 2.4918）**，
说明这 1.15% 的标签改动对策略的实际行为几乎没有影响（只有在与 `ck-ab` 对局时才出现 −6.8 的细微差别）。

### 47.4 这条线的账

| 做法 | 结果 |
|---|---|
| 照常模仿（基线） | 对 v2 +307 |
| 删掉"碰"标签（本轮） | +284（零） |
| 加权 10× 学"碰"（第 35 轮） | **−1358**（灾难） |
| 手写"多鸣牌"（第 21 轮） | −340 |
| 老师 eager=2（第 14 轮） | −750 |

四条独立的路都指向同一句话：**在这套对手里，"会鸣牌"是负收益，而学生恰好没学会它。**

## 50. 第 41 轮（发布阶段）：一次差点漏掉的"代码漂移"，与两个自行否决的小优化

这一轮在做发布与界面工作，顺手做了三件事，其中第一件是个**真问题**。

### 50.1 源码里还留着第 31 轮那个被否掉的 753 维特征块（已修）

第 31 轮给编码器加了"对手立直后舍牌"的 16 维特征块（737 → 753），实验结果是**零到略负**、
没有采用。但当时只否掉了**数据与权重**，源码没有回退 —— 于是树里一直留着那个块。

后果本来会很难看：任何一次 `cargo build` 之后，`mmj-selfplay` 就会用 753 维编码器生成数据，
而服务与循环那条血脉的权重是 737 维。生成出来的 753 维经验文件一旦混进循环的数据混合里，
训练会立刻因维度不匹配而失败（循环自己的错误处理会停下来，不会写坏权重，但会白跑一轮）。

**发现方式**：发布前跑那条"数据逐字节可复现"的核对，md5 与基线不一致。
先怀疑刚加的 shanten 缓存，做了旁路实验——**旁路之后 md5 依旧不一致**，于是排除缓存，
去看生成文件的头部，直接看到 `feature_dim: 753`。

**修法**：删掉该块与它的常量，编码器回到 737；核对随即恢复为与基线**逐字节一致**
（`6339b63f…`）。同时在原地留了一段注释说明"为什么这里少了一块"，
免得下一轮有人再把它加回来。

**教训**：一个实验被否掉时，要连**代码**一起否掉。只回退数据与权重，
树里就会留下一个"随时会被下一次构建激活"的开关。

### 50.2 顺带测掉的小优化：手牌级 shanten 记忆化（零收益，已回退）

推理时同一步里编码器、规则老师、引擎自己的决策生成会反复问同一批手牌的向听，
理论上可以记忆化。实现（线程内 HashMap，键 = 34 个计数 + 面子数，容量 8192 满了就清空）
并用等价性测试钉住，然后做交替 A/B：

| | 1200 局生成耗时 |
|---|---|
| 不记忆化 | 43.1 s / 44.8 s |
| 记忆化 | 43.3 s / 42.9 s |

**差异在噪声内（约 2%，且两对符号相反）** —— 因为真正的重复早就被花色 profile 的缓存吸收了，
再包一层手牌级缓存只剩哈希开销。生成的记录仍逐字节一致（这是记忆化应有的性质，
也顺带证明了实现没写错）。按本项目一贯的纪律：**没有可测收益就不留代码**，已回退。

### 51.1 牌桌重做（三条反馈 → 一块牌桌）

| 反馈 | 原因 | 做法 |

| 牌面看不清 | 每张牌只有"墨"（面），印在深绿呢上 | 牌 = **白牌体 + 面**：`.tile` 用 `Front.svg` 作底，面用 `<img>` 叠在上面（`inset:0`），尺寸仍由 `--w/--h` 控制；素材是 CC0 的 `FluffyStuff/riichi-mahjong-tiles` |

### 51.2 一个真规则 bug：被搶槓的加槓留下了"幽灵宝牌"

**现象**（`state.rs`）：`do_kakan` 调 `register_kan(..., reveal_dora=false, allow_abort=false)` 是**对的**
（加槓的宝牌指示牌要等搶槓窗口关闭），但 `register_kan` 里 `total_kans += 1`、`wall.on_kan()`
是**无条件**执行的。而 `revealed_indicators() = 1 + kan_count`，于是：

1. **搶槓窗口内**，`view.dora_indicators` 已经多了一张指示牌（此时那张牌**还不该**翻开）；
2. 若窗口内有人**搶槓和了**，`finish_kakan` 被跳过，但 `kan_count` / `total_kans` 已经加过了——
   加槓"从未发生"，树上却留下一张**幽灵宝牌指示牌**，而且这张牌在 `win_context` 里会被算成宝牌，
   **计入搶槓者的和牌**——与代码里那句注释（"the 加槓 never happens, so no kan dora is turned"）直接矛盾。

**修法**：把"计数 + 翻指示牌"整块推迟到 `finish_kakan`；`register_kan` 在 `reveal_dora == false` 时
只做与"鸣牌已宣告"有关的事（清一发、置 `any_call`）。`wall.on_kan()` 全工程只有这一处调用，改动是局部的。

**怎么证的**：

* 新增单测 `robbed_kakan_leaves_no_phantom_dora`：造出"1 家碰 5m → 摸到第 4 张加槓 → 3 家搶槓和了"的局面，
  断言窗口内 `wall.kan_count() == 0`、`revealed_indicators()` 不变，和了后由 `Event::Win` 记录到搶槓役。
  **并且做了反证**：把旧逻辑临时改回去，这条测试立刻失败（`left: 1, right: 0`），
  说明它测的是这个 bug 本身，而不是一个恒真断言。
* **行为差异量**：改动前/后二进制在同一 seed 上各生成 1000 局（tonpuu、`--batch 32`）：
  记录数 **716504 → 716504，逐字节完全一致** —— 也就是说这份 1000 局样本里，
  没有一局的记录会因为这个修复而改变。频率参照：`kan_rate = 0.0277`
  （每个座位手牌里出现过杠的比例，2000 局统计），加槓是其中一部分，
  而"加槓还恰好被搶槓"更少见，所以数据层面测不出差异是合理的。
  （**更正**：本节初稿写的是"717555 → 717939，+0.05%"。那个数字来自默认 `--batch 256`，
  而当时的生成器在该 batch 下**本来就不可复现** —— 详见 §52.4，这是噪声不是效应。
  这个修复的必要性依据是规则错误本身，不是数据差异。）
* **棋力无影响**：修完之后重跑标准协议——
  `mmj-eval --a ck-ab.bin --b efficiency-v2 --games 9600 --seed 4242` = **+304.7**
  （修前同协议 **+307.1**；差 2.4，而 9600 局的标准误是 62~70，即 <0.1 SE）。
  两侧用的是同一个引擎，所以"候选 vs 在位者"的同批比较完全不受影响。

**代价与结论**：`6339b63f…` 那条"24 局数据逐字节一致"的基线**从此作废**——不是回归，
而是一次**有意的行为修正**。现有权重是在"搶槓窗口内多一张宝牌指示牌"的数据上训出来的，
但那只是极少数窗口里的输入差异（且不影响标签对错），因此**不重训、不重测历史结论**；
往后所有按同批协议做的比较都在新引擎下进行，仍然可比。

**教训**：行为类修复**不是 no-op**，必须给出差异幅度（这次是 +0.05% 的记录数、对棋力 <0.1 SE），
否则"逐字节一致"这条纪律会被误用成"任何差异都是回归"。
一条"逐字节一致"基线的有效期，只到下一次**有意**改动为止；改动之后要重新立基线（拿前后二进制对打，而不是拿旧 md5）。

### 52.2 新检查又抓出第二个 bug：立直后手牌"没锁"

为了把这条反馈变成可重复的回归检查，`scripts/ui_check.py` 增加了 `riichi` 模式：
它一直打到能立直、点下立直，然后在**此后每一个决策窗口**检查
"有没有出现吃/碰/杠按钮""手牌里有几张可点"。拿**修前**的二进制跑，它照实报错：

```
illegal calls offered after 立直: ["东3局: offered ['碰']", "东3局: offered ['吃 7m8m9m']", ...]
```

修好引擎之后再跑，动作按钮干净了，却冒出另一条：

```
东1局: 3 clickable hand tiles after 立直
```

原因是客户端 `findDiscardAction` 的"同种类回退"：立直后引擎只给**摸到的那一张**，
而客户端会把**手里同种类的其余几张**也算成可打（点它们实际发出的是摸切）。
规则上不算错（同种类的牌等价），但它让"手牌已锁"这件事在界面上看不出来。
修法是两条：立直后**只有摸到的那张**可点；同种类回退**不再跨红五**——
红五是另一张牌，悄悄换成普通五会改变牌河与宝牌计数，宁可提示"现在不能打出"。
（顺带记录一个已知简化：动作列表是**按种类**给的，所以"手里同时有红五和普通五"时，
引擎只会提供普通五那张，玩家无法主动打红五。要改就得把动作空间按红/非红拆开，
那是特征层面的改动，本轮不动。）

### 52.3 面板遮挡：提示面板正好压在鸣牌按钮上

用"量"的办法查界面（见 §51.4）时又抓到一条：`#hint-box` 原本固定在右下角，

### 52.4 差点骗了我的东西：`generate` 在默认 batch 下**本来就不可复现**

做 §52.1 的对照实验时，我按老办法跑"同一 seed、改动前后各 1000 局、比对 md5"，
得到"修前 717555 条、修后 717939 条"的差异，差点写进结论。幸亏顺手做了一次
**同一二进制、同一 seed、跑两遍**的对照：

```
/tmp/sp-presentation generate --games 1000 --out det-1.bin --seed 1
/tmp/sp-presentation generate --games 1000 --out det-2.bin --seed 1
→ md5 不同
```

**同一份二进制、同一个 seed，生成的数据都不一样。** 根因在 `runner.rs`：
`Engine` 是**每个 rayon worker 创建一次**（加载权重很贵），而它的 RNG 用固定种子
`0xC0FFEE`，于是"某一局抽到了哪些随机数"取决于**那个 worker 在它之前恰好打了几局**，
也就是取决于 work-stealing 调度。后果：

* 批量小的时候（`--batch 1`、`--batch 32`）分割边界稳定，数据可复现（且三者 md5 相同）；
* `--batch 256`（**工具默认值，也是训练循环一直在用的值**）下每次运行都不同：
  同一二进制两次跑出不同 md5，`RAYON_NUM_THREADS=2` 又与默认不同。

这解释了为什么"四席全用老师的 1000 局"能逐字节一致（老师是规则 bot，不用那个 RNG），
也解释了 §51 里那个"加槓修复让记录数 +384"的结论 —— **那是噪声，不是效应**。

**修法**：`play_game` 一开始用**这一局自己的 seed** 重新播种 RNG
（`StdRng::seed_from_u64(seed ^ 0x5EED_1234_ABCD_0001)`）。修完之后：

| 配置 | md5 |
|---|---|
| `--batch 256` 第 1 次 | `a5595590…` |
| `--batch 256` 第 2 次 | `a5595590…` |
| `--batch 1` | `a5595590…` |
| `--batch 32` | `a5595590…` |
| `RAYON_NUM_THREADS=2 --batch 256` | `a5595590…` |

批次大小与线程数都改不动结果，数据只由 `--seed` 决定 —— 这才是"逐字节可复现"该有的样子。
副产品是探索噪声也变干净了：以前同一个 worker 上的若干局共享一条随机流（彼此相关），
现在每一局独立。

**教训**：任何"改动前后各生成一份数据、比对 md5"的实验，
**必须先证明该配置下生成器本身可复现**（同一二进制跑两遍）。这次的
"逐字节一致"纪律恰好是最先被破坏的东西，而它破坏的方式是**伪造出一个效应**。

### 52.5 修正后的三组对照（1000 局、seed 1、`--batch 32`）

| 改动 | 记录数 | md5 | 结论 |
|---|---|---|---|
| 加槓/搶槓 修正（§51.2） | 716504 → 716504 | **完全相同** | 数据层面无影响（只在"被搶槓"那一步才有区别，1000 局里没触发到会被记录的地方） |
| 立直后禁止鸣牌（§52.1） | 716504 → **716288**（−0.03%） | 不同 | 有影响：被移除的非法选项偶尔会被 2% 探索选中，从而改变后续走向 |
| 展示用新字段（`furiten_temp/riichi`、`dora/ura/aka_han`） | 716288 → 716288 | **完全相同** | 纯展示，符合预期 |

注意第一行**推翻了 §51.2 里"记录数 +0.05%"的说法**：那个数字是 batch 256 的噪声。
加槓修复的必要性依据不是数据差异，而是"幽灵宝牌会被算进搶槓者的点数"这条规则错误本身。

## 53. 第 43 轮：小局结算 —— 一个"报番面板永远不出现"的服务端 bug

### 53.1 现象与根因

使用者反馈："每一小局结束应该有结算，有人和牌应该报番，流局有人听牌应该有流听罚符；
我自己自摸之后看不到番数，直接就进到下一局了。"

客户端**有**结算面板（`showWin` / `showRyuukyoku`，带役种、番符、收支表），
所以先问一个更基础的问题：这些事件到底有没有送到客户端？用一条裸 WebSocket 打了几局，
把收到的消息类型全打出来：

```
events: ['Discard', 'Draw', 'Discard', 'Draw', 'Discard', 'Draw']   # 六条事件，全是别人的
```

一个人类玩家打出一张牌，服务端**一条事件都没发**。原因在 `main.rs` 的动作处理里：

```rust
if let Err(e) = s.table.submit(s.human, action) { ... }   // 返回值被丢掉了
let events = s.advance();                                  // 只收下"之后"自动发生的事件
```

`submit` 返回的正是**这一步产生的事件**。于是：

* 玩家自己的舍牌不进日志（"对局记录"里从来没有"你 打出 X"）；
* 玩家**自摸 / 荣和 / 九种九牌**时，`Win` 事件被丢掉 → 客户端收不到 → 没有报番面板；
* 玩家的那一张牌**打空牌山**（荒牌流局）时，`Ryuukyoku` 事件同样被丢掉 → 没有流局结算；
* 别人和牌/流局时事件由 `advance()` 产生，所以**那些**面板是能出现的 —— 这解释了
  为什么这个 bug 看起来"时有时无"，也解释了为什么我之前的自动化检查没抓到它
  （它们点击的"自摸！"面板多半是 bot 的）。

**修法**：把 `submit` 的事件留下，与 `advance()` 的事件合并后一起发。

### 53.2 结算本身：报番、罚符、结算后点数

顺手把结算做成真正的结算（这也是使用者的要求）：

| 面板 | 内容 |
|---|---|
| 和牌 | 和了者与和了牌、**和牌手牌（含副露，和了牌描金）**、役种列表（报番）、宝牌/里宝牌/赤宝牌各加几番、合计番符与庄家、放铳者支付/每家支付（含立直棒）、**四家本局增减 + 结算后点数** |
| 流局 | 流局原因；荒牌流局列出四家听牌 ○/×；有听牌时写明"不听罚符：不听者每人 -1000，N 家听牌者平分 N×1000"；同样的收支表 |

引擎为此在 `Event::Win` 上补了 `hand` / `melds`（`#[serde(default)]`，旧牌谱仍可读）——
只报一个"3 番"而不显示是哪副牌和了，不叫结算。之前 `ScoreResult` 也已经带上
`dora_han` / `ura_han` / `aka_han`（§52.6）。

还有一个"顺序"上的细节：面板是模态的，但服务端在发完事件后紧接着就会把**下一局**的状态发过来，
于是玩家会在读结算时看到身后的牌桌已经换成新一局。现在客户端在结算面板打开期间**暂缓渲染**，
把新状态先存着，点"继续"时才切过去 —— 实测：面板打开时牌桌停在刚结束的那一局
（`东1局 余22 手牌13张`，`pending=true`），点继续后切到 `东2局 余66 手牌14张`。

顺带修掉一个把引擎记号漏到界面上的问题：提示面板写着"推荐：E"（`E` 是引擎里"东"的
内部记号，`pon5m5m5m` 这类也一样）。现在统一过一个 `friendlyAction()`，
显示成"推荐：打出 东"/"碰 5m 5m 5m"，牌谱分析面板的选项分布同样处理。

### 53.3 怎么让它以后不会再坏

`scripts/ui_check.py` 增加两个模式：

* **`protocol`（秒级、确定性）**：用裸 WebSocket 打几局，断言"玩家自己的动作产生了事件"。
  这是根因的检查，与能不能碰到自摸/流局无关。**反证**：把服务端改回丢掉事件，
  它立刻失败并直接说明后果——
  `the player's own action produced no events, so no settlement can be shown for a tsumo, a ron or a final discard`。
* **`settle`（分钟级、内容检查）**：用浏览器打牌（借"提示"面板按基线推荐出牌，
  这样人类真的会赢），每当有面板出现就检查内容：和牌面板必须有手牌图、有"番"、
  有四人收支表；流局面板必须列听牌、有听牌时必须出现"罚符"字样与收支表。
  它还会统计"面板是不是由我们自己的动作触发的"。

这一轮它抓到的第一件事是**我自己写的 bug**：`showWin` 里把 HTML 字符串直接
`appendChild`（`TypeError: parameter 1 is not of type 'Node'`），面板当场渲染不出来。
这正是把反馈变成检查的价值 —— 肉眼很难分辨"面板没出现"和"面板出现了但内容是空的"。

另外还发现检查脚本自己的两个坑（都已修）：一是每轮轮询都去点"提示"，
把服务端算提示的算力吃满、反倒饿死了对局消息（现在按"每个决策问一次"限流，
客户端也给"提示"按钮加了 400 ms 防抖）；二是当基线推荐的不是打牌（暗杠/鸣牌）时，
检查会原地打转导致一局永远结束不了（现在退回"随便打一张"以保证牌局继续）。

## 54. 第 44 轮：多人荣和逐家结算、立直/和牌大字提示、牌面重排（以及一轮系统自审）

使用者这一轮提了四条，其中两条是"交互漏看"，一条是美术比例，一条是多人荣和的结算顺序。
做完之后又跑了一轮系统自审（读代码 + 真实浏览器 + 575 份牌谱回放），自审又抓出 12 个问题。

### 54.1 多人荣和：一家一张面板，按逆时针依次结算

原来的客户端只取**最后一条** `Win` 事件，所以双响只看得到一家的手牌与报番。
现在结算做成**队列**：一局结束时把所有 `Win`（或流局）按"离放铳者最近的一家优先"排序
（即出牌顺序 / 逆时针：`(seat - from + 4) % 4`），逐张弹出，点"继续"看下一家。
双响先播报"双响"两个大字，再依次结两家的牌。

顺带修掉一个**引擎层面的错**（审计发现）：`apply_win` 把**整局的合计收支**和**同一份立直棒**
塞进了每一条 `Win` 事件里，于是双响时两家的面板都写"立直棒 +2000"、都显示对方的进账。
现在事件里多了 `paid`（这家自己收了多少）和 `nagashi`，立直棒只算在**第一家**（引擎本来就是这么分的）。
另外 `Event::Win` 的 `hand`/`melds`/`nagashi` 全部 `#[serde(default)]`，旧牌谱仍可读。

### 54.2 交互：立直、和牌、流局都要"喊一声"

* **立直**：一张牌悄悄横过来确实容易漏看，现在切换成一瞬间放大淡出的**"立直"大字**（92px 金字，
  带轻描边与弹出动画）+ 是谁立的。它 `pointer-events: none`，绝不挡点击。
* **和牌**：先播报"自摸"/"荣和"/"双响"/"流局满贯"，**1.2 秒后**才弹结算面板
  （原来两者同时出现，面板会把大字盖住 —— 使用者要的是"先看一眼大字，再看结算"）。
* **流局**：同样先喊"流局"并带上原因（荒牌流局 / 九种九牌 / 四风连打…）。
* **顺序保证**：从手牌结束那一刻起 `boardHold = true`，下一局的状态一直被压着，
  直到最后一张面板被点掉才切过去 —— 不会在读结算时看到身后的牌桌换了局。

### 54.3 牌面：把 SVG 缩进白牌里，并统一比例

先**量**再改（这轮没有靠眼睛）：

| 量出来的事实 | 数值 |
|---|---|
| 牌身（`Front.svg`）的画布 | 300×400，但图形实际范围是 315.4×426 —— **四角被自己的 viewBox 切掉** |
| 各花色的留白 | 从 **0.1%**（`Sou1`）到 15%（`Pei`），29/38 个花色留白小于 4% |
| 「白」这张牌 | `Haku.svg` 里所有图形都在 `<defs>` 里，**什么都不画**（空牌）；上游另有 `Blank.svg` 是带边框的白牌 |

做法（只改素材的 `viewBox`，不动图形、不加 CSS 技巧）：

* 牌身/牌背：`viewBox` 设成它**真实的外接框**，于是圆角不再被裁、牌面正好铺满牌块；
* 每个花色：`viewBox` 重新居中到它自己墨迹的外接框，并让墨迹占牌面的 **74%**（各家一致）；
* 「白」改用 `Blank.svg`（带边框的白牌，也是这副牌里唯一画不出东西的一张的替代）。

改完实测：**任意花色的最小留白 11.5%**（原来 0.1%）、**居中误差 ≤0.6%**（原来 ≤3%）。

## 55. 第 45 轮：第二轮系统自审（引擎、牌谱、仪表盘），共 12 个问题

第 44 轮结束后又跑了一轮"不同角度"的自审：不看牌桌，而是逐条对照**特殊流局/役满/责任払い**、
**牌谱分析链路**、**训练仪表盘**，并写探针程序实际构造局面验证。抓到的都修了，下面按影响排序。

### 55.1 引擎：两个会真正影响对局的错误

1. **四槓散了之后，下一局多摸一张牌**（`aborted`/phase 判据失效）。
   `abort_round()` 内部会 `pump()`，而 `pump()` 直接进入**下一局**，所以三处
   `if self.phase == Phase::RoundEnd { return; }` 的守卫**永远为假** —— 杠的"岭上摸牌"
   落在了下一局、还轮不到他，于是该家 14 张、牌山少一张。
   修法：加一个 `round_seq`（每局开始自增），杠的处理前后比对它；变了就说明这杠触发了流局，
   不再摸牌。**反证**：去掉守卫，新增的单测 `a_four_kans_abort_does_not_draw_into_the_next_round`
   立刻失败（新一局里出现 `Draw{rinshan:true}`）。
2. **四風連打 / 四家立直 抢在荣和之前**：两张流局判据都写在"生成鸣牌窗口"**之前**，
   于是那一张牌上的荣和被无声丢弃。修法：改成"延迟流局"——先记下 `pending_abort`，
   等鸣牌窗口关闭且无人和牌时才真的流局。**反证**：单测 `a_ron_beats_a_deferred_abort`
   同时给了和牌臂与对照臂（无人能和时才流局）。

另外**栄和/和了相关的三个记账错误**：

| 问题 | 现象 | 修法 |
|---|---|---|
| `paid` 把立直棒算进去了 | 面板写"支付 2300 点 · 立直棒 +1000"，实际只有 1300 易手 | `paid` 只报本局支付，立直棒单独由 `riichi_sticks_taken` 表示 |
| 责任払い 指向错的人 | 面板按 `from`（放铳者）写"谁支付"，但 pao 时是**责任者**付全部 | 事件加 `pao_payer`，面板写"責任払い：X 支付全部 N 点" |
| `RoundEnd` 带的是**旧**本场数 | 日志"下一局 N 本场"永远少 1 | 事件加 `next_honba`，日志改用它 |

### 55.2 牌谱分析：从"94% 的文件打不开"到全部可用

* 根因一（结构性）：验证器逐字节比较**重建的事件日志**，但事件结构这一路加了
  `hand/melds/paid/pao_payer/nagashi/next_honba` 与宝牌拆分的三个字段，
  于是**改动之前录的牌谱天然不可能通过**。修法：比较**规范化投影**（剥掉这些后加的字段），
  这样"重建出的对局确实不同"仍会被抓出来，而"只是字段变多了"不再误杀。
  实测：200 份抽样里 **0 → 233/250 通过**。
* 根因二（诚实性）：`Decision::allows` 只按**种类**校验弃牌，而 `do_discard` 会悄悄移除一张同种类的牌、
  却把请求的那张**写进日志**——于是日志里出现"打出一张手上没有的牌"（真实案例：一局里
  6s 被打出两次），**这样的牌谱无法回放**。修法：`do_discard` 记录**真正离手的那一张**
  （精确匹配优先，否则取手上同种类的牌）。同时客户端在结算期间**禁用点击**，
  避免"牌桌已经走到下一步、界面还停在旧决策"时发出陈旧动作。
* 兜底：万一仍无法精确重建（规则真的变了），不再直接报错，而是**退化成"按牌谱记录统计"**
  并明确标注"未能精确重建，结果仅供参考"，同时跳过逐手分析。
  实测抽样 120 份：**100 份精确重建 + 20 份降级可用，0 份报错**（改动前是 0 可用）。
* 顺带修：流し満貫 在牌谱回放里被当成"自摸"动作，导致重建在下一个决策处分叉；
  未听流局把途中流局也算成"未听"（每次流局凭空多 4 个未听）。

### 55.3 规则：連風牌 的符数与自己写的文档矛盾

`rules.rs` 的字段注释写着"連風牌雀头 4 符；天鳳用 `false`（2 符）"，
但 `Rules::tenhou()` 传的是 `true`、`competitive()` 传的是 `false` —— 两个预设**装反了**。

影响面很小（需要场风与自风相同且有该风对子），但这是使用者明确要求"按更标准的来"的类别。

### 55.4 仪表盘：两个会误导人的显示

  **相对在位者的分差**（-138…+72）。画在同一坐标轴里，真实的趋势被压成一条线，

### 55.5 修完之后的又一轮自查（第 45 轮续）

## 56. 第 46 轮：一次"看起来像 bug"的途中流局，以及被浏览器缓存骗了 24 小时的牌面

使用者这一轮报了两条：**"我第四巡宣布立直立刻流局了，牌山还远远没有摸完"** 和
**"牌的图案还是铺满牌面，四周没看出留白"**。两条都不是我以为的那个原因，查清过程值得记下来。

### 56.1 那条"立刻流局"是合规的途中流局，但界面没说清

先按"能不能复现"的顺序查：

1. **引擎里的每个 `abort_round` 判据**：九種九牌（要求 `draws == 1`、无鸣牌）、
   四風連打（要求四家**首巡**同风且无人鸣牌）、四家立直（四家全部立直）、
   四槓散了（四个杠且非同一人）、三家和了 —— 逐条读代码，判据都在。
2. **把 755 份已存牌谱全部拿来对账**：从事件日志里重建每一局的经过，
   对每一次"非荒牌流局"核对它自己的日志能否解释这次流局。结果：

   | 流局原因 | 次数 | 对账结果 |
   |---|---|---|
   | 荒牌流局 | 1365 | — |
   | 九種九牌 | 9 | **全部合规**（都在首巡、无鸣牌、牌山接近满） |
   | 四家立直 | 2 | **全部合规**（第 4 家立直后立刻流局） |
   | 四風連打 | 1 | **合规**（四家首巡同风、无鸣牌） |
   | 四槓散了 / 三家和了 | 0 | — |

   不合理的流局：**0 次**。
3. **写探针按"正常玩家"的方式打**（照基线建议出牌、一有机会就立直）：
   9 次立直宣言、0 次异常流局。

结论：使用者遇到的是**合规的途中流局**，最可能是**九種九牌**——即某一家用**第一次摸牌**
手里就有九种以上幺九牌，宣布本局作废；此时牌山几乎还是满的（余 66 张），
而使用者自己的立直恰好就在前后，于是看起来像"我立直→立刻流局"。
（`docs/RULES.md` 第 23 条也明确：五种途中流局全部**连荘**，这也是它看起来"没打完就结束"的原因。）

**真正的缺陷在界面**：结算面板只有一行"流局 / 九种九牌"，既没说**是谁宣布的**，
也没解释**为什么牌山没摸完也能结束**，更没有**把牌山余数摆出来让玩家自己核对**。
所以这一轮改的是"让它说清楚"：

* 事件 `Ryuukyoku` 新增 `by`（谁宣布，九種九牌用）与 `wall_remaining`（本局结束时牌山余数），
  两者 `#[serde(default)]`，旧牌谱仍可读；
* 面板现在写：**「九种九牌 · 神经网络 AI 1 宣布」**＋一句解释
  （"途中流局：某家在第一次摸牌时手中有九种以上的幺九牌，宣布流局"）
  ＋**"本局结束时牌山还剩 66 张（途中流局：不计点数，庄家连庄并加一本场）"**；
* 大字播报也带上宣布者，并且途中流局播报的是**"途中流局"**而不是"流局"，
  与荒牌流局区分开；
* 对局记录行同样写明宣布者与余牌数。

新增单测 `a_nine_terminals_abort_names_the_declarer_and_the_wall`，
并在 `settle` 检查里加了断言：注入一次九種九牌流局，面板必须**同时**出现
"九种九牌""宣布""余 66 张"三项信息。

### 56.2 牌面留白没生效：浏览器拿着 24 小时前的旧素材

牌面（第 44 轮）确实已经改好——服务器上的 SVG 是新的、渲染出来的留白是 13~20%。
但使用者看不到，因为**服务器给 `/tiles/*.svg` 发的响应头是 `Cache-Control: public, max-age=86400`**：
浏览器最多可以**一整天**不重新请求，于是我改完素材、重启服务、刷新页面，
浏览器仍然用自己缓存里的旧图。这是一个纯粹的自伤：**素材换新必须让 URL 或缓存策略换新。**

修法两层：

* 服务端：`/tiles/*.svg` 改为 `Cache-Control: no-cache` + **内容哈希 ETag**，
  条件请求返回 304（实测：带 `If-None-Match` 得 `304`，不带得 `200`）；
  `app.js` / `style.css` / `dashboard.*` 这些同样"编译进二进制"的资源也一并改成 `no-cache`，
  免得改完前端还要等浏览器缓存过期。
* 客户端：牌面 URL 带上版本号（`/tiles/Man1.svg?v=2`），
  这样**已经缓存过旧图**的浏览器（比如使用者现在这个）也会立刻重新拉取。

实测（按页面真实加载的方式渲染）：Man1 留白 L/R 15%、T/B 13%；Sou1、Pin9 13%；
Chun、Blank 横向 20%。也就是说"缩进白牌、居中留边"这次是真的生效了。

**教训**：这次两条报告都来自"我改的东西看起来没生效"和"看起来像 bug 的合规行为"。
前者是缓存策略的问题（服务端资源换新要配 ETag/no-cache 或 URL 版本号），
后者提醒我：**规则的可见性也是 UI 的一部分** —— 玩家无法验证的合规行为，
在他的体验里与 bug 没有区别。

## 57. 第 47 轮：白板被贴成了"？"、红五终于可以主动打，以及第三轮自审查出的 7 处规则偏差

### 57.1 "红中变成了问号"—— 是我上一轮自己换错了文件

上一轮我把"白"（haku）从 `Haku.svg` 换成了 `Blank.svg`，理由是"`Haku.svg` 什么都不画"。
结果 **`Blank.svg` 是这套素材里的"占位图"**：它的图形是一个 **红色问号 "?"**（`fill:#d71e1e`）。
于是玩家在手里看到"红中变成了问号"——其实是**白板**，而且那个"?"就是图本身，不是加载失败。

**证据**（自审用像素级办法确认）：把服务器实际返回的字节在浏览器里栅格化，
`Blank.svg` 画出来的形状是"弧线 + 竖 + 分离的点"= "?"，而中（`Chun.svg`，13485 px 全红）
画的是"中"字；`Haku.svg` 的 `layer1` 组**没有任何子元素**，所以它画出来是空的 ✓
——**空白的白板本来就是标准画法**。

**修法**：`HONOR_FILES[4]` 改回 `"Haku"`（并在注释里写明"不要换成 Blank.svg，那是占位图"）。
另外给白板加了一条**很淡的内框**（`.tile.haku::after`），免得一整张空白牌在别的花牌旁边被当成坏图；
不想要这圈框的话删掉那一条 CSS 即可。

顺带修掉一个会咬人的前端 bug：文本兜底里用了**未定义**的 `NUMERAL`，
所以只要某张万字牌图加载失败，兜底路径会抛 `ReferenceError`、留下一个空白方块。
现在 `NUMERAL` 有定义，并且兜底把手牌名也改成"赤5p"这种玩家读得懂的写法（不再是引擎的 `0p`）。

### 57.2 红五可以主动打了（而且不影响 AI）

之前**每种牌只提供一个"打牌"动作**，`pick_physical` 固定挑**非红**的那张，
所以手里同时有普通五和红五时，玩家点红五会被拒绝。

修法：**每种牌的每一张实际牌各给一个动作**，但**普通五排在前面**——
这正是 `pick_physical` 原本的选择，也就是所有 agent 的选择顺序不变。
验证：

* **数据逐字节不变**：用"每张牌一个动作"与"每种牌一个动作"两个二进制在同一 seed 下各生成 1000 局，
  md5 **完全一致**（`eaf762ac…`）。
* **红五确实可打**：新增单测 `both_copies_of_a_five_can_be_discarded` —— 断言两个动作都在、
  普通五在前、提交红五会被接受、**并且牌河与手牌记录的都是那张红五**（这条同时保证了牌谱可回放）。
* 用真实对局验证：起手 `[58,68,85,88,91,96,101,109,115,126,130]` 时，
  引擎同时给出 `88`（赤5s）与 `91`（普通5s）两个动作，提交 `88` 被接受。

（顺带修了 `nn_agent::evaluate`：它按动作返回分布，多张同种类的牌共用一个策略槽，
于是"分布"求和会超过 1 —— 现在按槽去重，测试 `evaluate_is_a_distribution` 重新成立。）

## 58. 第 48 轮：结算面板的手牌是空白、白板要"纯白"、大字要落在发生家

### 58.1 结算面板里和牌者的手牌全是空白 —— 一个"元素在、像素不在"的 bug

使用者报：和牌结算面板里，和牌者的 14 张牌**全是空白**。

自查发现两个叠加的原因：

1. **面板被 `innerHTML` 重建过**：`showWin` 用 DOM 构建面板（因为里面有牌），
   但最后把它交给 `overlay(title, body.innerHTML)` —— 序列化再解析会**生成全新的元素**。
   牌的"面"当时还在异步加载，加载完成后写进的是**已经被丢弃的那批元素**，
   于是面板里那 14 张牌永远不会被填上图案。
   修法：`overlay()` 现在接受 **DOM 节点**（字符串照旧），面板不再经过 `innerHTML`。
2. **"先隐藏、加载完再显示"的做法输给了竞态**：上一轮我给 `<img>` 加过
   `visibility:hidden` + `load` 回调，结果在面板这种"刚建好就测"的场景里，
   事件在监听器挂上之前就已经发生过，图片**永久隐藏**（实测 `naturalWidth=300` 却 `visibility:hidden`）。
   修法：牌的"面"改成 **CSS 背景图**（`div.tile-face`）。背景图有两个天然好处：
   **永远不会画出浏览器的"破图"图标**，也不存在"隐藏/显示"的竞态；
   加载检测改用一张**不挂到 DOM 上的探针图**，成功才把背景设上去，两次失败才回退文字牌面。

**教训**：`document.querySelectorAll('.tile').length` 这类"数元素"的断言骗过了我一整轮 ——
元素在、尺寸对，但**一个像素都没画**。以后这条路径上的检查必须看**像素**或**计算样式**。
现在 `settle` 检查会在每个结算面板上断言
`每张牌都有已设置的背景图`（`painted == tiles`），并用截图字节数交叉验证。

### 58.2 白板改回"纯白"，不加任何边框

上一轮我为了避免"空白牌看起来像坏图"给白板加了一圈淡色内框，使用者明确不要：
**白板就是纯白的牌**。该 CSS 规则已删除（`tiles` 检查仍然断言"白板必须什么都不画"）。

### 58.3 继续自查：把"元素在、像素不在"变成一类可检查的问题

上一节的两个 bug 都是同一类：**DOM 里元素齐全、尺寸也对，但屏幕上什么都没有**。
所以这一轮把这类检查固化下来，并且顺手补掉它们背后的隐患：

* 新增 `paint` 检查模式：**遍历页面上每一个 `.tile`**（牌桌 + 任何打开的面板），
  断言每张牌都有"面"元素、面的背景图已设置（白板除外，它本来就没有图案）、
  盒子非零、没有跑到屏幕外。这正是能抓到"结算面板 14 张牌全空白"的那类断言。
* 同一模式里**强制走兜底路径**：用 CDP 把 `/tiles/*` 全部拦掉，然后断言
  **14 张手牌每张都显示得出字**（"五萬"这种）、且失败的"面"元素已经移除。
  这条会直接抓到上一轮那个 `NUMERAL` 未定义的 `ReferenceError`。
* **启动时预热全部牌面**（37 个文件、几百 KB 的矢量图）：此前首次发牌会有一两帧
  空白（面是探针异步加载的），预热之后首帧就是完整的牌。

顺带用同一套"看似正常其实有问题"的眼光扫界面文字，抓到一条：
**侧家的对手名字被截断成同一个省略号**（"神经网络 AI 1/2/3" 在 1152×720 下只剩 59px 可用宽度，
三个名字都显示成"神经网络…"）—— 这正好让玩家分不清谁是谁。
现在座位头与牌河标签用**能区分的最短形式**（`AI 1`/`AI 2`/`AI 3`，完整名字放在 `title` 里），
同一扫描下"被截断的文字"从 2 条降到 **0 条**。

### 58.4 "立直/和了"的大字显示在**发生的那一家**，而不是桌子正中间

`announce(text, sub, ms, seat)` 现在接第四个参数：按座位相对关系
（自家 / 右家 / 对家 / 左家）把大字块放到对应区域 ——
对家在上方、左右家分别贴左右两侧、自家在下方；
荒牌流局这类"不属于某一家的"事件仍留在中下方。左右两侧的字号略小以免压住手牌。

修这个时又抓到一个**排序 bug**：双响时结算面板用的是
`wins.slice().sort(...)`（副本），而**大字用的是 `wins[0]`（未排序的原数组）**，
于是"双响"大字落在引擎列出的第一家、而不是离放铳者最近的那一家。
现在两者都用排序后的结果。`multi` 检查新增断言：注入"右家荣和"的事件后，
大字必须带 `at-right` 类（并且必须在**那一次播报还在显示时**读取类名，
否则读到的是紧接着的别的播报）。
